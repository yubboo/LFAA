# LFAA 开发计划与进度

本文档统一记录 LFAA 的开发阶段、当前进度、待开发事项和验收目标，作为项目执行清单。系统组件职责以[系统总体架构](系统总体架构.md)为准，代码和文档要求以根目录[开发规范](../开发规范.md)为准；发布记录写入[更新日志](updata-log.md)。

## 1. 开发方向

LFAA 面向 SteamCMD 游戏开服、Minecraft 管理、写作和各应用内的 AI Work。开发采用“控制端 + 节点执行端 + 多端界面”的分布式结构：

- `frontend/` 提供 Web、Tauri、Electron 共用的界面；每个业务应用同时有常规模式和内置 AI Work。
- `server/` 是控制端，集中处理用户身份、权限、游戏业务、任务状态、AI Agent 与节点调度。
- `daemon/` 部署在本机或远程主机，按授权执行安装、进程、文件、终端和资源监控任务。
- SteamCMD、Minecraft 和写作先作为独立业务应用建设；LLM 驱动的主 Agent 根据需要委派子 Agent，并通过受控工具完成操作。
- 首期保持 server 为模块化单体，daemon 独立部署；业务边界清楚后再评估是否需要拆分服务。

### MCSManager 参考结论

MCSManager 将产品分成 `frontend`、`panel` 和 `daemon` 三个核心部分：前端负责交互，panel 管理用户、节点连接、认证授权和 API，daemon 管理实例进程、容器、文件和实时终端。它还提供游戏服务端的一键部署、多节点管理与细粒度多用户权限。[项目说明](https://github.com/MCSManager/MCSManager) · [简体中文开发指南](https://github.com/MCSManager/MCSManager/blob/master/DEVELOPMENT_ZH.md)

它的开发安装脚本一次准备项目所需依赖和节点侧 PTY、压缩工具；正式安装则提供 Windows 即用包、Linux 安装脚本和 Docker 方案。[开发依赖安装脚本](https://github.com/MCSManager/MCSManager/blob/master/install-dependents.bat) LFAA 采用相同的三层职责思路，并补充写作和应用内 AI Work。SteamCMD、Java、PTY 等主机运行环境属于 LFAA 的运行数据和部署管理范围，不应混进前端 npm 依赖清单。

MCSManager 允许前端为性能直接连接节点。LFAA 首期先通过 server 执行权限检查、任务审计和节点路由；终端或文件传输确需直连时，再单独设计短期凭证、授权范围和审计方式。

## 4. 后续里程碑

### P2：分布式节点基础

1. daemon 使用受保护身份向 server 注册节点，汇报操作系统、版本和可用能力。
2. server 接收心跳，展示节点在线、离线和版本状态；Minecraft 活跃任务通过 30 秒租约续期，租约过期时报告结果未确认，不自动重放副作用操作。
3. 定义任务编号、目标节点、输入参数、进度、结果、失败原因、超时和取消语义。
4. daemon 只执行已授权的任务类型；文件访问限定数据根目录和实例路径，不开放模型生成的任意命令。
5. 在真实本机 daemon 和一台 Linux 远程 daemon 间完成连通与重连演练。

**验收目标：** Web 控制端能登记并监控本机及远程节点；创建的测试任务有完整状态流转和可追踪结果。

### P3：SteamCMD 开服 MVP

1. 建立可扩展的游戏目录和部署参数定义，先接入一款选定的 Steam 游戏。
2. 实现 SteamCMD 工具安装/检测、服务端下载、目录准备、配置编辑和启动参数校验。
3. daemon 执行部署与进程生命周期；server 持久化实例和任务状态。
4. 前端显示下载/安装进度、实时日志、终端、启动/停止状态、资源使用和可视化配置。
5. 加入备份、失败恢复和重复部署保护，再扩充更多游戏目录条目。

**验收目标：** 用户从 Web 界面选定节点和游戏后，能完成安装、启动、查看日志、停止及再次启动；服务端实例数据、配置和日志按约定位置持久化。

### P4：Minecraft 管理 MVP（当前优先）

Minecraft 进入常规模式后显示应用专属菜单：总览、实例、Java 环境、任务；选择实例后展开实例概览、服务器配置、控制台日志和世界备份。应用菜单与工作台只负责 Minecraft 业务，不改变最左侧全局导航。顶部常规 / AI Work 切换只改变交互方式；AI Work 复用已有模型服务和账户，但当前不注册 Minecraft 执行工具。

当前实现范围为本机 Windows x64 Daemon、Minecraft Java Edition 官方 Vanilla 服务端：从 Mojang 官方版本清单选正式版，按该版元数据匹配 Java；本机没有受管理 Java 时可通过 Adoptium 官方 API 安装并校验 JRE；创建实例前明确同意 Minecraft EULA；实例启动前 Rust Sandbox Host 为该实例创建独立 AppContainer 身份，验证规范路径，为实例目录授权读写并设低完整性标签、为受管理 Java 目录授权读/执行，再通过显式网络能力创建 Java 进程；Job Object 限制进程数和内存，并在 Sandbox Host 关闭时结束进程。缺少或建立沙盒失败时拒绝创建/启动实例任务，不回退到普通进程。启动、停止、配置写入、日志和停服后世界备份仍通过现有真实任务队列执行。节点能力来自 Sandbox Host 探测，实例状态来自 Daemon 心跳；面板显示当前沙盒状态、文件/网络边界和资源管理。节点、实例、任务和日志没有后端数据时展示空状态或离线状态，不填演示数据。

AppContainer 的 Windows 边界参照 Microsoft 的 [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)、[AppContainer implementation](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 和 [Mandatory Integrity Control](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control) 文档。构建验证不能替代目标 Windows 主机对 ACL、低完整性标签、网络绑定、启动、停止和宿主退出清理的验收。

插件/模组、Bedrock、Paper/Spigot/Fabric/Forge、远程多节点、交互式任意命令、主机资源采集和 Agent 自动操作不属于本轮 MVP。后续完成 Minecraft 后，依用户顺序接 P3 SteamCMD，再接 P5 写作。

**验收目标：** 专属菜单正确切换；在线本机节点与正式版目录真实读取；管理员在同意 EULA 后可创建官方 Vanilla 实例，查看任务和实际输出、启动/安全停止、修改白名单字段及为已停止实例备份世界；每个 Java 服务进程实际以该实例 AppContainer SID 运行，其他实例数据和宿主机凭据不可访问，能力范围内允许服务端网络，进程内存/数量受 Job Object 限制，并在 Sandbox Host 关闭后清理。刷新后状态来自 server/daemon 持久数据。实际 Minecraft 下载和开服验收需在用户 Windows 主机执行；构建检查不能替代该验收。SteamCMD、写作和第三方插件不得因此标记为已隔离。

### P5：写作应用

实现作品与章节管理、编辑器、自动保存、历史恢复和资料管理。先让常规写作流程可用，再接入 AI Work；写作数据归属独立于游戏实例。

**验收目标：** 用户能创建作品、编辑章节、关闭并重新打开应用后恢复内容。

### P6：各应用内的 AI Work

当前执行 `LFAA-AI-RUNTIME-01`：在已验证的 Cordis 宿主上完成 Provider 对话、持久化会话、扩展契约和设置中心正确分类。`LFAA-AI-PERMISSIONS-01` 将“请求审批”“替我审批”“完全权限”接入账户设置、server 授权器、单次审批和可撤销的精确范围记忆授权。SteamCMD、Minecraft、写作和网络穿透的实际操作工具只在其业务模块和 daemon Runner 就绪后连接；不存在的能力须清楚标记为未接入。

1. 在 server 配置 LLM 提供方、密钥、模型、超时和用量；前端不保存模型密钥。
2. 每个应用内提供独立上下文的 AI Work 面板，不增加一个替代业务 App 的全局 AI 应用。
3. 当前主 Agent 是可版本化的对话配置；多步 Agent Loop、任务步骤和停止条件待实现。
4. SteamCMD、Minecraft、写作等专业子 Agent 委派待对应业务上下文和工具范围就绪后实现。
5. Tools 调用 server 业务服务；有副作用的操作使用核心授权和单次审批，并检查节点、路径和任务状态、记录审计。下载/安装/配置修改属于写入操作，命令执行属于高风险操作；“完全权限”不绕过业务检查或单独的 Minecraft EULA 同意。当前无可执行业务工具。
6. Skills 与提示词提供领域流程和行为约束，不绕过业务校验，也不直接运行任意 Shell。

**当前 Runtime 验收目标：** 配置活动 Provider 后，SteamCMD、Minecraft 和写作各自的 AI Work 能创建、继续、归档会话并显示流式回复、Token 用量和实际扩展状态。未配置 Provider 时页面指向“AI 与模型”。业务工具、任务步骤与节点执行的验收须等 P2–P5 对应服务实现后进行。

### P7：多端与生产安装

1. 先稳定 Web 版与 Docker Compose 开发部署，再制作可重复升级的数据持久化方案。
2. 将 daemon 作为可独立安装和升级的 Windows/Linux 节点程序，明确运行环境、数据目录和权限。
3. Tauri 与 Electron 共用 frontend 业务界面，分别验证 Windows/Linux 外壳和系统能力。
4. 分开维护开发依赖安装与用户生产版一键安装；生产安装负责程序、SteamCMD/Java 等运行环境、服务注册和数据迁移。

**验收目标：** 新环境按对应平台说明完成安装；升级程序不删除游戏实例、世界存档、写作数据、配置和备份。

## 5. 进度维护规则

- 本文档是里程碑、进度和待办的唯一汇总处，不另外复制一份“开发进度”和“待开发清单”。
- 状态统一使用：`待开始`、`进行中`、`已完成`、`阻塞`。没有代码或可检查产物时，不标为已完成。
