## 问题根因与设计方案

1. **原问题定位**：
   - 此前仅左二/右栏整体开关、左一固定应用与外观色值存入了 `localStorage`，其余大量界面操作仅使用组件 `useState` 内存默认值：`NavigationGroups` 的 `expanded`（置顶/项目/最近）、`sectionExpanded`（各自定义分区）与 `sort`、`WorkbenchShell` 的 `mode`、`WorkbenchClientService` 的 `activeView`/`activeProjectId`，以及 `AppearanceSettings` 的 `advancedOpen` 与多文件夹项目的 `selectedRootPath` 会在刷新页面后全部重置。
   - 此外，响应式窄屏自动收起抽屉的逻辑会直接写入持久化开关，`NavigationGroups` 监听 `pinnedProjects.length` 的 `useEffect` 在异步加载完成后也会覆盖用户手动收起「置顶」的记忆。
2. **统一持久化实现**：
   - **新增共用浏览器存储工具模块 `packages/ui/layout/client/ui-preferences.ts`（139 行）**：封装 SSR 安全读写、类型守卫与兜底容错，统一管理 `lfaa:active-route`、`lfaa:workspace-mode`、`lfaa:nav-group-expanded`、`lfaa:section-expanded`、`lfaa:project-sort` 及既有的 `lfaa:left-sidebar-open`、`lfaa:right-panel-open`，并在 `@lfaa/ui-layout/client` 导出 `readStoredJson` / `writeStoredJson` 供 `@lfaa/workspace` 与 `@lfaa/ui-theme` 复用。
   - **路由与侧栏开关记忆（`workbench-service.ts`、`WorkbenchShell.tsx`、`@lfaa/ui-layout/src/index.ts`、`local-project-store.ts`）**：记录当前所在视图或打开的项目 ID，新增可选 `WorkbenchProjectProvider.hasLoaded` 在项目列表尚未完成异步拉取前呈现平滑占位，若已删除则自动回退首页；`setLeftSidebarOpen` / `setRightPanelOpen` 增加 `persist` 参数，使窄屏自适应收起抽屉不会覆盖桌面端保存的展开状态。
   - **分组折叠与排序记忆（`NavigationGroups.tsx`）**：同步持久化「置顶 / 项目 / 最近」展开状态、各自定义分区 ID 折叠状态与项目排序方式；区分“首次异步拉取完成”与“会话内新增置顶”，确保用户显式收起「置顶」后刷新仍保持收起。
   - **跨包局部记忆**：在 `AppearanceSettings.tsx` 持久化“高级选项”折叠开关（`lfaa:appearance-advanced-open`），在 `ProjectWorkspace.tsx` 按项目 ID 持久化当前选中的源文件夹页签（`lfaa:project-selected-folders`）。

## 风险、回滚与遗留问题

- 风险：极低；所有持久化读写均有异常吞吐保护与结构守卫，即使 `localStorage` 数据损坏也会平滑回退默认值。
- 回滚办法：移除 `ui-preferences.ts` 及对应组件的读写调用并重新构建即可。
- 遗留问题：暂存区基于浏览器 `localStorage` 记忆（同一浏览器跨刷新/重开长期生效，更换浏览器或无痕模式从默认状态起步）。
- Git 状态及提交：`E:\lfaa` 不是 Git 仓库；无提交。
- 本轮有无用户可见变化、是否新增 updata-log：界面折叠、排序、模式、页面路由等用户操作刷新后不再丢失，已同步新增同编号 `updata-log`。
