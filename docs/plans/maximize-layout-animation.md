# 方案：最大化/还原的布局编排动画（双面板同步）

- 状态：已实施（2026-11-26，DEV-000573）；机制按实施结论修订，见 §3.5
- 关联：`packages/ui/layout/client/shell/WorkbenchShell.tsx`、`WorkbenchShell.module.css`、`workbench-service.ts`、`pane-anim.ts`、`use-pane-anim.ts`、`PaneAnim.module.css`
- 前置记录：DEV-000563（去掉白屏）、DEV-000564（纯 CSS 轨道过渡失败）、DEV-000565（FLIP 单面板失败）

## 1. 结论先行

前三次失败的本质是同一个：**只让一块动**。

- 纯 CSS 轨道过渡：轨道插值与面板固定宽度不同步 → 空白帧；
- FLIP 单面板：面板用 transform 缩回旧位置，但会话列同一帧归零 → 面板还没长过去的区域是空的（实测 7 帧空白）。

所以正确做法是**两块同时动画**，任何一帧都有内容覆盖可视区。

## 2. 目标

1. 最大化 / 还原都是 260ms 连续动画；
2. 任意一帧：`会话列 + 右侧面板` 的**并集覆盖**整个中间+右侧区域，不允许空白；
3. 动画期间不参与栅格布局（避免与列宽插值打架）；
4. 两种排版（聊天区在左 / 预览区在左）都生效；
5. 失败即瞬时切换（保留 DEV-000563 行为），不允许白屏。

## 3. 方案：动画外壳 + 定格内容

### 3.1 结构

点击最大化时，把「中间列 + 右侧列」两个元素**同时**移入一个覆盖该区域的动画外壳（`position: absolute; inset: 0`，普通文档流之外），外壳内保留两块的原尺寸快照：

```
.animLayer (absolute, 覆盖 中间+右侧 区域)
  ├─ .paneSnapshot--chat     (原中间列尺寸，transform 动画)
  └─ .paneSnapshot--panel    (原右侧列尺寸，transform 动画)
```

- 底层真实布局立刻切换到终态（最大化后的栅格）；
- 动画外壳在最上层播放 260ms：聊天列 `translateX(-w) + opacity 1→0`，面板 `translateX(-Δ) + scaleX(gain) → 1`；
- 动画结束后移除外壳，真实布局露出（此时已是终态，无缝衔接）。

### 3.2 关键点

- 快照用**同一份 DOM 子树**（不是截图），即动画期间把真实节点临时移入外壳；结束后放回原位——避免「截图模糊」或「内容不一致」。
- 只动 `transform` 与 `opacity`，不动布局：任何一帧都不触发重排；
- 会话列不写入宽度、不重排，因此滚动位置不受影响（已有滚动记忆仍生效）。

### 3.3 状态机

| 阶段 | 时长 | 说明 |
|---|---|---|
| prepare | 0 | 量两块矩形，插入外壳，迁移节点 |
| play | 260ms | `transform` + `opacity` 过渡 |
| settle | 0 | 节点归位、移除外壳、清理内联样式 |

快速连点：若 `play` 未结束又来一次，先 `finish()`（直接跳终态并清理），再开始新一轮。

### 3.5 实施修订（2026-11-26，DEV-000573）

1. **就地固化代替搬节点**：两块加 `position: absolute` + 显式 `grid-area: 1 / 1 / 2 / -1` + 旧几何，外壳只做交互锁。网格绝对定位子项以「自己的网格区域」为包含块（[css-grid-1 §9.1](https://www.w3.org/TR/css-grid-1/#abspos)），不显式化会把 `left/top` 算到某条轨道上；就地固化还省掉 detach，滚动与 React 父子关系都不受影响。
2. **会话列淡出 + 收窄 8%**，不再是 `translateX(-w)`：会话居左时外包边就是左二栏边界，平移会滑到左栏上面。
3. **几何曲线改 `cubic-bezier(0.65, 0, 0.35, 1)`**：强调曲线前段就跑完约 95% 位移，遮蔽会留出约 150ms 的「只有底色」死区。
4. 方向不用外部参数，读 `shell.dataset.rightMaximized`；还原方向在排版切回后重新量一次常态几何，期间外壳 `transition: none` 保持冻结。

### 3.4 降级

`prefers-reduced-motion: reduce`、测量失败、节点迁移异常 → 直接走终态，也就是当前行为。

## 4. 验收（无头 Edge，16ms 采样）

1. 两种排版各切一次最大化、一次还原；
2. **空白帧 = 0**：采样 `document.elementFromPoint()` 在中间区域多点取样，任一点来自 `body`（无内容）即判空白；
3. 宽度序列 ≥ 6 个不同值（确有动画）；
4. 动画结束后：无残留内联 `transform`、无 `data-anim` 属性、节点已归位（父节点与切换前一致）；
5. 聊天滚动位置与切换前一致；
6. 控制台 0 报错。

## 5. 风险

| 风险 | 处理 |
|---|---|
| 节点迁移导致 React 状态错乱 | 迁移期间锁定交互（`pointer-events: none`），结束立即归位；用 `flushSync` 保证迁移与终态在同一帧 |
| 迁移触发聊天组件重挂载（丢滚动） | 迁移只改变父节点，不改变 key 与树结构；验收第 5 条专门盯滚动 |
| Shell 文件已到 400 行上限 | 动画编排放独立文件 `pane-anim.ts` + `use-pane-anim.ts`，Shell 只接线 |
| 与拖拽/折叠冲突 | 动画期间禁用拖拽手柄与折叠按钮 |

## 6. 不采用

- 继续调轨道变量（两次失败，见 DEV-000564）；
- 单面板 FLIP（实测 7 帧空白，见 DEV-000565）；
- 引入动画库：为一次切换增加运行时依赖，收益不匹配。
