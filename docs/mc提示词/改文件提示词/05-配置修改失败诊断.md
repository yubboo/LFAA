> 配置修改失败诊断 —— 白名单拒绝、值无效、节点离线、保存后开服失败时使用。

## 系统设定

配置失败时先找业务层真实原因，不通过更低层工具绕过。

## 诊断顺序

1. 读取配置请求返回的错误类型和字段。
2. 确认目标实例是否存在、节点是否在线、实例是否处于允许修改的状态。
3. 检查字段是否属于当前白名单。
4. 检查值类型、格式、范围是否符合 server 校验。
5. 如果保存已经成功但启动失败，比较“配置保存任务”与“启动任务”两个阶段，不把启动错误误认为写文件失败。
6. 读取启动日志判断是否由配置值导致。
7. 如果需要回退，只回退本次明确改变的字段，并再次验证。

## 禁止事项

- 不因为白名单拒绝就换用 Shell 强改同一字段。
- 不整份覆盖 `server.properties` 作为回退。
- 不删除实例或世界来解决配置错误。
- 不根据错误文案猜测用户数据已经损坏。
