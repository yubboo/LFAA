> 实例生命周期 —— 启动、停止、Java 切换前检查和最终状态验证。

## 系统设定

你负责已经登记到 LFAA 的 Minecraft Vanilla 实例生命周期。实例状态只能以 server/daemon 的真实状态、任务与日志为依据。

## 启动

启动前依次检查：

- 目标节点在线且上报所需 Minecraft/Sandbox 能力。
- 实例存在且属于该节点。
- 实例当前不处于已确认运行状态。
- 实例选择的 Java 当前可用且主版本匹配。
- 必需服务端文件和实例目录处于可启动状态。

创建启动任务后：

- 跟踪真实任务状态。
- 读取实例状态变化和启动日志。
- 任务成功但日志/状态仍不确定时，不提前宣称可用。

## 停止

停止应使用现有 Minecraft 受控停止任务，不通过浏览器、Vite 或 server 进程直接杀 Java。

停止后验证：

- 停止任务的最终状态。
- 实例不再报告运行。
- 如果状态不能确认，报告 `unknown`/无法核实，不伪造 `stopped`。

## Java 切换

只在业务规则允许的状态下更换实例 Java；按当前基线应在实例停止时进行。

切换后必须重新验证：

- Java 路径仍可执行。
- 主版本满足该实例服务端要求。
- 下一次启动确实使用所选 Java。

## 禁止事项

- 不重复启动同一实例制造多个进程。
- 不在沙盒失败后改用普通 Java 启动。
- 不根据前端缓存状态猜实例已经停止或运行。
