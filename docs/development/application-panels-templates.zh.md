# 应用面板与模板目标

[English guide](application-panels-templates.md)

用户于 2026-10-16 确认：LFAA 以通用编程 Agent 和多 Agent 协作为主线；应用是系统内可手动操作、展示成果与管理数据的传统面板。未来用户通过对话使用内置或自定义模板，既可以生成成果，也可以生成应用面板。

合同：[LFAA-APPLICATION-PANELS-TEMPLATES-20261016](../PROMPTS.md#lfaa-application-panels-templates-20261016)。本文记录目标，不宣称模板能力已上线。

## 用户流程

用户在 `/work` 提出目标，必要时指定模板、项目或已有应用实例；主 Agent 按需加载模板与能力、委派子 Agent，通过真实工具完成工作和验证。成果或应用实例进入对应管理面板，用户可查看、编辑、继续处理。面板发起智能体协助时回到共享工作区，传递必要对象引用；手动与 Agent 操作调用同一服务、数据和权限 Owner。

游戏、写作和视频 App 继续保留专门面板及服务。解耦不删除业务能力，不把真实数据迁移到聊天记录。`normal/ai-work` 旧协议值可为兼容保留；产品分别表达“应用面板”和“智能体工作区”。

## 两类模板与实例

| 类型 | 模板定义 | 实例与管理 |
|---|---|---|
| 成果模板 | 输入字段、成果结构、参考资料、必要能力、验收要求 | 真实文档、代码项目、研究资料或媒体，进入对应文件/项目/领域面板 |
| 应用面板模板 | 输入字段、布局/组件、数据与动作合同、必要能力、验收要求 | 可继续操作的应用实例，进入应用目录与实例管理页面 |

模板是可复用定义，实例是基于某个版本生成的独立对象。修改模板不静默覆盖已有实例或用户编辑。实例关联模板 ID/版本、项目/领域对象及生成任务，正文由原领域或文件 Owner 保存，避免会话、模板和面板各保存一份权威数据。

自定义模板目标包括创建、编辑、复制、导入/导出、版本管理及删除；实例目录区分成果和应用实例，按真实项目、类型和状态管理。具体字段与 UI 在实现合同时限定，不提前建立假入口或演示成果。

## 执行与归属

- 模板提供方法、结构和验收要求，模型按目标及真实结果决定行动，不用固定业务流程代替模型决策。
- 面板组件必须绑定真实查询与业务动作；缺少服务、凭据、节点或能力时返回真实不可用状态，不写死成功。
- 需要生成可执行应用代码时，先生成项目成果并验证，再经既有插件/应用装配合同登记运行。不能把任意生成脚本直接注入主工作台，也不能将生成 HTML 视为业务已接入。
- 模板和外部资料不构成操作授权。安装、写入、进程操作及面板动作沿用 `permissions.mode` 与唯一 Permission Owner，保留账户、对象、路径和参数校验，不增加第二套审批。
- 目录/实例有界查询，详情按需读取，离开页面撤销请求和订阅；后台生成由原 Agent/Jobs 持续执行，避免无界轮询及重复 Agent。

现有对话、会话、委派和工具执行继续归 Agent/Session/Tools，面板归 Client，事务和内容归原领域/文件 Owner。当前没有本文两类模板的完整注册、版本、实例与动态面板合同。正式实现前核实 Preset、Knowledge、Workspace、Deliverables 和插件装配的可复用部分，确定模板定义和实例索引的唯一 Owner；不直接把模板等同于 Skill、Prompt、Agent Preset 或插件，不把动态实例写成固定 App ID。

模板来源、存储、生成预算、默认行为等若需配置，先接入设置中心的类型/默认值、校验、持久化及前端映射。面板消费现有 Appearance，并按实际容器宽高响应式布局，不写死用户偏好。

## 实施与验收

1. 清理面板中的旧 App 专属 Agent 展示，保留业务操作、写作方法与数据；共享工作保留旧会话与真实工具。
2. 接入模板定义、版本及自定义管理，用真实成果模板验收“对话 → 生成 → 校验 → 入库 → 面板编辑 → 继续对话”。
3. 接入面板模板与实例装配，验证真实查询/动作、刷新恢复、并发编辑、失败状态、卸载清理及设置效果。
4. 用通用编程和复杂成果任务验收协作：子任务目标/上下文/成果可追踪，代码修改可审阅，冲突被处理，验证来自真实执行。

本轮只执行第 1 步的 UI 残留清理。模板 CRUD、模板生成、动态面板装配及真实多 Agent 模板任务均未实现、未验收。源码、构建、内置浏览器、模型、节点/桌面和性能证据分别报告。
