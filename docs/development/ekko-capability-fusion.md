## 优先级与完成定义

用户目标是可独立干活的编程 Agent、有效协作和真实成果；应用保留传统操作与成果管理面板。先逐项闭环，再扩大范围：

1. **P0 编程与协作底座：** 项目理解 → 文件搜索/修改 → 命令/验证 → Git 差异 → 真实错误修复；前台/后台子任务及有据可查的结果。保持主/子模型、权限、预算、项目和数据 Owner。
2. **P1 Coding Agent 工作台：** 独立运行时目录与调度入口，先接通一个真实外部 Agent，再逐个适配；展示模型/安装/可用性、任务轨迹、产物、变更和错误。源码已有驱动不等于可作为主运行时或在真实项目中可用。
3. **P2 协作与工作树：** 分工、上下文、范围、结果合同，按需并行；由现有 Git Owner 创建/管理工作树，处理冲突、整合和最终回归。任务可补充要求、暂停/继续/停止，刷新不丢失真实状态。
4. **P3 多运行时聊天、群聊与工作流：** 一份真实可用的运行时目录，三种消费入口；不通过关键词业务路由或固定流程替代模型选择，不复制会话和权限系统。
5. **P4 成果 Skills 与模板：** 文档/表格/PPT/研究/写作/应用操作先逐项验证真实产物；模板预置格式、资料、专家引用及验收要求。自定义模板、成果实例和应用面板实例分离。
6. **P5 其余能力：** 按下表逐项登记实现、装配和真实验收，保留上游来源及许可记录。

每项的完成记录必须附源码 Owner、配置、直接回归/构建、真实模型/运行时和 UI 证据以及未测范围。不能用合成 Provider 替代真实模型验收，不能用源码登记替代运行时可用性。

## 本轮第一项合同

保留原 lfaa_delegate_subagent 主入口和驱动，增加 mode=foreground/background；后台先限已接入的进程内驱动，外部 CLI 后台协议单独实施。数量、深度、工具范围、模型、计划模式和权限复用父 Run。后台立即返回真实标识，父 Run 正常完成不取消子任务；显式停止仍按原取消链执行。结果写入原 Session，读取可等待且不重放；取消等待不取消子任务，进程重启后未完成状态报告中断，已完成结果可读。

验收账号由用户在对话中提供，只在登录时使用；任何文档、源码、截图和日志不得保存其密码。真实编程验收应在明确的测试项目中创建产物，记录目标、diff、执行/错误修复、测试及交付。阶段状态和实际证据继续写入本文件与任务合同。

## 第一项实施证据

已接通原工具的前台/后台模式、来源会话持久化、结果查询/等待和取消语义，后台当前只支持 in-process。真实账户当前 DeepSeek / deepseek-flash 在受管 AI Worktree 完成读取、复现（2 通过/4 失败）、后台只读委派、仅修改一个源码文件、验证（6 通过/0 失败）、Git 差异和子任务结果回收；维护者独立复跑 npm test 与 diff 一致。原基线仓库保持干净。

现场同时发现确认失败的测试命令在源码修复后仍被防重，模型用等价 node --test 完成首轮验证；随后 Shell Owner 接入原 retryAfterRecovery，补充真实 Shell 回归验证“确认失败→成功写入修复→同参数重验”允许，“超时→成功写入→同参数重放”拒绝。没有增加自动重试、权限模式或模型降级。
