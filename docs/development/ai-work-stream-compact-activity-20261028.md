## 目标与边界

- 用户反馈：AI Work 流式回复中展开工具说明后出现大块说明卡、参数网格和阶段说明，视觉过重；参考图要求用图标、短动作行和连续正文呈现工具过程。后续又反馈对话滚动不可触发、长 JSON/代码输出块需要可滚动，以及切换其他会话再返回时原本停在底部的消息区跳回中间。最新反馈要求最终答复完成后，将命令/工具过程收到“小鱼助手 · 用时”标题下的可展开区域，默认收起，最终答复保持直接可见。
- 运行入口：Web/Desktop 共用 AI Work `/work`，消息时间线由 `packages/client/ui-chat` 的 `AiWorkResponse` 渲染。
- 唯一 Owner：`packages/client/ui-chat` 持有助手回复、活动时间线、消息滚动与工具输出内容盒子的交互；`packages/client/store` 持有账户隔离的本地滚动状态存储；`packages/client/ui-workspace` 只持有工作区级滚动条可见性/布局规则。SSE、Agent Loop、Session 与工具执行继续由现有 Owner 提供和处理。为恢复本轮真实页面验收，另修复 `packages/session/session-persistence-jsonl` 对可重建 SQLite 会话索引的启动处理，不改变会话事件或消息 Owner。
- 设置：复用设置中心已映射的 Appearance 主题、强调色、界面/正文/代码字体与字号、对比度及减少动态效果；不新增、不重置设置。
- 数据/权限：只呈现 `AiActivityItem` 已公开的真实活动和安全阶段；不改变 Session 数据、工具调用、执行结果、审批或 Permission Owner，不呈现参数值、原始工具返回正文或隐藏推理。
- 性能：不增加请求、订阅或计时器；复用已有有界活动与阶段列表。长详情与代码块按当前容器/视口约束滚动，嵌套区域到边界后仍可继续滚动消息区。
- 允许修改：`ui-chat` 时间线组件、代码块/输出区和消息滚动交互及其长期回归/README；`client/store` 共享滚动恢复实现与包说明；若需调整工作区滚动条可见性，可修改 `ui-workspace` 对应父容器样式和包说明；Session JSONL 启动投影一致性回归、包 README 和系统架构记录；本合同和 `docs/PROMPTS.md` 索引。
- 禁止修改：Agent/SSE/工具/权限行为、模型与用户设置、工作区会话状态、真实 Home 中的用户会话/SQLite 记录、非本任务已有改动。

## 实施记录

- `AiWorkResponse` 默认只显示“查看执行步骤”及简短阶段名；完整工具名称、用途、Schema、操作约定和阶段说明移到第二层手动展开，仍不显示参数值。
- `AiWorkChat` 不再因消息正在流式输出而自动展开含工具合同的活动详情；用户仍可主动展开真实活动与完整合同。
- 完成态呈现批次已实现：只要存在过程记录，“小鱼助手 · 用时”标题即为默认收起的原生折叠入口；打开后沿用原过程时间线和单步/工具合同折叠，最终答复始终留在外层并保持可见。流式运行中的实时活动顺序与可见性不变；没有过程记录时不显示空折叠入口。
- 最新滚动缺陷复现：完成态外层详情实际使用 `.ai-work-chat__response-process`，消息区事件却匹配已移除的 `.ai-work-chat__response-history`，因此展开过程后仍按“跟随最新”触发同步贴底；Chromium 自身折叠布局还会把标题推移约 106px。事件现绑定实际类名；展开时暂停布局自动贴底，并在绘制前校正标题视口位置，不让展开/校正产生的程序滚动单独触发“回到底部”；全部收起后恢复原跟随状态，展开期间用户主动滚动优先。
- `AiWorkChat` 将当前会话的“跟随最新消息”语义状态交给 `client/store` 与像素滚动位置一起保存；内容准备完成后按该状态贴底或保留阅读位置，不修改服务端消息和用户偏好。
- 会话切换首帧可能暂时沿用上一个会话的 `messagesReady`；`AiWorkChat` 现在要求就绪状态与 `messagesSessionId` 匹配当前会话后才允许滚动恢复，避免把已保存位置先应用到旧 DOM 并被错误夹到顶部。
- `ai-work-chat.css` 将活动行、已回答的澄清/审批记录和文件变更入口改为低对比度、无大块卡片的紧凑时间线；沿用现有主题、字号和字体令牌，未新增设置或 CSS 变量。
- 同一 CSS 为长 Markdown 代码块增加 `min(45dvh, 420px)` 高度上限及纵/横向滚动；代码块、活动输出、工具组列表和完整合同详情显示现有强调色细滚动条，并在滚动边界把滚轮交回消息区。
- `ui-chat/README.md` 已说明主消息区与受限内层滚动区域的职责及滚动传递。
- README、系统架构记录与任务索引已同步。
- 启动恢复发现 SQLite 会话头只是一条可重建投影；整段 JSONL 不存在时忽略该孤立头，不让其阻断整个服务或显示成仍有效会话；标题查询按键集分页越过孤立键，继续返回最多 200 个有效会话；日志存在而已提交修订缺失时继续保留完整性错误。真实 Home 只读审计，没有删除或改写其中的会话/SQLite 记录。
