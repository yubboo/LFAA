# AI Work 活动文件路径与右侧 Git 文件查看（2026-10-28）

<a id="lfaa-ai-work-activity-project-file-dock-20261028"></a>

## 用户问题与目标

AI Work 的“小鱼助手”过程记录展示项目文件操作路径。读取路径目前是静态文本；写入/新建/删除路径即使可点，也进入居中 Git 审阅弹窗。用户期望路径在有真实项目绑定时可点开右侧工作区文件标签，查看项目文件、路径面包屑，并按需展开文件夹形式的 Git 更改列表及状态。

实现完整的只读文件查看闭环：读取、创建、修改和删除活动路径都使用同一右侧文件标签；正文由当前项目文件 Owner 读取；“显示更改”列表和颜色来自该项目实时 Git 状态；选择变更文件可查看 Git 差异。路径、项目、账户和来源节点绑定保持服务端校验。没有项目绑定的活动不得猜测其他项目或仓库。

## 运行入口、Owner 与设置

- 运行入口：Web/Desktop 共用 Client 的 AI Work `/work`，右侧 `ApplicationWorkspace` 工作区标签页。
- 展示 Owner：`packages/client/ui-chat` 的 `AiWorkChat`/`AiWorkResponse` 负责公开活动路径及用户点击回调；`packages/client/ui-workspace` 的 `ApplicationWorkspace` 持有右侧工作区标签与文件查看器。
- 活动元数据 Owner：Agent Loop/Session 只提供经校验的相对路径、操作类型、项目 ID 和可选来源 ID；不含文件正文。
- 文件与 Git Owner：沿用认证的 Workspace 文件读取、Git 状态及 Git 差异接口，由 Workspace Controller、Host Project Files 与 Git Owner 校验项目/节点/path；界面不直接访问本机文件系统。
- 设置：沿用外观设置中的主题、强调色、字体/字号、对比度、壁纸遮罩与减少动态效果共享映射；沿用 Git 差异标记配置。无新增设置、无用户偏好写入。
- 权限与数据：查看只调用现有认证读取合同；不保存新文件索引，不执行写入、暂存、提交或仓库切换，不更改当前账户、项目或节点绑定。

## 修改边界

- 只改 AI Work 活动文件入口、右侧文件查看器/标签、紧邻的样式、直接回归和必要 Owner 文档/任务合同。
- 文件 tab 以项目 ID、相对路径和来源节点作为作用域；打开相同作用域与路径时复用标签，关闭标签按现有工作区标签生命周期处理。
- 面包屑可用来显示/定位当前相对路径；Git 树只展示 Git Owner 返回的有界变更文件，不伪造完整项目目录。文件夹只展开/收起真实变更路径。
- Git 状态颜色使用现有 Appearance/Git 颜色令牌，不能以活动记录中的“修改”字样推断当前 Git 状态。
- 不触碰对话/SSE/Agent Loop 执行顺序、隐藏推理、文件数据/授权合同及无关共享工作树修改。

## 验收条件

1. 有已登记项目的读取、创建、修改、删除文件路径均可键盘/鼠标打开右侧文件标签；读取操作展示文件内容，变更操作提供当前 Git 差异入口。
2. 右侧文件标签有项目根至文件名的面包屑；文件路径在窄分栏可换行/省略并可访问，不引发横向溢出。文件标签可切换、复用和关闭。
3. 点击“显示更改”后读取当前绑定项目 Git 状态，以可展开/收起的文件夹树显示真实 changed file；不同 Git 状态有可辨认的颜色/标记。点击文件打开对应文件/差异。
4. 项目未绑定、项目不在当前账户/App、节点来源不匹配、Git 干净/错误、文件读取失败、删除文件无当前正文等情况均给出真实状态，不猜测路径、不回退到其他仓库。
5. 文件查看只读；打开/刷新/切换/关闭标签时没有请求重叠、旧响应覆盖当前路径或遗留订阅。文件列表受 Git Owner 的返回上限约束。
6. 直接回归与 ui-workspace、Web 构建通过；正式 Web 的 ChatGPT 内置浏览器 `/work` 实测桌面和相关窄分栏的路径点击、切换标签、面包屑、文件夹开合、Git 状态与文件内容。
