## 用户目标与验收范围

- 用户认为输入框模型入口难辨认，现有弹层把推理设置、回复长度和模型目录堆在一起；参考截图要求模型选择独立呈现，并在列表里提供“管理模型”。
- `/work` 输入栏的当前模型控件进入简洁推理面板；面板内点击当前模型名进入独立模型目录，选择后保存并回到推理面板。全局输出长度策略继续只在设置中心配置，不在模型弹层重复呈现。
- 唯一 UI Owner：`packages/client/ui-chat/src/AiWorkChat.tsx` 与 `ai-work-chat.css`；目录展示继续消费 `packages/client/ui-settings-models` 的账户顺序、模型名、版本与能力映射；账户、目录和推理偏好继续由 Connection / Settings Service / LLM Owner 提供。
- “管理模型”使用既有 `onOpenSettings("ai", focusTarget)` 导航能力，定位当前活动账户的 `settings-ai-account-${id}`；无活动账户时打开 AI 与模型设置首页。
- 设置盘点：模型账户/目录/思考模式仍使用 Settings Owner 当前认证账户数据；输出长度使用 `aiRuntime.speed`（快速/均衡/深入），默认值 `balanced`，由 Settings Service 校验并持久化；界面继续消费 Appearance 主题、强调色、字体字号、浮层表面与减少动态效果映射。不新增设置、不重置用户偏好。
- 数据与权限：目录搜索为现有本地筛选；仅用户明确选择模型或推理档位时才调用现有 Settings API。实页验收只打开/关闭视图、搜索和导航，不选择模型、不保存设置、不触发模型请求。
- 性能与维护：保留已有目录分页/上限、账户边界和错误处理；弹层视图切换不新建订阅、请求、定时器或持久化状态；不改 Provider 请求参数和模型目录合同。

## 验收条件

1. 输入栏控件不显示容易误认作模型名称的独立版本号；当前模型与思考档位可直接识别，完整名称可从选择面板读取。
2. 默认面板只呈现模型入口与推理档位；模型弹层不显示全局输出长度策略。设置中心“AI 与模型 → 推理参数”仍能读取和保存 `aiRuntime.speed`。
3. 模型目录作为独立视图显示真实账户、模型名及必要 ID；搜索、选中态、有限加载、键盘操作和失败反馈继续可用，不展示长能力摘要堆叠。
4. “管理模型”进入 AI 与模型设置，并聚焦当前活动账户；该跳转不自动修改账户或模型。
5. `/work` 桌面与窄分栏/短屏下浮层宽度、滚动与操作均可达，主题和字体沿用当前设置，无横向溢出；相邻输入栏行为保持原样。
6. 运行新增定向回归、ui-chat 包构建、Client 类型检查和正式 Web 构建；按规则从当前源码启动正式服务，在 ChatGPT 内置浏览器 `/work` 检查桌面与窄视口，记录视口、交互、截图及未测范围。性能仅记录实页交互观察，不以构建结果代替帧时间测量。
