## 目标

明确“简洁优先”不得被解释为只做最小演示或删减明确需求。功能按用户目标完成端到端的核心流程，再以简洁、精准控制实现复杂度和范围。

## 修改

- 在根目录《开发规范.md》的核心原则中增加“完整功能优先”硬性规则，并说明它与简洁优先、精准修改的关系。
- 不修改产品源码、运行数据、设置、权限或构建入口。

## 验收

1. 规则明确要求依据用户目标整理完整流程与可观察验收点，覆盖适用的入口、交互、状态、数据、权限、错误/恢复和结果反馈。
2. 明确禁止以“最小实现”为由留下核心路径占位、演示版、伪成功或将必要能力推迟到未承诺的后续。
3. 明确简洁优先仍用于减少无关范围与实现复杂度；发现硬依赖或验收阻断时，如实记录，不能把局部实现宣称为完成。
4. 运行 `git diff --check` 和 `pnpm sync:workspace`，如同步门禁报告当前已有文档问题，逐项记录且不得误报为本次新问题。
