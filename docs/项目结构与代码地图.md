# LFAA 项目结构与代码地图

> 这份文档专门解决“这个文件夹是什么、这个文件是干什么的、UI 从哪里开始看”的问题。
> 第一次打开项目时，建议先看本文件，再进入具体源码。

## 1. 最先记住的四个入口

如果只想知道项目怎么读，先记这四个：

```text
README.md
→ 项目是什么、怎么启动

DEVELOPMENT.md
→ 开发时必须遵守什么规则

docs/项目结构与代码地图.md
→ 每个主要目录 / 文件是干什么的

ARCHITECTURE.md
→ 各模块在整个系统中的上下游关系
```

如果是修改 Web 工作台 UI，再按下面顺序：

```text
apps/web/src/App.tsx
→ packages/app-shell/src/AgentWorkbench.tsx
→ packages/app-shell/src/agent-workbench.css
→ packages/ui/src/workbench/ResizableWorkbench.tsx
→ packages/ui/src/workbench/workbench.css
→ apps/web/src/LocalTerminal.tsx
→ apps/web/src/local-terminal.css
```

## 2. 根目录：你在资源管理器第一眼看到的东西

### 2.1 根目录文件夹

| 路径 | 人话解释 | 什么时候需要看 |
|---|---|---|
| `.git/` | Git 历史数据库。保存 Commit、分支、远程信息。只存在稳定工作区，不属于发布包内容。 | Git / Push 出问题时；平时不要手改。 |
| `.lfaa/` | 当前项目自己的 Skills、Experts、Plugins、Extensions、MCP 资源根。 | 做 Agent 扩展、插件、技能时。 |
| `apps/` | 真正可以运行起来的应用入口。 | 看 Web、Desktop、CLI、Server 从哪里启动。 |
| `crates/` | Rust 原生能力和安全 Broker。 | 做文件、进程、PTY、Sandbox、Secret 等系统能力时。 |
| `docs/` | 所有开发规范、架构、计划、日志、版本记录。 | 不知道“为什么这样做”时先看这里。 |
| `evals/` | Agent Eval 的工程级测试资产入口。 | 后续做 Agent 回归测试时。 |
| `node_modules/` | pnpm 安装出来的本地依赖缓存。不是手写源码。 | 一般不要看、不要改、不要提交为版本包差异。 |
| `packages/` | TypeScript/React 的共享业务模块和 UI 模块。 | 绝大部分应用逻辑会逐步放这里。 |
| `scripts/` | 项目治理、检查、Windows 菜单背后的实现脚本。 | Setup / Sync / GitHub / Update 或治理检查出问题时。 |

### 2.2 根目录主要文件

| 文件 | 作用 |
|---|---|
| `README.md` | 项目总入口：产品是什么、怎么启动、当前阶段。 |
| `DEVELOPMENT.md` | 当前唯一有效开发流程；规定开发前读什么、开发后更新什么。 |
| `AGENTS.md` | 给 AI / Agent 的开发入口，重复强调阅读顺序和边界。 |
| `ARCHITECTURE.md` | 当前系统总架构和不可破坏的依赖方向。 |
| `PROJECT_PLAN.md` | 当前开发顺序和模块状态。 |
| `CHANGELOG.md` | 最近版本变更索引。 |
| `lfaa.release.json` | 当前发布版本号和架构/协议版本号的机器可读事实源。 |
| `package.json` | Node workspace 根配置、pnpm 脚本、核心前端依赖。 |
| `pnpm-workspace.yaml` | pnpm workspace 范围和原生依赖构建白名单。 |
| `pnpm-lock.yaml` | Node 依赖精确锁定结果。不要手工随意编辑。 |
| `Cargo.toml` | Rust workspace 根配置。 |
| `rust-toolchain.toml` | 本项目要求的 Rust 工具链版本。 |
| `tsconfig.base.json` | TypeScript workspace 共用基础配置。 |
| `turbo.json` | monorepo 任务编排配置。 |
| `.editorconfig` | 编辑器通用格式约定。 |
| `.env.example` | 环境变量示例，不保存真实 Secret。 |
| `.gitignore` | Git 忽略规则。 |
| `NOTICE.md` | 项目归属和第三方声明入口。 |
| `LFAA-Setup.bat` | Windows 开发环境总菜单入口。 |
| `LFAA-Sync.bat` | 版本包 → 稳定工作区同步入口。 |

## 3. `apps/`：可以启动的应用

`apps/` 只放“应用入口”，共享能力尽量下沉到 `packages/`。

| 路径 | 作用 |
|---|---|
| `apps/web/` | 当前 Web 开发工作台，Vite + React。 |
| `apps/desktop/` | Electron 桌面应用骨架。 |
| `apps/server/` | 后续 Agent Server / Remote Runtime 入口。 |
| `apps/cli/` | 命令行入口。 |

每个 app 里常见文件：

```text
package.json   → 这个 app 的包名、依赖、脚本
README.md      → 这个 app 的职责说明
tsconfig.json  → 这个 app 的 TypeScript 配置
src/           → 真正源码
```

### 3.1 当前 Web 入口怎么串起来

```text
apps/web/index.html
→ apps/web/src/main.tsx
→ apps/web/src/App.tsx
→ @lfaa/app-shell / AgentWorkbench
```

`apps/web/vite.config.ts` 不负责页面长什么样，它负责本地 Vite 服务以及两个开发桥：

```text
.lfaa 资源元数据桥
真实终端 node-pty 桥
```

## 5. `crates/`：Rust 原生系统能力

TypeScript/React 不能直接越过权限层访问 OS。真正系统能力最终通过 Rust Broker。

| Crate | 作用 |
|---|---|
| `native-core` | Rust 原生能力总入口与 Broker 组合。 |
| `native-protocol` | TypeScript / Rust 之间的原生协议类型。 |
| `fs-broker` | 文件系统访问。 |
| `process-broker` | 系统进程执行。 |
| `pty-broker` | Terminal / PTY。 |
| `sandbox` | Sandbox / 进程隔离边界。 |
| `secret-store` | OS Credential Store / Secret Broker。 |
| `workspace-security` | canonical path、项目范围、安全校验。 |
| `file-watcher` | 项目资源目录监听。 |

当前大部分 crate 仍处于骨架阶段，具体状态看各自 `README.md`。

### 7.1 为什么以前你会觉得 docs 很多但看不懂代码

之前的 docs 主要做的是：

- 记录规范；
- 记录历史需求；
- 记录架构边界；
- 记录版本变更；
- 给治理脚本提供事实源。

它们**没有做好“人类第一次打开项目时的代码导航”**，也没有把关键源码文件的文件头注释强制落地。这就是本文件新增的原因。

## 8. 当前 Web UI 到底由哪些文件负责

这是当前最重要的代码关系。

### 8.1 宿主层

```text
apps/web/src/App.tsx
```

负责：

- 从 Vite 拉 `.lfaa` 资源元数据；
- 监听资源变更；
- 把资源和 `LocalTerminal` 传给 `AgentWorkbench`。

它**不负责 UI 布局算法**。

### 8.2 App Shell 层

```text
packages/app-shell/src/AgentWorkbench.tsx
packages/app-shell/src/agent-workbench.css
```

`AgentWorkbench.tsx` 决定“有哪些区域、里面有什么、按钮控制什么”。

当前结构（v0.0.47）：

```text
AgentWorkbench
└─ Workbench Stage（ResizeObserver 观察真实容器尺寸）
   ├─ Left Hover Preview（Desktop / Compact，左栏收起后临时出现）
   └─ ResizableWorkbench
      ├─ LeftSidebar
      ├─ CenterWorkspace
      │  ├─ var(--agent-shell-header-h) Center Header
      │  │  ├─ 左栏按钮 + Web 工作台标题
      │  │  └─ 更多 / 分享 / 响应式 Shell Actions
      │  ├─ Conversation
      │  └─ Composer
      ├─ RightSidebar
      │  ├─ Desktop：Right Shell Header
      │  └─ 工具与资源正文
      └─ BottomTerminal
```

响应式现在不是固定断点，而是：

```text
Workbench Stage 宽高
→ workbench-layout.config.ts
→ ratio / floor / ceiling
→ 计算左右栏 + 中央区能否同时容纳
→ Desktop / Compact / Mobile
```

参考结果：1024 左右仍可双 Dock；950 / 820 / 760 左右通常为左 Dock + 右 Overlay；约 640 及更窄进入双 Overlay。边界由公式决定，不是硬编码 viewport breakpoint。

`agent-workbench.css` 负责内容盒子视觉，并使用 `--agent-*` 变量、`rem`、`clamp()`、`calc()`；**不负责三栏拖拽数学**。

### 8.3 纯 Layout 层

```text
packages/ui/src/workbench/workbench-layout.config.ts
packages/ui/src/workbench/ResizableWorkbench.tsx
packages/ui/src/workbench/workbench.css
```

负责：

- 单一布局 Token：ratio / floor / ceiling / center / separator / hysteresis；
- 依据容器宽高计算 Desktop / Compact / Mobile；
- 左右栏宽度与历史持久化宽度重新 clamp；
- separator 拖拽；
- 动态 max 与中央区保护；
- 到动态 min 吸附收起 / Pointer Capture；
- 底部终端高度；
- 按住 Pointer 时从吸附状态反向拖回 min；
- Pointer Up 后正式收起，separator 禁止反向展开；
- Desktop 双 Dock / Compact 右 Overlay / Mobile 双 Overlay 几何。

当前动态 min 大致：左 196~232、右 228~288、Bottom 136~176；这些不是业务固定值。

不关心左栏里到底是“项目列表”还是别的内容。

### 8.4 真实终端层

```text
apps/web/src/LocalTerminal.tsx
apps/web/src/local-terminal.css
apps/web/vite.config.ts
```

数据流：

```text
用户键盘
→ xterm.js
→ Vite HMR 事件
→ node-pty
→ PowerShell / Shell

Shell 输出
→ node-pty
→ Vite HMR 事件
→ xterm.js
→ 浏览器显示
```

`vite.config.ts` 只在本地开发模式提供这个桥，不是正式 Agent Tool Runtime。

## 9. CSS 怎么看：哪个文件管哪个盒子

不要把三个 CSS 文件混着看：

```text
agent-workbench.css
→ “里面长什么样”
→ 顶栏、左栏内容、中间内容、按钮、右栏、输入框、终端外壳

workbench.css
→ “这些大盒子怎么摆、怎么拉”
→ Grid、左右宽度、separator、min 吸附收起、底部高度、Dock / Drawer 响应式

local-terminal.css
→ “终端黑盒内部怎么铺满”
→ xterm host、viewport、状态角标
```

三个 CSS 文件从 v0.0.41 起都有：

- 文件头职责；
- 关联 TS/TSX 文件；
- 盒子结构；
- 分区编号注释。

## 11. 新代码的可读性要求

以后关键实现文件不能只“代码能跑”就算完成。

必须同时做到：

1. 文件开头说明“作用 / 负责 / 不负责 / 状态归属 / 对外接口 / 关联文件 / 修改注意事项”；
2. 复杂算法写“为什么这样做”，不是逐行翻译；
3. CSS 按页面区域 / 盒子分区；
4. 新增顶层业务目录必须有 README；
5. 目录职责变化必须同步本项目地图；
6. `scripts/comment-check.mjs` 作为治理门禁防止关键文件再次漏注释。

### v0.0.48 左栏宽度链路

`ResizableWorkbench.leftWidth → onLeftWidthChange → AgentWorkbench.leftPaneWidth → --agent-left-preview-width → Hover Preview`。Hover 不是第二套侧栏，只是正式左栏真实宽度的临时投影。
