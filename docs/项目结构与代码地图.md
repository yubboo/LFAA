## 2. 根目录：你在资源管理器第一眼看到的东西

### 2.1 根目录文件夹

| 路径 | 人话解释 | 什么时候需要看 |
|---|---|---|
| `.git/` | Git 历史数据库。保存 Commit、分支、远程信息。只存在稳定工作区，不属于发布包内容。 | Git / Push 出问题时；平时不要手改。 |
| `.lfaa/` | 当前项目自己的 Skills、Experts、Plugins、Extensions、MCP 资源根。 | 做 Agent 扩展、插件、技能时。 |
| `apps/` | 真正可以运行起来的宿主入口。当前只有 `apps/web`。 | 看 Web 从哪里启动；Desktop/CLI/Server 有真实入口后才会新增。 |
| `crates/` | Frozen Rust Native Kernel。当前只保留真实工作的 `secret-store`。 | 做 Secret 或未来确实需要的 Native primitive 时。 |
| `docs/` | 所有开发规范、架构、计划、日志、版本记录。 | 不知道“为什么这样做”时先看这里。 |
| `evals/` | Agent Eval 的工程级测试资产入口。 | 后续做 Agent 回归测试时。 |
| `node_modules/` | pnpm 安装出来的本地依赖缓存。不是手写源码。 | 一般不要看、不要改、不要提交为版本包差异。 |

> v0.0.55 起，`LFAA-Setup.bat → 1/7` 会直接打印依赖位置：项目 `node_modules`、`node_modules/.pnpm`、`pnpm store path`、`pnpm-lock.yaml`、Cargo registry/git cache、Rust toolchains 与 Cargo.lock，方便排错时快速定位。
> v0.0.56 起，菜单 1 还会把“项目依赖真实可解析”和“pnpm Store 缓存健康”分开判断；Store 路径存在并不代表缓存完整，状态缓存也不代表真实依赖可用。
> v0.0.57 起，菜单 1 / 7 还会实时显示 pnpm executable、PNPM_HOME、active Store 与 Store 来源；仓库不设置项目级 `storeDir`，历史 `.lfaa/state` 不得回放旧机器路径。
> v0.0.78 起，Sync 会按依赖声明 fingerprint 判断是否保护稳定工作区已有 `pnpm-lock.yaml`；Setup 的 dependency-state 只作缓存，版本号/缓存变化本身不再触发重复安装。
> v0.0.78 起，`scripts/language-ownership-check.mjs` 把 TypeScript-first + Frozen Rust Native Kernel + Optional Python Runtime 变成机器 Gate。
| `packages/` | TypeScript 真实模块。v0.0.80 起禁止无 Consumer 的占位 workspace。 | 看 Plugin/Agent/Config/UI/App Shell/Host Adapter。 |
| `scripts/` | 项目治理、检查、Windows 菜单背后的实现脚本；`workspace-preflight.mjs` 是 Sync/GitHub 共用静态预检入口。 | Setup / Sync / GitHub / Update 或治理检查出问题时。 |

## 8. 当前 Web UI 到底由哪些文件负责

这是当前最重要的代码关系。

### 8.1 宿主层

```text
apps/web/src/App.tsx
```

负责：

- 从 Vite 拉 `.lfaa` 资源元数据；
- 监听资源变更；
- 把资源和 `LocalTerminal` 传给 `AgentWorkbench`。

它**不负责 UI 布局算法**。

### 8.2 App Shell 层

```text
packages/app-shell/src/AgentWorkbench.tsx
packages/app-shell/src/agent-workbench.css
```

`AgentWorkbench.tsx` 决定“有哪些区域、里面有什么、按钮控制什么”。

当前结构（v0.0.47）：

```text
AgentWorkbench
└─ Workbench Stage（ResizeObserver 观察真实容器尺寸）
   ├─ Left Hover Preview（Desktop / Compact，左栏收起后临时出现）
   └─ ResizableWorkbench
      ├─ LeftSidebar
      ├─ CenterWorkspace
      │  ├─ var(--agent-shell-header-h) Center Header
      │  │  ├─ 左栏按钮 + Web 工作台标题
      │  │  └─ 更多 / 分享 / 响应式 Shell Actions
      │  ├─ Conversation
      │  └─ Composer
      ├─ RightSidebar
      │  ├─ Desktop：Right Shell Header
      │  └─ 工具与资源正文
      └─ BottomTerminal
```

响应式现在不是固定断点，而是：

```text
Workbench Stage 宽高
→ workbench-layout.config.ts
→ ratio / floor / ceiling
→ 计算左右栏 + 中央区能否同时容纳
→ Desktop / Compact / Mobile
```

参考结果：1024 左右仍可双 Dock；950 / 820 / 760 左右通常为左 Dock + 右 Overlay；约 640 及更窄进入双 Overlay。边界由公式决定，不是硬编码 viewport breakpoint。

`agent-workbench.css` 负责内容盒子视觉，并使用 `--agent-*` 变量、`rem`、`clamp()`、`calc()`；**不负责三栏拖拽数学**。

### 8.3 纯 Layout 层

```text
packages/ui/src/workbench/workbench-layout.config.ts
packages/ui/src/workbench/ResizableWorkbench.tsx
packages/ui/src/workbench/workbench.css
```

负责：

- 单一布局 Token：ratio / floor / ceiling / center / separator / hysteresis；
- 依据容器宽高计算 Desktop / Compact / Mobile；
- 左右栏宽度与历史持久化宽度重新 clamp；
- separator 拖拽；
- 动态 max 与中央区保护；
- 到动态 min 吸附收起 / Pointer Capture；
- 底部终端高度；
- 按住 Pointer 时从吸附状态反向拖回 min；
- Pointer Up 后正式收起，separator 禁止反向展开；
- Desktop 双 Dock / Compact 右 Overlay / Mobile 双 Overlay 几何。

当前动态 min 大致：左 196~232、右 228~288、Bottom 136~176；这些不是业务固定值。

不关心左栏里到底是“项目列表”还是别的内容。

### 8.4 真实终端层

```text
apps/web/src/LocalTerminal.tsx
apps/web/src/local-terminal.css
apps/web/vite.config.ts
```

数据流：

```text
用户键盘
→ xterm.js
→ Vite HMR 事件
→ node-pty
→ PowerShell / Shell

Shell 输出
→ node-pty
→ Vite HMR 事件
→ xterm.js
→ 浏览器显示
```

`vite.config.ts` 只在本地开发模式提供这个桥，不是正式 Agent Tool Runtime。

## 11. 新代码的可读性要求

以后关键实现文件不能只“代码能跑”就算完成。

必须同时做到：

1. 文件开头说明“作用 / 负责 / 不负责 / 状态归属 / 对外接口 / 关联文件 / 修改注意事项”；
2. 复杂算法写“为什么这样做”，不是逐行翻译；
3. CSS 按页面区域 / 盒子分区；
4. 新增顶层业务目录必须有 README；
5. 目录职责变化必须同步本项目地图；
6. `scripts/comment-check.mjs` 作为治理门禁防止关键文件再次漏注释。

### v0.0.48 左栏宽度链路

`ResizableWorkbench.leftWidth → onLeftWidthChange → AgentWorkbench.leftPaneWidth → --agent-left-preview-width → Hover Preview`。Hover 不是第二套侧栏，只是正式左栏真实宽度的临时投影。
