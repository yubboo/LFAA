# 弹窗规范（强制）

> 状态：已实施（2026-11-27 负责人确认：确认弹窗只能按钮关闭、手机端弹窗改底部弹层）。
> 适用：`@lfaa/ui-primitives` 的 `ModalDialog`（表单 / 重命名等普通弹窗）与 `ConfirmDialog`（删除 / 移出 / 卸载等破坏性二次确认），以及任何新建的模态弹窗。
> 参照实现：`packages/ui/primitives/client/ModalDialog.*`、`packages/ui/primitives/client/ConfirmDialog.*`。

弹窗是「打断当前操作、必须先处理」的一层，不是第二个页面，也不是悬浮卡片。桌面端居中、手机端贴底，关闭方式按「是否破坏性」分成两套。

## 1. 两种弹窗

| 组件 | 用途 | 关闭方式 |
|---|---|---|
| `ModalDialog` | 表单、重命名、详情等**非破坏性**内容 | 取消 / 关闭按钮、点遮罩、Esc |
| `ConfirmDialog` | 删除、移出项目、卸载、删除凭据等**破坏性**确认 | **只有**取消、确认、右上角关闭 |

破坏性确认不提供隐式退出：

- 点遮罩不关闭；Esc 不关闭，并在捕获阶段 `preventDefault` + `stopPropagation`，避免连带关掉背后的菜单或浮层。
- 两种「想关但关不掉」的输入都要有**动作反馈**：整卡横向轻抖一次（约 360ms、幅度 ≤7px、逐次收敛）。只抖不弹文案、不加描边框，避免噪声。
- 系统开启「减少动效」（`prefers-reduced-motion: reduce`）时完全静默，不做位移。
- 理由：确认识别的是一次不可逆操作，误触关闭等于让用户以为自己「取消过了」；抖动明确告诉他「外面点不掉，请选一个」。
- 悬浮卡片的「点外部 / Esc 关闭」规则**不适用**于确认弹窗（见 [floating-cards.md](floating-cards.md)）。

## 2. 桌面端（> 767px）

- 遮罩：`position: fixed` 铺满、`--color-scrim`、`backdrop-filter: blur(5–6px)`，吃掉遮罩上的点击。
- 卡片：居中，宽度按内容档位 `sm 26rem / md 34rem / lg 46rem`，最大高度 `min(86vh, 46rem)`。
- 圆角 1–1.25rem，四边全圆；内容超高时在卡片内部滚动（`ModalDialog` 的 body 区 `overflow-y: auto`）。
- 关闭按钮在右上角，尺寸 2rem 左右，hover 有背景。

## 3. 手机端（≤767px）：底部弹层

断点与 `floating-cards.md` 的窄屏口径一致：`@media (max-width: 767px)`。

- 位置：`align-items: end`，遮罩不留内边距，弹层**贴住视口底边**，宽度 100%。
- 圆角只留上沿（1.2–1.25rem），下沿为 0，边框去掉底边。
- 安全区：底部内边距叠加 `env(safe-area-inset-bottom)`，iPhone 横条不压按钮。
- 高度：`max-height: min(88vh, 88dvh)`，内容超高时在弹层内滚动，不撑破视口。
- 进场：从下往上 220ms（`translateY(24–28px)` + 淡入），不使用居中卡片的缩放动画。
- 按钮：`ConfirmDialog` 的取消 / 确认等宽铺满，触控高度 ≥ 44px（2.75rem）。

## 4. 文案与结构

- 标题一行说清「删哪个对象」；说明一段，写清后果与不可恢复。
- 破坏性按钮用危险色，放在右侧（桌面）或右侧等宽位（手机），取消在左。
- 不在弹窗里放多余的解释性小字、规则摘要或快捷键提示。

## 5. 交付自检

1. 桌面 1440×900：卡片居中，四边圆角，宽度按档位。
2. 手机 390×844：贴底、整宽、上圆角、下圆角为 0，按钮 ≥ 44px，无横向滚动。
3. 深色与浅色两套主题各看一眼：遮罩、卡片底色与文字对比正常。
4. 破坏性确认：点遮罩与 Esc 都不关闭；取消 / 确认 / 右上角关闭都能正常退出。
5. 控制台 0 报错；关闭后背景滚动恢复。
