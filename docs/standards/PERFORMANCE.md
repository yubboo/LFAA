# LFAA 性能与资源预算规范

## 1. 先定义预算再优化

涉及运行时、数据库、UI、网络、Agent、Tool 或大文件的模块，在进入 `in-progress` 前必须在 Plan 写明：

- 测量场景和数据规模；
- P50 / P95 / P99 延迟；
- 吞吐或最大并发；
- CPU、内存、磁盘和网络预算；
- 超时、取消和背压策略；
- 可接受回归阈值。

没有测量场景的“性能很好”不算验收条件。

## 2. 回归门禁

- 基准必须保留机器、数据集、命令和结果；
- 超过模块 Plan 规定的回归阈值时检查失败；
- 接受回归必须记录原因、影响和恢复计划；
- 不得用关闭测试或缩小真实数据集掩盖退化。

## 3. UI / Desktop / Web

至少测量冷启动、首屏、主要交互响应、长列表、流式输出和内存稳定性。

UI 主线程不得执行数据库、文件扫描、模型调用或阻塞式系统操作。

## 4. Agent / Model / Tool

至少记录首 token、完整响应、工具等待、重试、成本、取消时间和并发队列长度。

所有外部调用必须有 timeout、取消、有限重试、退避和并发上限。

## 5. Event Store / SQLite

必须定义：

- 单写者或并发写模型；
- 事务边界和 busy timeout；
- WAL 策略；
- 索引和慢查询预算；
- Event snapshot、compaction、retention；
- 启动重放与 Crash Recovery 时间预算；
- Migration 在目标数据规模下的时间与空间预算。

## 6. Observability

Trace、Metrics 和日志必须限制基数、单条大小、缓冲区和保留期。

观测系统不得无限增长或阻塞主执行链。
