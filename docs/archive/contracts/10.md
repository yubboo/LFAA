## LFAA-COMPUTER-USE-LOCAL-GAMES-20261008：发现本机应用与游戏并按用户选择启动

### 用户目标、运行入口与 Owner

- Windows `desktop` Profile 中，Agent 能按用户给出的自然语言游戏名查找当前电脑实际安装的游戏/应用，并启动对应的 Steam 客户端或 Windows 开始菜单快捷方式；用户未指定游戏时，模型读取可用的 LFAA 启动请求记录，向用户提出选择后才启动。
- 运行入口仍是 `apps/cli/config/profiles/desktop` 中装配的本机 Control Plane。目录读取、目录项校验、启动调度与短期推荐历史归 `packages/computer-use/computer-use`；模型目标理解与 Tool 选择归现有 Agent Loop，用户选择复用 `lfaa_ask_user`；副作用授权复用现有 Tool Approval Owner。
- 只扫描当前 Windows 用户与所有用户的开始菜单 `.lnk` 目录，以及从当前 Windows Steam 注册安装位置和其 `libraryfolders.vdf` 指向目录中枚举的已安装 `appmanifest_*.acf`。不读取 Steam 账户、云端/网络 API 或游戏存档。个性化游戏历史仅记本 Control Plane 进程当前生命周期内、按 LFAA 账户隔离的 Steam 游戏启动请求次数和最近请求时间；Control Plane 重启后历史清空，不代表实际游戏时长或 LFAA 外启动的游戏。开始菜单快捷方式可按名搜索和启动，但来源无法可靠分类为游戏，因此不计入游戏推荐。

### 设置、权限、安全与性能

- 设置中心复用 `computerControl.enabled`（账户级，默认关闭）控制相关工具是否可见及每次执行时是否允许；启动动作标为 `dangerous` 并复用 `permissions.mode`、完整审批参数和记忆授权规则。`full_access` 仍受电脑操控账户开关约束；其他模式按既有规则审批或拒绝。只读目录查询标为 `read`。不新增设置字段。
- 开始菜单路径和 Steam 安装目录只从已知系统位置/注册表读取；模型只接触不透明目录项 ID、显示名和启动器类别，不接收本机绝对路径或可执行参数。启动 ID 必须在同一用户、同一 Agent Run 的搜索/推荐中实际返回；启动前重新扫描、核对安装状态并重验设置开关，再仅将已发现的 Windows `.lnk` 路径交给 Explorer，或把经清单校验的数字 AppID 传给 Steam `-applaunch`。子进程使用 `shell:false`，不接受 `cmd`、PowerShell、任意 Shell 字符串、任意路径或模型自带启动参数。
- 不指定目标时模型不得自行挑选并启动；先展示真实推荐/候选，再通过 `lfaa_ask_user` 等待选择。候选 ID 按用户和 Agent Run 隔离、每项一次性消费，Run 清理时删除；无历史时明确当作新记录，不称为常玩。自然语言搜索无匹配或多匹配时如实报告或继续澄清。
- 目录枚举、文件数、文件大小、用户历史、运行候选数均设上限；使用异步 I/O，不建立轮询/后台发现；进程生命周期结束清除有限的内存历史与目录缓存。启动工具只报告 Windows/Steam 客户端已接收启动请求，不伪称游戏已经运行或进入游戏画面。

### 允许修改与禁止修改

- 允许修改 `packages/computer-use/computer-use/**`、直接相关的 Agent Loop 工具说明/摘要、当前电脑操控设置页说明、对应长期 CLI 回归、`docs/PROMPTS.md`、`docs/系统总体架构.md`、`docs/开发计划.md`、目标包 README 与所需工作区清单/锁文件。
- 不装配到 Web Profile 或远程 Daemon，不新增第二个 Shell/Host/游戏业务执行器，不连接第三方账户/网络 API，不安装游戏、不启动真实游戏、不扫描游戏进程或读取存档，不持久化历史、不添加/重置用户偏好，不重启当前服务、不提交/推送/发布。

### 验收条件

- 合成 Start Menu/Steam 夹具覆盖发现、含引号/反斜线的 VDF 路径、Steam AppID 不匹配、卸载/越界条目排除、空结果与开始菜单扫描上限；回归覆盖账户历史隔离、普通快捷方式不计入游戏历史、猜测 ID 拒绝、未知/卸载目标拒绝及 Agent Run 候选清理。
- 禁用账户、非 Windows/非桌面 Profile 不得使用该功能；开始菜单路径不能从模型参数注入。Mock spawn 确认从不启用 Shell，Steam 参数仅为固定 `-applaunch` 与经清单校验的数字 AppID，快捷方式只来自允许的开始菜单根。
- Tools 由模型根据自然语言和真实目录结果选择，不增加关键词业务路由；推荐和澄清不触发启动；一次用户选择后危险启动仍经过当前 `permissions.mode`。会话/工具历史不保存本机绝对路径、目录清单或启动结果原文。
- 运行本地应用定向回归、`lfaa-computer-use`/Control Plane 与共享设置 UI 构建或类型检查、工作区实际可用 Gate 和差异检查；真实 Windows 快捷方式/Steam 客户端启动、Provider 问答、浏览器设置交互、安装包实机与帧时间分别如实标记。

### 实施记录

- 已实现 Windows `desktop` Profile 的本地目录工具：Start Menu `.lnk` 和注册 Steam 客户端的已安装库；自然语言映射由 Agent Loop 完成。未知游戏时工具返回当前 LFAA 启动过的 Steam 游戏、最近请求和频繁请求，或冷启动 Steam 候选，模型使用 `lfaa_ask_user` 等待用户选择。Windows 开始菜单快捷方式依旧能精确搜索/启动，但不伪称是已识别游戏。实际用户选择流程由模型提示与既有结构化问答工具衔接，Provider 端到端仍待实机确认。
- 启动 ID 限定为本轮真实工具结果之一，同一用户/Agent Run 隔离并一次性消费；目标每次重新扫描且必须仍安装。只创建固定 Explorer/Steam 子进程，`shell:false`；返回 `launch_requested` / `unverified` 表示启动请求已收，不代表游戏窗口已出现。推荐历史只存当前运行期 LFAA 发起的 Steam 启动请求，不读账户游玩时长，Control Plane 重启清空。
- 使用现有设置：`computerControl.enabled`（账户级，默认关闭）和 `permissions.mode`（沿用用户当前风险策略）；未新增设置或重置用户偏好。设置 UI 文案已说明发现来源、启动权限模式和推荐数据范围。
