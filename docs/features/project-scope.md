# 项目范围锚定（Project Scope）开发方案

## 1. 要解决的问题

当前项目只有名称与本机目录，Agent 运行时的系统提示只告诉模型「已绑定项目」与授权目录，模型并不知道这个项目要做什么。于是：

- 在项目里新建会话时，模型可以把任何话题当成当前任务执行，产出与项目目标无关的代码、文件或结论；
- 会话侧栏按项目分组，用户预期「项目里的会话都在做这个项目的事」，实际没有约束；
- 项目本身没有可复用的目标说明，每个新会话都要靠用户重复交代。

本方案让项目拥有可编辑的「项目简介」，并在每个绑定该项目的会话运行时把项目范围写入系统提示，形成可执行的防跑偏策略。

## 2. 使用流程

1. **创建项目**：选择本机文件夹后，Host 读取 README / package.json / 顶层结构生成一段简介初稿，填入「项目简介」并允许修改；留空时由 Host 再次兜底生成。
2. **编辑项目**：项目操作菜单 → 编辑项目 → 修改项目名/目录/简介，可点「重新生成」按目录刷新初稿。
3. **在项目里开新会话**：会话继承项目绑定；切到「工作」模式时，空会话的输入栏上方出现一条单行的项目范围提示（`本项目专注「项目名」 · 简介`，简介未填写时提示先确认目标），完整规则放在悬停提示里；「聊天」模式不显示这条提示。
4. **运行**：系统提示新增项目范围段，包含项目名、简介、范围规则与跑偏处理要求。
5. **跑偏**：用户请求明显超出项目范围时，模型先说明「这看起来不属于本项目范围」，再询问是否仍在本项目继续，或改用项目外聊天/新建项目；未获确认前不执行无关修改、命令或生成。

## 3. 数据与公开契约

`@lfaa/workspace`

- `WorkspaceProjectSummary` 继承 `WorkbenchProjectItem.description`，作为项目简介（≤500 字符，空表示未填写）。
- `CreateProjectInput` / `UpdateProjectInput` 增加可选 `description`；创建时缺省或为空则调用自动生成。
- 新增 `DraftProjectBriefResult { brief: string; sources: string[] }`。
- 新增 `WorkspaceService.draftProjectBrief(name, rootPath)`：只读读取 `README.md`、`README.zh.md`、`README`、`package.json` 与顶层条目，生成确定性简介；不写文件、不调用模型。
- 新增 `WorkspaceService.getProject(projectId)`，供装配层解析项目范围。
- 新增 `POST /api/workspace/projects/draft-brief`（入参 `{ name, rootPath }`）。
- 创建/更新项目的请求体接受 `description`。

`@lfaa/agent`

- 新增 `ProjectScope { projectId, name, description? }`。
- `AgentService.setProjectScopeProvider(provider | null)`：装配层注册，按 `projectId` 解析项目范围；未注册或找不到时按未填写处理。
- `RunExecutionParams.projectScope?: ProjectScope`，由 `beginAgentRun` 在解析授权目录后取得。
- 系统提示新增「项目范围」段（紧跟在会话工作位置之后），内容为项目名、简介与防跑偏规则；项目简介缺失时要求模型先只读了解项目再与用户确认目标。

装配：

- `@lfaa/bundle-web` 的联线插件注册 `ctx.agent.setProjectScopeProvider(...)`，数据源为 `ctx.workspace.getProject`。
- `@lfaa/chat` 空会话读项目列表中的 `description`，在「工作」模式的输入栏上方展示单行范围提示，不新增 Host 接口。

## 4. 关键交互

| 场景 | 交互 |
| --- | --- |
| 创建项目选好目录 | 简介区显示「正在根据目录生成初稿…」，完成后填入文本域；用户编辑后不再自动覆盖；可点「重新生成」 |
| 目录为空 / 没有 README | 生成「本机目录项目，尚未填写项目目标与交付范围」类兜底文案，提示用户补充 |
| 编辑项目 | 简介文本域可清空，保存后为空即视为未填写 |
| 项目详情右栏 | 增加「项目范围」一行，显示简介或「未填写」 |
| 项目内新会话 | 「工作」模式空会话在输入栏正上方显示一条单行提示（项目名 + 简介，超出省略，悬停看完整规则）；「聊天」模式与已发消息后的停靠输入栏不显示；未绑定项目的会话不显示 |
| 跑偏 | 模型先说明再询问，不直接拒绝也不静默执行 |

## 5. 实施顺序

1. `@lfaa/workspace`：契约、简介生成器、服务、HTTP、Client Store。
2. `@lfaa/workspace` Client：创建/编辑弹窗的简介字段（抽为独立组件，避免弹窗继续膨胀）、项目详情展示、双语文案。
3. `@lfaa/agent`：范围提供器、运行参数、系统提示段与单元测试。
4. `@lfaa/bundle-web` 装配；`@lfaa/chat` 空会话范围卡片与文案。
5. 测试、检查、构建与内置浏览器深/浅色实测。

## 6. 验收条件

- 新建项目后 `~/.lfaa/projects.json` 含非空 `description`，创建弹窗可看到自动初稿并可改。
- 绑定项目的会话运行时，系统消息包含项目名、简介与防跑偏规则；未绑定项目的会话不包含。
- 项目内新会话：切到「工作」模式显示范围提示条；项目无简介时显示「未填写」提示而不是空白；「聊天」模式不出现该提示。
- 跑偏请求在模型回复中先说明范围并询问，不直接产出无关文件。
- `pnpm check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过；内置浏览器深/浅色实测通过。

## 7. 风险与回滚

- 简介自动生成是启发式，可能不准确：字段可编辑、可清空，模型在简介缺失时被要求先确认目标。
- 系统提示变长：范围段控制在数行，且只在绑定项目时出现。
- 旧项目没有 `description`：读取缺省为未填写，不迁移、不报错；下次保存或创建时补全。
- 回滚：移除范围提供器与提示段即可恢复现状，数据字段向后兼容，旧客户端忽略新字段。
