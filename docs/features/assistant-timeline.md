# 助手回复过程

负责人已确认六张参考图所示的交互与验收条件，并明确要求开工。A1 范围限于现有聊天消息流、会话回看和工具详情，使用 LFAA 自有主题与工作区布局。

- 运行中，顶部显示「思考」和本轮已经过的时、分、秒，实际模型或工具阶段可在展开后的详情中查看。用户可见的模型正文逐段流出，同轮真实活动跟在正文之后。活动组和单条操作均可展开。审批卡在需要确认时直接显示。
- 完成后，顶部显示「用时」和本轮总计的时、分、秒，并控制整段过程的展开。最终答复和现有交付卡片保持可见。展开过程后，进度正文和工具轨迹按原顺序列在最终答复前。
- `@lfaa/agent` 在工具轮结束正文的位置记录 UTF-16 偏移。会话消息使用可选 `progressText` 保存偏移对应的正文前缀，`content` 仍是最终答复。可选 `runDurationMs` 记录实际运行用时。步骤中的可选模型阶段和命令详情沿用步骤事件、快照和会话持久化。结束事件携带已写回的助手消息。旧记录继续读取，缺失的历史片段无法还原。
- 实施涉及 Agent 循环与运行收尾、Memory 的消息和轨迹类型、Tools 的终端结果，以及 Chat 的流消费与回复组件。命令仍经现有授权路径，详情采用有长度上限的纯文本。适用的开发与更新日志同轮补齐。
- 先验证 Host 的偏移、真实工具及退出码、会话写回，再验证 Web 流、历史回看和两级展开。内置浏览器覆盖浅色和深色，并检查刷新后的历史与窄屏展示。回滚仅撤销本轮差异，新增的可选会话字段对旧版本读写无迁移要求。
- 验收时重启用户实际访问端口的本地 Host，并以新回复的结束事件和会话 API 核对正文。Vite 的前端热更新会更新展示，Host 的流式与持久化代码在重启后加载。
- 聊天视口在接近底部时跟随流式正文、工具和输入栏带来的高度变化。主动上滚阅读历史时保持当前位置，回到底部后继续跟随。滚轮上滚在默认滚动发生前就交出滚动所有权，内容继续增长也不会把视口拽回底部；聊天和左侧会话列表的滚动条为相邻的分隔手柄预留独立操作空间。

## 活动动效与文件变更联动

负责人要求实时展开执行过程、区分创建和编辑及命令反馈，并用现有右栏打开文件记录。运行中可独立展开或收起过程。活跃工具有局部渐变，状态和图标随实际事件切换，展开及右栏切换采用短缓动并尊重减少动态效果设置。

`@lfaa/tools` 内置写入和编辑工具在成功执行后返回真实操作类型、路径和有上限的前后片段。Agent 以可选 `fileChange` 保留这些数据，随步骤事件和会话恢复。聊天 Store 用会话、消息和步骤定位选中的文件，右栏沿用现有能力面板的挂载点。旧记录可以查看原有操作详情；有项目映射的相对路径可查看当前 Git 差异。

按工具记录、Host 持久化、聊天行与右栏联动、动效的顺序实现。验收覆盖实际写入、编辑、命令、查看右栏、刷新回看、双主题和减少动态效果。回滚仅撤销对应增量；新增步骤字段对旧会话可选。

负责人补充右栏以文件标签页呈现。点击文件默认打开带行号的只读源文件，选择同一个文件复用标签并定位本次变更，标签可切换、关闭。工具栏切换本次更改与当前文件，聊天仍在工作区。读取 API 通过会话、助手消息和成功步骤定位路径，再用当前工作区授权校验，不接受浏览器提供任意文件路径。文件源文本按大小限制，超出范围或读取失败时明确提示，已保存的更改仍可切换查看。

## 工具实时进度

收到 Provider 的工具名增量时，沿用步骤事件发布准备状态。只有完整调用通过参数校验及现有审批后才进入真实执行。浏览器在同一活动组中原位更新状态，完成后按操作类型显示结果，可继续展开或打开变更文件。验收用分段的真实 SSE 请求覆盖准备、执行、会话回看和双主题。未提供工具增量的 Provider 从收到完整调用开始报告状态。

相邻工具轮之间没有新的用户可见正文时，步骤继续追加到已展开的活动组。命令子行运行时在正文前显示进度，成功后在行尾的展开箭头前显示勾，完成后的详情保留输出及退出码。

第一轮尚无工具时，也可展开实时状态。15 秒无增量后显示在等待模型或剩余工具参数。Host 每个模型轮限制 45 秒静默、10 分钟总时长、连续 3 分钟或 128,000 字符的纯推理；`supportsReasoning` 为真的模型放宽到 10 分钟连续推理、20 分钟总时长与 256,000 字符。工具参数增量计入进展。符合条件的重试通过真实步骤事件显示，停止时保留已产生的可见消息和工具记录。

## 尾部持续执行状态与工程步数优化

流式输出期间，时间线尾部状态可直接展开查看轮次、最新活动和最近完成的操作。稳定的步骤起点与后续更新时间共同随 SSE、快照和历史透传，刷新后继续计时。旧记录使用稳定的消息时间。参数流记录已接收的字符数及已解析的文件目标，实际写入完成后再显示变更。命令详情随真实输出更新，结束时标记结果和退出码。

活跃文字使用当前强调色与正文色生成流动渐变，等待执行的圆环旋转，确认等待及终态采用静态反馈，并尊重系统减少动态效果设置。概览打开时读取当前会话的后台任务、子智能体和项目 Git 状态，前台命令使用聊天已有的实时步骤。

针对多文件工程与构建任务，`@lfaa/agent` 默认步数上限由 `10` 提升至 `28`，收口轮次同步支持推理进展事件，系统提示词加入独立文件并行调用、匹配当前 Shell 语法与实测核验约束；`@lfaa/shell` 单次命令超时由 `15s` 调整为 `90s`；`@lfaa/skills` 新增内置 `minecraft-plugin-dev` 技能。

## 长任务预算、命令时限与工具轨迹

工程任务的实际耗时集中在多轮工具调用，单轮 28 步会在构建、测试、修复闭环尚未完成时收口。默认步数预算改为 `100`：预算用尽且上一轮确实执行过工具时，自动追加 `100` 步继续推进，单轮硬上限 `300` 步；显式传入 `maxSteps` 仍视为硬上限。步数提示只在剩余不超过 8 步时写入系统提示，其余轮次保持前缀稳定以复用提示缓存；接近上限时提示先交付可运行的一小步。子智能体默认 40 步硬上限。

前台命令默认时限由 `90s` 调整为 `10` 分钟，`run_command` 可用 `timeoutMs` 指定 `5s`–`30min`；达到时限时命令标记为超时，并自动转入后台任务继续执行（返回任务 ID，用 `get_background_task` 轮询）。步骤轨迹只保留命令输出尾部 `200` 行 / `8,000` 字符，工具步骤与增量正文共用 `180ms` 持久化节流，避免命令高频输出时反复全量重写会话文件。

内置文件工具新增 `glob`（按文件名模式）与 `grep`（正则内容检索，可 `include` 过滤），`edit_file` 改为唯一命中校验：多处命中时拒绝执行并给出行号，可显式传 `replaceAll`。会话上下文附带历史工具轨迹要点（已改文件、已跑命令、工具计数），运行结束时以确定性方式滚动写入会话摘要，长会话恢复时不再重新探索同一批文件。

## 运行内上下文、崩溃恢复与命令安全

一次运行内的上下文按字符预算管理，默认 `160,000` 字符。每轮发送前先压缩早期工具结果（尾部片段），仍超预算时从最早处整组丢弃，并插入可复用的压缩说明；首条系统提示、最近 4 轮和最后一条用户请求始终保留。供应商返回上下文超限时，强制压缩到一半预算后重试一次，不再直接把整轮判为失败。单条工具结果进入模型前统一限长：`read_file` 16,000 字符、`grep`/`glob`/`search_files` 12,000 字符、命令保留末尾 8,000 字符，并在截断处提示续读方式。模型因长度上限截断（`finishReason=length`）时，系统提示会要求拆分写入。

应用启动时结算上次退出遗留的运行：没有活跃运行的 `streaming` 助手消息改为 `aborted`，保留中断前内容与步骤并补一条中断说明，同时清理写入中断产生的 `.tmp` 文件；启动日志只输出计数，不读取消息正文。

命令执行具备基线安全约束：前台命令达到时限时使用 `taskkill /T`（其他平台先用进程组）终止整棵进程树，避免残留子进程；子进程环境剔除模型供应商密钥（如 `OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`AWS_SECRET_ACCESS_KEY`），保留构建与包管理器所需变量；引用 `llm-config.json`、`smart-approvals.json`、`.lfaa/credentials`、`.lfaa/sessions` 的前台与后台命令会被拦截；每条命令写入 `~/.lfaa/logs/commands.jsonl` 审计（可用 `LFAA_COMMAND_AUDIT_LOG` 覆盖路径）。命令仍以当前用户权限运行，没有 OS 级路径隔离，该限制在系统提示中如实告知。

## 记忆闭环、只读并行与用量计量

长期记忆原先只有写入工具，缺少“什么时候该写”的引导，等于只读不写。系统提示新增记忆准则：用户明确陈述跨会话仍需记住的偏好、约定或项目约束时调用 `save_memory`，一次一条、只记可独立复述的事实。模型未主动保存时，运行结束会按句提取命中「记住 / 以后统一 / 不要再 / 偏好 / 约定」的明确陈述（最长 200 字符）写入当前项目或全局记忆，并在时间线留下「已自动沉淀长期记忆」步骤；普通任务描述不会命中。下一次运行通过召回写入 system 提示，形成“写回 → 召回”的完整闭环。

在显式偏好之外，收口还会用当前模型做一次低成本提炼（最多 3 条，8 秒超时，失败静默），把本轮结论、决策与踩坑转成带 `kind` 的结构化记忆，成功时在时间线留下「已自动提炼长期记忆」步骤。召回复核见 [记忆系统](agent-memory.md)。

同一轮中连续的只读工具（`read_file`、`grep`、`glob`、`list_dir` 等）最多 4 个并行执行，写文件、命令与需要审批的调用保持串行；步骤与工具消息始终按模型给出的调用顺序回填，工具调用与结果配对不变。这样同一轮的多文件读取不再串行消耗时间，也不改变审批与副作用顺序。

每轮供应商返回的用量会累加为单次运行的 `tokenUsage`，随助手消息持久化（`ChatMessageRecord.tokenUsage`），并通过运行状态与消息接口暴露；供应商未返回用量时字段缺省。OpenAI 兼容流式请求声明 `stream_options.include_usage` 以获取末尾用量分片，若服务不识别该字段，会自动去掉并重试一次，不影响正常调用。完成态在时间线顶部用时旁显示紧凑用量（如 `1.2k tokens`），流式进行中不显示；该文本复用既有次要文字颜色，深色与浅色主题都保持可读。

输入框下方是会话状态栏，提供三个可点击入口：上下文占用、Token 用量、会话统计，分别展开锚点浮层；没有会话数据时整条不显示。数据来自各助手消息持久化的 `tokenUsage` 与新增的 `metrics`，缓存 token 由适配器解析（OpenAI `prompt_tokens_details.cached_tokens`、DeepSeek `prompt_cache_hit_tokens`、Anthropic `cache_read_input_tokens`、Gemini `cachedContentTokenCount`、Responses `input_tokens_details.cached_tokens`），供应商未返回时对应指标缺省。

`metrics` 在 Host 侧按真实执行过程采集：`llmMs` 为每轮模型请求墙钟时间之和，`toolMs` 只累计工具实际执行时间（不含审批等待），`ttftMs`/`ttftSteps` 记录首 token 延迟与样本数，`decodeMs`/`decodeTokens` 用于计算输出速度（TPS），`context` 记录本轮实际发送的系统提示、工具定义与对话消息 token 估算（按 4 字符/token 的固定密度估算，与 DSH token-meter 口径一致）。

上下文百分比只在模型配置填写了「上下文窗口（tokens）」时显示，按 `(系统提示 + 工具定义 + 对话消息) / 窗口` 计算；未配置时只显示估算用量与构成，不伪造窗口比例。Token 浮层展示总计、缓存命中率、未缓存输入、缓存读取与输出；会话统计浮层展示轮次与工具步数、模型用时、工具调用用时、平均首 token 延迟与输出速度。

## 完成前自检与审计轮转

运行会在内部记录最后一次代码修改与最后一次验证命令所在的轮次。`write_file`/`edit_file` 命中代码或配置扩展名（如 `.ts`、`.java`、`.json`、`.css`）时视为“需要验证”；`run_command` 命中 `pnpm/npm/mvn/gradle/go/dotnet` 等运行器并带 `build/test/lint/typecheck/package` 动作，或直接调用 `tsc` 时视为“已尝试验证”。当模型准备收口、代码修改晚于最后一次验证且还有至少 2 步预算时，时间线插入「完成前自检」步骤，并向模型追加一次要求补验证或说明原因的消息；每次运行最多提示一次，模型说明原因后即可结束，未验证结束时保留「模型未执行验证即结束」步骤，不伪装成通过。只改文档不会触发。

命令审计写入 `~/.lfaa/logs/commands.jsonl` 前按大小轮转：默认单文件 5 MB、保留最近 3 份；`LFAA_COMMAND_AUDIT_MAX_BYTES` 与 `LFAA_COMMAND_AUDIT_KEEP_FILES` 可覆盖（供测试或特殊环境使用）。

项目首次运行时，Host 会在绑定目录创建 Git 基线提交，供右栏审查与回退使用。提交前先枚举 `.gitignore` 之外的未跟踪与已跟踪文件，命中 `.env`、`*.pem`/`*.key`、`credentials/`、`secrets/`、`id_rsa`、`.npmrc` 等疑似密钥名称时跳过自动基线，并在运行轨迹中记录可见错误，避免把密钥写进项目历史；被 `.gitignore` 忽略的文件不会被提交。

## 思维链与工具链全程可视化、排版净化与全站流式性能优化

负责人确认四项界面与性能升级方向：欢迎页统一采用轻量无边框行风格并对齐中轴、AI 回复正文彻底回归干净标准 Markdown 排版、流式执行过程全程默认展开展示交错的思维链与工具链（每段思考与每个工具调用随时可展开/收起）、系统性消除流式输出期间的整页卡顿与滚动回流。

- **后端思维链与工具目标契约（向后兼容旧会话）**：
  - `@lfaa/agent` 的 `delta(kind="reasoning")` 事件附带可选 `iteration`，每轮思考结束时将本轮完整思考文本（上限 `24,000` 字符）写入对应 `think-${iteration}` 步骤的 `detail`，并保留 `startedAt` 用于计算该轮思考耗时。
  - 工具执行器按参数动态提取直观的 `toolTarget`（依次适配 `path` / `filePath` / `directory` / `pattern` / `query` / `glob` / `url` / `command` / `role` / `title` / `name` 等，不写死固定工具白名单），并将 `argsPreview` / `resultPreview` 预览上限放宽至 `1,200` 字符以便原地展开查看细节。
- **前端交错式流式时间线（默认全程展开）**：
  - 按真实轮次顺序交错展示「思维链块（脑形图标 + 思考中… / 已思考 · 耗时 + 左侧柔和引导线）→ 过程说明正文 → 工具链列表（左侧引导线串联，依据工具类型与参数动态呈现动作/工具名与目标参数，保持 §2.3 活动行左对齐与行尾固定展开位）→ 最终答复」。
  - 思维链与工具链在流式运行中全程展开，运行结束后折进一行总行（2026-11-27 调整，见文末「过程总行」一节）；仍支持单击任意思维块、任意工具行或顶部总行随时收起或展开。
  - **思维链正文限高滚动与流式贴底**：思考正文区域复用 `@lfaa/ui-primitives` 的 `ScrollArea` 并限制最大高度（桌面 `15rem` / 窄屏 `12rem`），短思考自然贴合高度不显示滚动条；超过阈值后原地出现统一细滚动条并按可滚方向展示柔和边缘渐隐。流式思考时同步贴底跟随最新推理，用户主动上滚立即暂停跟随，滚回底部自动恢复；思考结束后保持同样限高与滚动条，避免页面突然撑开跳动，也不影响下方工具链与正式答复的可见性。
