## 1. 要解决的问题

1. **工作模式下项目入口重复**：输入框上方挂载条（`ComposerScopeBar`）与输入框左下角（`ComposerAddMenu`）同时显示 `📁 项目名`，后者覆盖了 `+` 按钮且点开第一项仍重复列项目，形成视觉冗余与二级套娃。
2. **项目绑定规则不一致**：
   - 在项目内打开新聊天、切换历史会话或从输入框选好项目后，切到 `workspace` 时 `workbench.activeProjectId` 被清空为 `null`，导致左二会话项目菜单栏顶部「新聊天」丢失当前项目上下文；
   - 左二「最近」分组标题右侧的新会话按钮复用了顶部「新聊天」回调，无法区分「继承当前项目」与「项目外独立新会话」；
   - 聊天模式下绑定项目时，输入框左侧缺少紧跟 `+` 按钮的独立项目胶囊。
3. **缺少用户操作记忆**：空会话草稿绑定的项目/分区、左二项目文件夹展开收起态、最后点击的项目分组键刷新后全部重置，未能延续上次操作位置。
4. **四栏叫法需按最新规划统一**：统一为 **左一图标菜单栏 → 左二会话项目菜单栏 → 中间区域 → 右侧菜单栏**。

## 2. 关键交互与规则

### 2.1 输入区项目入口与 `+` 菜单融合

- **`+` 按钮始终保持纯 `+` 图标**：负责打开「添加上下文」菜单（文件、文件夹、提及、操作、浏览器、云端硬盘），不再变形为项目胶囊。
- **全屏只保留唯一项目入口**：
  - **工作模式 · 空会话**：保留输入卡片头行的挂载条（`此计算机` + `📁 项目名` / `📁 选择项目` + `worktree` 胶囊；头行与输入区同卡片，用一条分隔线隔开）；`+` 菜单不重复展示项目项。
  - **聊天模式（空会话 / 已有会话）与工作模式（已有会话停靠底部）**：上方挂载条收起；已绑定项目时，在 `+` 右侧紧跟一枚独立的 `📁 项目名` 胶囊按钮（点击直接打开/收起同一个项目选择器浮层，可搜索、切换、新建项目或「不在项目中工作」）；未绑定项目时不显示该胶囊，需要时可通过 `+` 菜单中的「选择项目」或 `@ → 项目` 绑定。

### 2.2 项目绑定矩阵（聊天模式与工作模式统一）

| 操作入口 | 目标绑定行为 | 对当前项目上下文的影响 |
| --- | --- | --- |
| 左二项目行右侧「新建聊天」 | 绑定该项目（发首条消息后归入该项目） | 更新为该项目 |
| 左二单击项目文件夹行 | 展开/收起子会话列表，**不自动跳走或清空当前聊天** | 高亮该项目并切换当前项目上下文 |
| 左二顶部「新聊天」 | 继承当前项目上下文；若当前绑定/选中了项目，则新会话绑定该项目 | 保持当前项目上下文 |
| 左二「最近」标题右侧新会话图标 | **强制开启项目外独立新会话**（`projectId = null`） | 清空当前项目上下文 |
| 输入框项目选择器选中项目 | 绑定该项目到当前草稿或会话 | 同步更新当前项目上下文 |
| 输入框项目选择器点「不在项目中工作」 | 解除当前草稿或会话的项目绑定 | 清空当前项目上下文 |
| 打开历史会话 | 按该会话真实 `projectId` 还原 | 同步为该会话的 `projectId`（项目外会话为 `null`） |

### 2.3 用户操作记忆（刷新页面恢复）

| 记忆项 | 存储位置 | 校验与回退 |
| --- | --- | --- |
| 当前视图与项目上下文 | `lfaa:active-route`（`@lfaa/ui-layout`） | 项目列表加载完后若项目不存在，自动清理为 `null` |
| 空会话草稿绑定项目与分区 | `lfaa:draft-project-id`、`lfaa:draft-section-id`（`@lfaa/client-ui-chat`） | 打开会话/切换项目/新建草稿同步写入；项目不存在时清理为 `null` |
| 左二项目文件夹展开/收起态 | `lfaa:project-expanded`（`@lfaa/ui-layout`） | 按行键 `groupKey:projectId` 独立记忆，默认展开 |
| 左二最后点击分组键 | `lfaa:active-group-key`（`@lfaa/ui-layout`） | 非法或过期分组由 `resolveActiveGroupKey` 自动回退 |
| 聊天 / 工作模式与分组展开 | `lfaa:workspace-mode`、`lfaa:nav-group-expanded`、`lfaa:section-expanded` | 沿用现有机制 |

## 3. 公开接口与跨包边界

- `@lfaa/ui-layout`：
  - `WorkbenchClientService` 新增 `setActiveProject(projectId: string | null): void`，仅更新当前项目上下文并持久化，不切换视图。
  - `NavigationGroups` / `NavigationSidebar` / `ShellLeftColumn` 新增 `onNewRecentChat`（项目外独立新会话）与 `onSelectProjectContext`（单击项目行更新上下文），区分顶部「新聊天」与「最近」右侧新会话。
  - `ui-preferences.ts` 新增 `PROJECT_EXPANDED_KEY`、`ACTIVE_GROUP_KEY` 及对应读写辅助函数。
- `@lfaa/client-ui-chat`：
  - `ChatWorkspace` 增加 `onProjectContextChange?: (projectId: string | null) => void`，在输入框切换/解绑项目或打开历史会话时同步回写 `workbench.setActiveProject`。
  - `ChatComposer` 统一持有项目选择器开关态，避免独立项目胶囊与外部点击监听的切换弹跳；`ComposerAddMenu` 恢复纯 `+` 按钮。
  - `chat-preferences.ts` 新增草稿项目/分区持久化读写。

## 4. 实施顺序

1. 落盘本方案并更新四栏布局统一叫法（`AGENTS.md`、开发规范、布局中文文案）。
2. 融合 `@lfaa/client-ui-chat` 输入区项目入口与 `+` 菜单，补齐聊天模式独立项目胶囊与无弹跳浮层开关。
3. 修正 `@lfaa/ui-layout` 与 `@lfaa/client-ui-chat` 的项目绑定链路与刷新持久化记忆。
4. 补齐回归单元测试，运行全套校验门禁、构建、截图与内置浏览器深/浅色双主题实测验收。
5. 同步 `docs/architecture/repository-map.md`，写入本轮 `dev-log` 与 `updata-log`。

## 5. 验收条件

- 工作模式绑定项目空会话中，全屏仅出现一枚 `📁 项目名`（位于输入卡片头行），左下角为纯 `+` 按钮，且 `+` 菜单内不再重复出现项目项。
- 聊天模式绑定项目时，`+` 右侧紧跟独立 `📁 项目名` 胶囊，placeholder 为 `在“项目名”中新建聊天`；点击胶囊可切换/新建/解绑项目；发送消息后会话归属该项目。
- 左二单击项目行后仅高亮并切换项目上下文（不跳走当前聊天）；随后点左二顶部「新聊天」，新会话绑定该项目；点左二「最近」右侧新会话图标，工作模式变为 `📁 选择项目`、聊天模式为无项目标签的纯新对话。
- 刷新页面后，当前模式、草稿项目绑定、项目文件夹展开收起态与高亮上下文均准确恢复。
- `pnpm check`、`pnpm lint`、`pnpm readme:pair`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm probe:boot`、`pnpm probe:loader`、`pnpm verify:web` 全绿，且深/浅色双主题浏览器实测通过。

## 6. 风险与回滚

- **旧记忆指向已删除项目**：在项目列表加载完成后做有效性清理，防止残留无效 `projectId`。
- **回滚**：所有新增 `localStorage` 键均有容错默认值，不改动 Host 持久化数据结构，回退前端变更即可完整恢复。
