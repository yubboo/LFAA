# LFAA 系统总体架构

## 1. 项目目标

LFAA 是一个多端应用工作台，首期提供 SteamCMD 游戏服务器管理、Minecraft 服务器管理和写作应用。每个应用有常规功能，并可进入内置 AI Work。用户可以用自然语言提出目标，由大模型驱动 Agent 规划步骤、召唤子 Agent、调用工具并跟踪结果。

应用决定自己的二级导航、工作台和业务流程；“常规”和“AI Work”是应用内交互模式，不是独立业务应用。全局导航在应用间保持稳定，进入 Minecraft 后二级栏切换为 Minecraft 菜单；SteamCMD 与写作以后按各自业务接入。

当前已接入 AI Work 对话、会话和扩展宿主，但尚未实现 Agent Loop、子 Agent 委派或 AI 业务工具。Minecraft 常规模式的本机 Windows x64 Daemon、官方 Vanilla Java 服务端任务、专属页面、数据库状态和 Windows AppContainer Sandbox Host 已有代码实现；真实 Windows 主机启动、网络和文件权限验收仍待执行。AI Work 共用一个 server 侧 LFAA AI Runtime、Provider 配置、账户权限与审批体系，并以 `appId` 隔离应用会话与扩展上下文；应用内模式切换不改变 App 身份和执行容器。离开 Minecraft 工作区不会自动停止其 Daemon 进程，进程继续留在该实例自己的 AppContainer 中，直到用户显式停止或宿主退出。业务工具只有接通相应 server 业务服务、真实 Runner 和授权检查后才可以注册。

```text
用户的一句话
   ↓
主 Agent ↔ LLM：理解、推理、规划和选择行动
   ├─ 直接调用工具
   └─ 按需委派给专业子 Agent
             ↓
     工具调用后端业务服务
             ↓ 需要操作主机时
        server 派发节点任务
             ↓
     daemon 执行并回传进度/结果
             ↓
主 Agent 检查任务结果并向用户完成交付
```

LLM 是推理能力来源；Agent Runtime 组织模型调用、上下文、任务循环、工具执行和委派。Tools 是受控能力接口。daemon 是分布式节点上的执行程序，不是 LLM Agent。

## 3. 组件与部署边界

| 组件 | 主要职责 | 部署位置 |
|---|---|---|
| `apps/web` | Web 平台入口 | Web 主机或静态站点 |
| `apps/desktop-tauri` | Tauri 桌面容器和平台能力 | Windows / Linux 桌面 |
| `apps/desktop-electron` | Electron 桌面容器和平台能力 | Windows / Linux 桌面 |
| `frontend` | 三端共用的 React UI，包括应用中心、常规模式和各应用 AI Work | 随 Web 或桌面外壳打包 |
| `server` | 控制端 API、权限、业务服务、AI 服务、任务调度和节点管理 | 中心服务器或本机 |
| `daemon` | TypeScript 节点连接与任务协调、游戏安装和进程管理；Rust Windows Sandbox Host 执行原生 AppContainer/Job Object 边界 | 本机或每台远程节点 |
| `data` | 控制面持久化数据和本机节点数据的开发默认目录 | 持久化磁盘或 Docker Volume |

前端 CSS 按样式所有权分层：`frontend/src/styles/tokens.css` 是全局设计变量来源，`base.css` 负责文档级基础样式，`common.css` 只维护跨多个独立组件共用的状态样式，`responsive.css` 维护跨页面断点；页面和组件专属规则仍留在 `styles/` 页面样式或组件同名样式文件中。全局样式由 `frontend/src/main.tsx` 按级联顺序导入一次；组件专属 CSS 由对应组件文件导入。

`server` 是控制端；根目录 `daemon/` 是受控节点上的常驻执行程序。`daemon/` 目录名表示后台服务进程，部署说明必须注明它是节点端。MCSManager 同样将网页后端、被控节点 daemon 和网页前端分开，并将进程管理、终端和节点文件操作放到节点侧。[MCSManager 项目说明](https://github.com/MCSManager/MCSManager/blob/master/README_ZH.md)

首期采用模块化后端加独立 daemon 的方式：`server` 内按业务模块组织，不先把每个功能拆成微服务；daemon 因运行位置、权限和升级周期不同而可单独构建和部署。

## 4. AI 服务设计

AI 服务统一位于 `server/src/ai/`，应用内 AI Work 通过后端上下文调用它。

- **LLM 接入**：管理模型提供方、模型选择、流式响应、超时和用量信息。模型密钥仅保存在后端安全配置中。
- **主 Agent**：维护任务上下文，调用 LLM 推理，形成步骤计划，选择工具，跟踪任务和停止条件，并汇总可验证的结果。
- **子 Agent**：在主 Agent 判断需要并行或专业分工时创建，例如 SteamCMD 部署规划、Minecraft 配置助手、写作审阅助手。子 Agent 应有明确任务范围和可用工具集合。
- **Skills**：封装领域知识和可复用流程，供 Agent 在适用时加载；不代替业务代码执行高权限操作。
- **Prompts**：定义 Agent 角色、输出要求和约束，按公共能力或业务领域维护。
- **Tools**：向模型描述可执行能力。服务端校验权限和参数后，调用游戏、写作、文件或节点业务服务；不开放任意 Shell。

### AI 插件宿主

- `server/src/ai/` 是 AI Host 和插件组合入口。当前用 Cordis Context、服务依赖和生命周期组织受信任内置的 Agent 配置、Skills、Prompts、Experts 与 Tools 目录；模型流式对话和用户隔离会话已接入。Agent Loop、子 Agent 委派和可执行业务工具仍待对应业务模块。
- AI Runtime Hooks 是插件生命周期扩展点，只能观察请求编号、应用、Provider、模型、消息数和结果用量等元数据；Hook 不接收对话正文，不能改写模型输入或授权决策。设置中心“钩子”目前专指编码工作流钩子，未与 AI 推理钩子混用。
- 插件注册、配置和资源监听必须拥有生命周期 disposer；插件卸载后清除其服务、事件监听、计时器和 watcher。一个任务开始后固定其插件与提示词版本，热更新只影响新任务。
- LFAA 身份认证、授权策略、审批、审计、游戏/写作业务规则及 daemon 任务通道属于受保护的核心边界。AI 工具权限由账户级“请求审批”“替我审批”“完全权限”三种模式控制：写入和高风险操作在前两种模式下分别逐次询问或按明确记忆授权精确匹配；记忆授权按账户、应用、工具标识/版本、风险和目标范围隔离，可查看并撤销。目标范围身份由受信任业务服务提供并只以哈希保存；审批界面显示经业务服务整理的目标说明。下载、安装与配置修改应标为写入，命令执行应标为高风险。
- “完全权限”仅免除对已登记真实业务工具的逐项审批，仍必须通过 server 身份、应用、目标及业务校验，不开放任意 Shell/任意路径。任何 AI 权限模式都不代替 Minecraft EULA 的单独展示与用户明确同意。单次审批有效 5 分钟，只绑定工具版本、风险、目标范围与完整参数摘要，且只能消费一次。当前 Minecraft AI Work 仍是对话模式，没有已登记 Minecraft 执行工具；Minecraft 常规模式下的受控管理操作由用户在专属工作台直接发起。
- 首阶段插件清单只包含随 LFAA 发布并经代码登记的内置插件。开发环境可热更新内置插件源码；生产环境不监听源码。第三方可执行插件未来必须经独立信任流程并在隔离进程中运行，不能因安装插件而获得 server 进程中的密钥、数据库或任意主机权限。
- Markdown Skills/Prompts 属于数据型扩展，可按版本热加载；插件代码的加载/卸载、Skill 内容更新和 AI 任务都需保留版本与审计记录。宿主不可卸载核心授权与审计闸门。
- `server/src/ai/` 不拥有 SteamCMD、Minecraft、写作或隧道的业务规则；对应工具只适配 `server/src/modules/` 的业务服务，节点动作由 `daemon/` 的受控 Runner 执行。

当前 AI 插件宿主建设状态和不在范围内的功能见[开发计划](开发计划.md)及[任务合同](PROMPTS.md)。

目标场景示例（当前尚未实现）：一次“安装并启动 Minecraft 服务器”的流程可由主 Agent 调用 LLM 推导版本与参数；需要时委派 Minecraft 子 Agent 检查兼容信息；Agent 请求部署工具；后端校验用户权限、节点和参数并创建任务；daemon 下载、写配置、启动进程并回传事件；后端确认状态后，Agent 将地址和结果交付给用户。

DeepSeek Harness 将子 Agent 作为可组合能力，并通过模型可见的委派工具启动子 Agent；Minecraft Host Agent 则明确采用 LLM 在 Agent Loop 中选择工具、后端负责执行与安全边界的模式。这些是 LFAA 的职责划分参考，不要求照搬其全部实现或目录规模。[DeepSeek Harness 子 Agent 设计](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/subagent.md) · [Minecraft Host Agent](https://github.com/AndrewNog0724/minecraft-host-agent)

### 应用执行隔离

- App 是 AI 会话、授权目标和业务数据归属的边界；常规面板、手动操作和 AI Work 是同一 App 的交互模式。切换模式不会切换 App 身份、实例数据或执行容器。切换应用只改变当前工作区上下文，不隐式停止其他 App 的后台进程。
- OS 沙盒按真实执行 Host 接入。当前仅 Minecraft Vanilla 有受支持的主机进程执行路径：每个实例使用独立 Windows AppContainer SID，由 Rust Sandbox Host 启动受管理 Java；服务端只向实际探测到 Sandbox Host 的 Windows x64 Daemon 派发启动任务。SteamCMD、写作、插件和未来 App 仍须在各自真实 Runner 完成后接入，不能复用 Minecraft 的身份或宣称已隔离。
- AppContainer 的实例目录授权读写并设低完整性标签；LFAA 管理的 Java 目录仅授予读/执行；启动环境不继承 Daemon 密钥或模型密钥。显式网络能力为 `internetClientServer` 与 `privateNetworkClientServer`，当前没有域名或端口白名单。Job Object 限制单进程和内存，并在 Sandbox Host 关闭时结束进程。Job Object 只管进程生命周期与资源，文件/网络/访问边界由 AppContainer 承担。
- AppContainer 或 Job Object、规范路径、ACL、低完整性标签、能力/启动设置有任一失败时，Daemon 拒绝启动，不回退为普通 Java 进程。节点能力来自 Sandbox Host 探测，实例状态来自 Daemon 心跳；页面展示未连接、不可用、待准备、已准备、运行中或无法核实，不推测成功。
- Rust Sandbox Host 的 Windows AppContainer 边界依据 Microsoft 的 [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)、[implementing an AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[Mandatory Integrity Control](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control) 和 [SetNamedSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setnamedsecurityinfoa) 文档设计。代码编译不能代替目标 Windows 主机运行验收。

40+ 游戏应由游戏目录数据驱动，不为每款游戏复制一套 API。目录定义包含平台标识、安装应用 ID、受支持系统、运行依赖、默认配置、启动参数和健康检查方式；部署代码通过统一流程调用具体游戏 Runner。

### 配置设置中心

设置中心是 Web/Desktop 共用的产品配置界面，包含常规、通知、导入、个人资料、外观、家长控制、受信任联系人、语音、配置、个性化、Mini 与虚拟宠物、键盘快捷键、使用情况和计费、账户、插件、电脑操控、应用快照、浏览器、钩子、连接、云端偏好设置、代码审查、Git、环境、Worktrees、已归档聊天，以及 LFAA 的 AI 与模型、用户与权限、项目与存储、开发者入口。设置页作为独立全屏页面复用 `frontend/src/workbench/ResizableWorkbench.tsx`：进入设置时隐藏应用全局顶栏和页脚；左侧分类栏停靠在视口左边，可拖动调整宽度或收起；设置与应用工作区通过 `frontend/src/workbench/workbench-preferences.ts` 共享左栏宽度；分隔线采用单像素边界，透明拖动热区覆盖边界两侧；侧栏收起后分隔器列归零；右侧内容独立滚动，常规页采用居中的宽内容列。设置页返回时恢复打开设置前的路由。拖动被取消、失去 Pointer 捕获、窗口失焦、页面隐藏或组件卸载时回滚到拖动起始尺寸并清理全局交互状态。配置按当前认证用户隔离，由 `server/src/modules/settings/` 校验和持久化；前端只调用同源设置 API。

工作台将实际滚动位置作为非敏感界面偏好，由 `frontend/src/shared/scroll-restoration.ts` 统一按认证用户和界面区域保存与恢复；设置分类、应用页面、应用导航、AI Work 会话消息和 Minecraft 日志使用各自独立的区域标识。为恢复 AI Work 消息列表，浏览器仅额外保存当前应用最近选择的会话 ID；聊天消息正文、草稿、账户配置、凭据和认证信息仍归各自服务端/内存 Owner，不写入浏览器持久存储。异步页面在数据加载就绪后恢复位置。

工作区按 `ResizeObserver` 读取自身实际宽高，并以 CSS Grid 安排可调整面板、以 Flexbox 收缩面板内容；宽屏显示左右停靠栏，中等宽度将右栏改为浮层，窄屏将侧栏改为可收起浮层。布局计算不抬高浏览器的实际宽高；终端面板按可用高度收缩，并为主内容保留至少 168px。设置内容区和侧栏各自滚动，移动端设置导航默认收起，极窄屏导航轨缩窄。响应式验收要覆盖 320px 窄屏、横屏矮窗口、竖屏长页面、窗口连续缩放及超宽桌面；禁止通过固定最小页面宽度制造横向滚动。

AI 配置按业务归属进入对应分类：Provider、模型、推理参数和实际 Runtime 状态进入“AI 与模型”；Agent 配置、Skills、Prompts、Experts、Tools、可信内置插件和 AI 推理 Hooks 目录进入“插件”；MCP 和外部服务进入“连接”；权限与待审批操作进入“用户与权限”；本地 Token 用量进入“使用情况和计费”；会话归档进入“已归档的聊天”。“常规”仅保留通用工作台交互偏好；“外观”只包含视觉呈现配置；“钩子”页面仅用于尚未接入的编码工作流钩子。

- 常规设置按账户保存默认任务目录、文件打开方式、智能体环境、集成 Shell、语言、完整视图、底部面板、终端位置、工作台导航布局、纯文本编辑器、发送快捷键、跟进处理方式、弹窗快捷键、独立聊天、通知策略与提示音和趣味实验偏好，并保留 LFAA 的默认应用模式与服务状态开关。工作台导航布局提供左侧导航双列、三列、右侧工具和专注四种预设，左右面板仍可拖动调整宽度。模型速度、提示建议、插件开关和上下文用量按其 AI 归属进入对应分类；授权审批偏好进入“用户与权限”。旧账户缺少新增字段时由服务端补齐默认值。
- 管理员查看本机已有账户的入口位于“设置中心 > 账户”；应用中心和应用内导航不再单独显示账户列表入口。旧 `/admin/users` 地址兼容打开设置中心的账户分类。
- 完整主机访问权不会由偏好开关直接授予；外部文件访问、终端执行和业务工具仍需对应的桌面宿主或业务服务接入后才能生效。模型推理参数由 AI Runtime 执行。AI Work 成功回复按账户通知偏好进入当前工作区内存中的通知卡片，并可通过浏览器 Notifications API 投递系统通知；提示音由 Web Audio 播放。通知卡片最多保留 8 条，离开应用工作区后不持久化；浏览器授权按浏览器保存，系统通知仅在页面进程运行时可用。权限等待、用户问题以及 ChatGPT/Codex 外部任务、额度、健康、群聊、营销、资料库和项目事件均无 LFAA 事件源，不显示为已接入能力。未接入的侧栏入口展示真实接入状态，不伪造可运行能力。
- 外观主题提供浅色、深色和跟随系统三种即时预览选项；深色背景使用中性 `#181818`；外观设置支持强调色、统一自定义侧边栏颜色、五个页面位置的背景选择、透明遮罩、模糊效果和个人背景上传。图片限制为 PNG/JPEG/WebP、3 MiB、单边 8192 像素、总面积 2000 万像素，并通过认证接口按用户读取。
- 会话恢复或登录时并行读取用户偏好与账户设置，收到设置后才挂载工作台，避免系统主题暂时代替账户主题；设置读取失败时显示错误和重试入口。工作台将已读取设置传给设置页，设置页不重复读取完整设置。设置分类所需的背景、AI、插件、用量、归档、权限和运行信息仅在用户进入相应分类时请求。
- 快捷键设置当前覆盖设置中心、应用中心、SteamCMD、Minecraft、写作入口，以及应用导航栏、工具资源栏、底部面板、终端和常规/AI Work 模式。每个动作最多可保存四组绑定，支持逐条录入与清除；浏览器只注册已有实际处理器的动作。旧版以单个字符串保存的用户配置在读取时转换为单项绑定，新增快捷键使用默认值补齐。
- AI 设置允许 OpenAI、DeepSeek、通义千问、Kimi、智谱和 Xiaomi MiMo 的固定 Provider 配置；模型目录与推理端点从固定 HTTPS 官方配置读取，禁止浏览器提交任意 Base URL。活动 Provider 账户由 AI Runtime 在 server 内安全读取，密钥不返回浏览器。
- AI 密钥在 server 上用 AES-256-GCM 加密，密钥文件位于 `LFAA_DATA_DIR/credentials/settings.key`；查询账户时只返回是否已保存，不返回密钥。备份和迁移控制端数据时必须同时保护数据库与该密钥文件。
- 当前角色仍是固定的管理员/普通账户，插件隔离运行时尚未实现；对应设置页必须说明不可操作原因，不能伪造插件安装、权限管理或执行结果。项目与存储、开发者页仅展示当前真实可读状态。

## 6. 数据、游戏文件与运行环境

控制面状态与 daemon 管理的实际游戏文件有不同的用途，但数据目录按内容和环境命名，而不是按部署角色或节点编号命名。每台 daemon 主机配置自己的数据根目录；多节点时，各主机可以使用相同的目录布局。

| 路径 | 用途 | 所属方 |
|---|---|---|
| `data/database/lfaa.sqlite` | SQLite 控制面数据库，保存账户、登录会话、应用偏好、分类设置、加密 AI 账户、个人背景图片、AI Work 会话/消息/用量、单次工具审批与账户级记忆授权记录 | 控制端 |
| `data/credentials/jwt-secret` | 开发环境自动生成并持久保存的本机 JWT 签名密钥；生产环境使用受保护配置中的 `JWT_SECRET` | 控制端 |
| `data/credentials/daemon-token` | 控制端与本机 Daemon 之间的随机身份校验密钥；不得返回前端或写入普通日志 | 控制端和本机 Daemon |
| `data/credentials/settings.key` | 加密 AI Provider 密钥的本地 AES-256-GCM 密钥；必须与数据库一起受保护备份 | 控制端 |
| `data/games/steamcmd/` | SteamCMD 下载和部署的游戏服务端文件 | daemon |
| `data/games/minecraft/<实例 ID>/` | Minecraft Vanilla 实例、配置、运行标记和世界存档；由本机 Daemon 所有 | daemon |
| `data/environments/java/` | 受管理的 Java/JRE 版本，按版本和平台区分 | daemon |
| `data/environments/sandbox/minecraft/<实例 ID>.json` | Minecraft 实例 AppContainer 后端、绑定 App/实例身份和准备状态元数据；不保存密钥 | daemon |
| `data/environments/python/` | 仅在需要托管 Python 运行环境时使用 | daemon |
| `data/lib/steamcmd/` | SteamCMD 工具文件 | daemon |
| `data/lib/pty/`、`data/lib/zip-tools/` | 终端和归档等辅助依赖 | daemon |
| `data/plugins/` | 插件包或插件下载缓存；实例实际启用的插件随实例保存 | daemon |
| `data/cache/` | 下载包和可再生成的临时数据 | daemon |
| `data/logs/` | 控制端和实例日志 | 各自运行进程 |
| `data/backups/minecraft/<实例 ID>/` | Minecraft 实例停止后的世界备份 | daemon |

`data/games/steamcmd/` 保存 SteamCMD 安装出来的游戏服务端文件；`data/lib/steamcmd/` 保存 SteamCMD 工具本身，两者用途不同。根目录 `data/` 是本机开发和单机部署的默认数据根目录。控制端和每台 daemon 主机分别通过各自进程环境中的 `LFAA_DATA_DIR` 配置数据根目录；默认仓库路径为 `data/`。`data/.gitignore` 忽略运行数据，只保留空目录标记。生产部署可以将各进程的数据根目录配置到独立磁盘或持久化卷；远程 daemon 在自己的主机使用相同的内容分类。升级程序不能删除实例、存档或运行环境。缓存、实例数据和备份要分别清理与恢复。

当前控制端将用户、角色、恢复密钥哈希、登录会话、应用偏好、设置、AI 账户、节点登记和 Minecraft 实例/任务元数据保存在本机 SQLite 文件 `database/lfaa.sqlite`；该方案不依赖浏览器 `localStorage` 或远程数据库服务。数据库结构通过 SQLite `PRAGMA user_version` 顺序迁移，目前数据库迁移版本为 12；后续 schema 变更必须新增迁移，不能删除用户偏好或运行数据来绕过升级。密码和恢复密钥使用 Node `scrypt` 加随机盐保存，登录会话使用已签名的 `HttpOnly` Cookie；开发环境未配置 `JWT_SECRET` 时，签名密钥会持久保存在 `credentials/jwt-secret`，避免控制端重启后现有会话全部失效；生产环境要求设置强 `JWT_SECRET`。系统只允许在本地数据尚无用户时初始化唯一超级管理员；此后不开放注册或新增用户接口。密码至少 8 位并至少包含大写、小写、数字、符号或汉字等字符类别中的三类；初始化、密码找回和恢复密钥设置共用此规则。恢复密钥用于验证身份并设置新密码，系统不提供查看原密码的功能。邮箱找回尚未接入，后续需先建立邮箱绑定和邮件发送配置。本机开发默认使用 Node `node:sqlite`，最低 Node.js 版本为 24.15.0；该 Node API 在当前 24.x 文档中标为 Release Candidate，账户类短请求使用同步数据库调用。进入正式部署或需要横向扩展前，应重新评估稳定版数据库驱动和集中式数据库。

## 7. API 与节点通信

- REST API 用于用户、配置、游戏目录、实例、任务和节点管理。
- Socket.IO 用于终端、日志、部署进度、实例状态和资源监控的实时传输。
- daemon 通过经过身份验证的连接注册节点、发送心跳、接收任务、上报进度与结果；心跳续租该节点正在执行的任务，任务租约为 30 秒。
- 每个任务具有唯一 ID、发起用户、目标节点、实例、当前状态和可追踪日志。租约过期时任务失败并标记“结果未确认”，相关实例状态转为未知；控制端不会自动重放可能产生副作用的操作，需检查实际实例后再决定后续操作。
- 需要文件传输时校验路径、大小、类型、目标实例和覆盖策略；节点不得按模型生成的任意路径访问磁盘。

## 9. 技术选型

| 层 | 计划技术 |
|---|---|
| 前端 | React 18、TypeScript、Ant Design 5、Zustand、Monaco Editor、Xterm.js、Socket.IO Client、Framer Motion、Vite、TailwindCSS |
| 控制端后端 | Node.js、TypeScript、Express、Socket.IO、JWT、Winston、Multer、node-cron、Axios、Joi |

根目录 `package.json` 固定 pnpm 版本，`pnpm-workspace.yaml` 纳入 `frontend/`、`server/`、`daemon/` 及未来加入的 `apps/*` Node.js 包。Windows 用户双击根目录 `lfaa.bat` 后进入彩色操作菜单；只有选择 `1` 才会由 `scripts/install-dependencies.ps1` 调用 pnpm 安装依赖并生成锁文件。Daemon Windows Sandbox Host 与 Tauri 原生 Rust/Cargo 依赖由 Rust 工具链管理，不属于 pnpm 安装范围；启动 Daemon 前检查 Windows x64 MSVC target。
