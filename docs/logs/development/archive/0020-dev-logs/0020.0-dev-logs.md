# #20 开发日志分层规范

- **主编号：** #20
- **名称：** 开发日志分层规范
- **记录版本：** #20.0
- **状态：** superseded
- **关键词：** 日志、索引、命名、中文、归档
- **已由：** #20.1 替代
- **当前查看：** `docs/logs/development/active/0020-dev-logs.md`

## 当时结论

#20.0 建立了：

```text
docs/logs/development/
├── INDEX.md
├── active/
└── archive/
```

并规定当前日志与历史日志分离。

## 为什么被替代

#20.0 只给 #1 - #19 建立了一个 legacy 指针，没有把旧主编号逐条纳入新的 Development Log 索引。

这会导致阅读者在 `development/` 中只看到 #20，无法直接对比旧编号。

## 新方案

从 #20.1 开始：

- #1 - #19 必须逐条进入新日志索引；
- #2 因仍在进行，进入 `active/`；
- 已交付任务进入 `archive/`；
- 原 Prompt / Progress / Changelog / Release 全部保留；
- Development Log Check 检查主编号是否连续缺失。
