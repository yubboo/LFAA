# 任务 000283｜回复结束后的底部跟随与输入框宽度修复

- 修好「最终回复完成后不会滚到最底部」：跟随原先只在流式输出期间生效，而交付卡片、追问建议和消息页脚都是在流结束后才挂载的，这批后到的高度变化被忽略——视口会停在离底部 100 多像素的位置（实测 131px），右侧「回到底部」箭头一直亮着。现在只要读者仍贴底，任何高度变化都会重新定位；读者主动上滚后不会被拽回去。
- 修好「输入框比正文宽」：输入栈的宽度限制类 `composerStack`（`width` 上限 + 居中）定义在 `ChatWorkspace.module.css`，而输入组件引用了 `ChatWorkspace.composer.module.css` 里的同名类，重构后类名变成 `undefined`，整条输入栈直接撑满栏宽。栏越宽，输入框比消息列多出来的部分越大。改回正确模块后两者同宽。
- 修好「输入框左边比右边多一截」：滚动条只占消息列右侧约 6px，正文列的居中轴因此比输入栏左移 3px、宽度也少 6px，肉眼就是左边空得多、右边贴得紧。现在滚动区用 `scrollbar-gutter: stable both-edges` 在两侧各留同宽槽位，正文列与输入卡片共用「正文列宽度」这一个变量，两条列居中轴完全一致，并且输入卡片比会话区左右各外扩约 15px（`--chat-thread-inset` 可调）。
- 实测（真浏览器，`127.0.0.1:5173`，1280×696）：正文列 `[272.5, 1010]`、输入卡片 `[257.3, 1025.3]`，中心同为 641.25，左右各外扩 15.2 / 15.3；打开会话 gap=0、箭头隐藏；上滚 500px 后再追加 140px 内容仍停在原处（gap=660、箭头可见）；点箭头回到 gap=0。
- 影响范围：只有聊天视图的滚动跟随策略和输入区外壳宽度，无数据与协议变化。
