# UPDATE-000365｜工作树「基于哪个分支」写清楚了，项目详情也能再打开

- 时间：2026-11-22 15:05 +0800（Asia/Shanghai）
- 类型：体验优化 / Bug 修复

## 你会看到什么

- 工作树创建弹窗明确说明：工作树必须使用独立分支，不能与主工作区共用 `main`；新分支默认从当前分支（HEAD）创建。
- 项目详情的工作树列表显示「基于 main / 基于 xxx」，不再只看到一个 `lfaa/...` 或 `feature/...` 新分支而误以为起点错了。
- 项目行双击、或「···」菜单里的「打开项目」，都能重新进入项目详情，查看和清理工作树。
- 完整「代码审查」页的 Git 状态、差异、暂存、提交、分支、PR 草案也按当前会话的工作树执行。

## 为什么之前看起来像“分支不对”

Git 不允许同一个分支被两个工作树同时检出，所以从 `main` 创建工作树时，实际检出的是一个**新分支**（默认 `lfaa/<日期>-<随机>`），它的起点是 `main`。现在界面把“工作树分支”和“基于哪个分支”分开展示，避免混淆。

## 兼容性

- 已有工作树记录没有 `baseRef` 时只显示分支与会话数，不影响使用。
- 未绑定工作树的聊天与审查页行为不变。
