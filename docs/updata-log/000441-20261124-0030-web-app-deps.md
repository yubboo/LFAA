# 000441｜修好「整个服务起不来」：界面搬家后 Web 端没跟上新包名

- 时间：2026-11-24 23:20–23:40（Asia/Shanghai）。
- 现象：双击 `lfaa.bat` 选 2、或直接 `pnpm lfaa web`，进程能起来，但页面一片报错：`Failed to resolve import "@lfaa/client-ui-library/client"`，每个界面模块都报一次，等于整站打不开。
- 原因：界面代码搬到 `packages/client/ui-*` 后，`apps/web` 的依赖清单还写着旧包名，导致开发服务器找不到新包。类型检查和生产构建有各自的解析路径，绕过了这个缺口，所以之前门禁全绿——这是门禁没覆盖真实启动路径的漏洞。
- 修复：`apps/web` 依赖改为 10 个 `@lfaa/client-ui-*` 并重新安装。现在 `lfaa.bat 2` 启动后首页与入口模块都正常返回，浏览器实测页面完整、控制台 0 报错。
- 加固：新增一条结构门禁——`apps/` 里用到哪个 `@lfaa/*` 包，就必须在自己的 `package.json` 里声明，否则 `pnpm check` 直接失败；打包脚本目录除外。这类「类型检查过、启动才炸」的问题以后会被提前拦下。
