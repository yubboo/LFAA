# UPDATE-000338｜任务清单在会话里持久化，多步任务会先列清单再动手

- 时间（含时区）：2026-11-22 00:18 +0800
- 类型：新增 / 优化
- 关联开发日志：`../dev-log/000201-000400.md`（DEV-000338）

## 用户能看到的变化

- Agent 接到「要新建/修改 2 个及以上文件」或「需要 2 条以上命令」的任务时，会先输出一份任务清单（`todo_write`），并在推进过程中把完成项勾掉；活动行显示「共 3 条（完成 1 / 进行中 1 / 待处理 1）」这样的真实进度，而不是只有一句「已更新」。
- 任务清单现在存在会话里：刷新页面、重启工作区后打开同一会话，清单还在（本版本先做到 Host 侧持久化与推送，任务卡界面在下个阶段）。
- 清单是整表替换语义：模型漏传的条目会被删除，不会再出现「旧任务一直留着」的假进度；同一时刻只允许一条「进行中」，传两条会被拒绝并回给模型一条可读的报错。

## 影响范围与使用提示

- 影响 `@lfaa/tool-todo`、`@lfaa/session`、`@lfaa/memory`、`@lfaa/agent`。旧会话没有 `todos` 字段，读回为空、界面按「没有清单」处理，不需要迁移。
- 工具行为有破坏性变更：`todo_write` 从「按 id 合并」改为「整表替换」，自定义预设里依赖旧合并语义的提示词需要跟着调整。
- 本轮没有任务卡 UI；界面上仍是在活动行里看清单摘要，输入框上方的常驻卡片属于下一阶段（P2，等并发会话收工后再做）。

## 已知限制

- 极简模式不装配 `tool-todo`，因此不会出现任务清单。
- 并行子智能体共用父会话清单时没有「多条进行中」的放行开关，建议下一阶段再按 DSH 的 `allowParallelInProgress` 做配置。
- 任务卡、活动行内的清单渲染（拖动折叠、12 条上限）、以及「轨迹」视图适配都还没做。
