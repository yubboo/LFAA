# 000329｜生图按用户比例生成（16:9 / 9:16 / 4:3 / 3:4 / 1:1），生成中改为消息内按比例占位

- 时间：2026-11-21 23:16 +0800。负责人要求：不同比例自动判断并生成对应尺寸；用户没提比例时给常用比例；提了比例就必须严格照做；生成中不要再用输入框上方那条「正在生成图片…」灰条，要像正常回复一样在消息区流式呈现，并明确告诉用户「图片生成完成了」。
- 画幅识别（`image-ratio.ts`）：识别 `16:9`、`9：16`、`4比3`、`1920x1080` 等显式写法（含全角冒号、比、像素尺寸与等值换算），以及「竖版 / 竖屏 / 手机壁纸」「横屏 / 宽屏 / 横幅」「方形 / 头像」等说法。
- 尺寸：明确比例请求 2048×1152、1152×2048、2048×1536、1536×2048；模型只接受固定分辨率时自动回落到 1280×720 / 720×1280 / 1152×864 / 864×1152 重试一次；未指定比例时用常用 1:1（2048×2048）。明确比例时把【画面比例】约束补进请求提示词，保存的提示词仍是用户原文。
- 计划接口：`POST /api/media/plan` 返回 `{ ratio, size, explicit }`，本地宿主毫秒级，供前端决定占位形状。
- 生成进度：发送后立即在消息区插入本轮用户消息 + 按目标比例的骨架占位（扫光 + 转圈 + 比例胶囊），移除输入框上方的状态条；完成后以「图片生成完成了（9:16 · wan2.7-image · 耗时 16 秒）。」收尾，失败时移除临时消息并恢复草稿。
- 真实验收：接口直连生成 9:16 → 返回 **1152×2048** PNG，文案「图片生成完成了（9:16 · wan2.7-image · 耗时 16 秒）。」；UI 复测占位骨架 189×336（9:16）、完成后图片显示 270×480、占位消失、控制台 0 错误。探索时发现真实模型会忽略提示词里的「512x512」（仍出 2048×2048），因此比例必须走尺寸参数而不是只写提示词，本轮已按此实现。
