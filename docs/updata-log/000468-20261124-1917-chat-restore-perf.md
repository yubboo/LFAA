# UPDATE-000468｜刷新不再先闪空态，运行中会话刷新也不再持续卡顿

- 时间（含时区）：2026-11-24T19:17:00+08:00
- 类型：修复
- 关联开发日志：`../dev-log/000401-000600.md`（DEV-000468）

## 用户能看到的变化

- **刷新不再先跳到「我们要做什么？」**：已经打开过会话时，刷新会先显示与真实对话同宽的静态消息骨架，输入栏固定在底部；会话详情回来后直接换成聊天记录，不再出现「空态闪一下 → 跳历史对话」的落差。
- **刷新后不再持续发烫、掉帧**：运行中会话的「用时/思考中」标题原来用逐帧移动的渐变扫光，会让界面在整片玻璃层里持续重绘；现在改为强调色 + 轻微透明度呼吸，同样的运行中页面主线程占用从约 `2.67s / 4s` 降到约 `0.18s / 4s`（本机 Edge 无头实测，约 15 倍）。
- **恢复更快一点**：会话详情与列表并行请求，项目计数不再把全部会话文件重复扫描第二遍；生产构建下恢复一条 1MB 会话的主线程耗时约 0.9s，开发模式仍会慢一些（React 开发版本身的代价）。

## 影响范围与使用提示

- 只改刷新恢复路径和「运行中」活动行/思维链标题的动效实现；正常聊天、新建会话、切换会话、深浅主题、消息内容与折叠行为不变。
- 空态页面（没有打开过任何会话）仍立即显示原来的引导页，不会先出现骨架。
- 若本地记住的会话已被删除或归档，恢复骨架会显示到接口返回为止，随后自动清掉本地记录并回到空态。

## 已知限制

- 首次恢复很长的会话仍需要一次性渲染全部历史消息（开发模式更明显）；这是渲染成本，不是网络或缓存问题，后续如需进一步优化应单独讨论「历史消息分批渲染」。
- 运行中标题的扫光改为呼吸后，视觉更安静；如果负责人希望保留流动扫光，需要换一种不触发逐帧重绘的实现再评估。
