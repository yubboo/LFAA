# 资料库合并「图像」入口（Library + Images）

状态：**已批准实施（2026-11-21，负责人选择方案 A：并入资料库，图像成为其中一个分类；入口沿用「资料库」+ 书籍图标）**。

## 1. 问题

左一图标栏同时有「图像」和「资料库」两个一级入口，但两者都在讲同一件事——本地产出与素材：

- 「图像」页只有左二的 热门 / 模板 / 我的图像 三个占位项，中心区始终是「功能尚未接入」，点了没有任何真实内容；真正生成的图片、视频、语音躺在工作区 `.lfaa-media` 里，只能从输入框工具栏的「生成素材库」弹窗看到。
- 「资料库」页已有真实的 Agent 产物、本地资产、Agent 记忆，但看不到生成媒体。
- 两个入口并列让用户以为图库和资料库是两套存储，重复且不可达。

## 2. 目标

1. 左一图标栏只保留一个「资料库」入口（书籍图标不变），删除独立的「图像」域。
2. 资料库中心页新增「图像」分类，真实列出已生成的图片、视频、语音，并与左二「资料库分类」菜单双向同步。
3. 旧的 `images` 路由（浏览器记住的活跃视图、外部链接）自动落到资料库的「图像」分类，不再出现死页。
4. 不新增包、不新增存储：图像分类直接复用宿主已有的 `/api/media/library` 与 `/api/media/file`。

## 3. 交互

- 左一：首页 / 定时任务 / 资料库 / 插件 / 更多（移除「图像」）。手机端「更多」菜单同步去掉「图像」。
- 左二「资料库分类」：资产与记忆 → **图像** → Agent 产物 → 本地资产 → Agent 记忆；「管理与存储」分组保留存储位置设置与返回工作区。
- 中心页分类标签（第一轮）同步为 资产与记忆 / 图像 / Agent 产物 / 本地资产 / Agent 记忆，均带数量；「资产与记忆」只统计资产库条目，图像数量单独计在「图像」。第二轮已按 §7 移除中心标签，分类只由左二切换。
- 「图像」分类内：
  - 顶部类型筛选：全部 / 图片 / 视频 / 语音；
  - 卡片网格：缩略图（鉴权接口经 blob 读取）、文件名、类型徽章；
  - 点击卡片在右侧预览：图片 / 视频播放器 / 音频播放条、模型、体积、提示词原文，操作提供「复制提示词」与「删除素材」（两段确认，删除同时删 sidecar 元数据）；
  - 空态说明「还没有生成的图片或视频，在聊天里让 Agent 生成一次就会出现」，不再指向不存在的模板/热门。
- 搜索框在「图像」分类下按文件名与提示词过滤。
- 输入框工具栏的「生成素材库」弹窗保留（快速复用提示词的入口），与本页共用同一套数据读取与缩略图逻辑。

## 8. 缩略图性能（第三轮，2026-11-22 00:40）

负责人反馈整理资料库后明显变卡。实测确认是缩略图实现问题，而不是列表或状态更新：

- **原因**：每张卡片都 `fetch` 完整原图再保留 blob URL。实测 31 张共 **178.6MB**（单张最大 8.5MB），31 张 2048×2048 同时解码并常驻；每次进入图像分类、切换分类回来都会重新下载；选中详情再下载一次原图。首屏约 2.6s，内存与 GPU 压力明显。
- **修复**（`media-thumb-cache.ts` + `MediaThumb.tsx`）：
  1. IntersectionObserver 懒加载：只加载视口附近（240px 预取）的卡片，首屏 20 张，其余滚动时按需加载；
  2. 浏览器内用 `createImageBitmap` + canvas 缩到 **480px WebP**（约 20–40KB），原图 blob 解码后立即释放，不再常驻大图；
  3. 并发上限 3，避免同时解码几十张；
  4. Cache Storage（`lfaa-media-thumbs-v1`）缓存缩略图，键含路径/大小/时间/宽度，文件变化自动失效；
  5. 卡片 `memo`，选中只重绘受影响的卡片；
  6. 右栏先用缓存的小图垫底，完整原图到达后替换；
  7. 宿主 `/api/media/file` 增加 ETag 与 304（需重启宿主生效），重复取原图不再整份重读。
- **实测**：冷启动 20 请求 / 128.9MB、首屏 1.7s、仅 1 次 80ms 长任务；同一浏览器热刷新 **0 请求 / 0MB**、首屏 1.1s；滚动 p95 4.7ms；滚动后补加载剩余 11 张，缓存 31 条；卡片图片实际尺寸 480px。
- **残余**：首次仍要下载原图（服务端没有图像缩放依赖）；之后走缓存。若要把首次 128MB 也降下来，需要引入服务端缩图依赖或生成时产出缩略图，属于新增依赖，需单独批准。
