# LFAA Plan 模式设计

- 状态：详细设计，供实现前评审
- 日期：2026-11-18（Asia/Shanghai）
- 建议包名：`@lfaa/plan`，路径 `packages/core/plan`

## 1. 交互

Plan 开关放在现有输入工具栏，`/plan` 和已有「计划模式」入口都驱动同一会话设置。`/plan <任务>` 先启用，再发送任务。`/plan off` 在无活动运行时退出，草案可再次查看。新聊天初始关闭，首次发送时将模式随会话创建或运行请求提交给 Host。活动运行启动后冻结其模式，避免一批工具执行到一半时切换规则。

进度条是现有输入框上方的一个整行按钮，位于聊天列，宽度跟随输入框。整个按钮可点，支持触摸和键盘。评审与步骤用同一个展开入口，计划完成后仍可查看，下一份计划开始时替换摘要。没有计划或规划任务时不占位置。

| 场景 | 默认折叠显示 | 展开后的主要动作 |
| --- | --- | --- |
| 调查中 | 正在规划 | 查看当前调查状态，沿用现有停止按钮 |
| 待评审 | 计划待确认 · 7 步 | 查看目标、版本、预计涉及范围、步骤和验证方式。批准并执行，或反馈后继续规划 |
| 启动中 | 正在启动执行 | 显示已确认版本和启动结果 |
| 执行中 | 第 5 / 7 步 · 运行类型检查 | 看已完成、当前、待执行的步骤与证据。需工具审批时沿用聊天现有审批 UI |
| 已暂停 | 暂停在第 5 步 · 等待重新检查 | 看原因，明确点击「继续执行」后再尝试 |
| 完成 | 已完成 7 / 7 步 | 查看结果、验证记录和关联消息 |
| 已取消 | 计划已取消 | 查看已有步骤与结果 |

「第 5 / 7 步」表示当前是第 5 步，即前四步已完成。等待工具审批属于当前步骤的说明，单独显示。执行中如有可靠文件记录，可补充「记录到 3 个文件改动」。首版按成功且确认改变文件的工具结果去重，统计当前计划下的文件路径。没有证据的命令输出、预先存在的未提交改动和模型文本不参与统计。若数据源只能识别部分文件，保留「记录到」字样。首版不提供行数或撤销按钮。

桌面和分屏按照聊天列的实际宽度适配。窄栏保留状态、步数与展开入口，当前步骤允许换行或省略，完整标题在展开面板中可读。评审面板继承输入框宽度，过长内容在面板内滚动，底部动作可换行，打开与关闭时维护焦点。使用 LFAA 浅色和深色主题变量，状态同时提供图标和文字。

## 2. 最小领域契约

- `PlanSnapshot` 包含 `sessionId`、`planId`、`revision`、`seq`、`mode`、`phase`、目标、作用域、步骤和当前执行尝试。作用域记录项目标识与 Host 解析后的工作区标识，客户端不提供授权路径。
- 步骤有稳定的 `stepId`、标题、预期结果、验证方式、状态和证据引用。状态为 `pending | running | completed | blocked`。首版只执行一条有序步骤链，最多一个步骤运行。跳过步骤如影响交付范围，应更新计划并重新评审。
- `PlanRevision` 记录描述和步骤定义。Host 校验模型输出后生成版本。批准绑定 `sessionId + planId + revision + scope`，批准版本的步骤定义冻结，执行日志单独更新。新的目标、工作区或步骤范围需要新版本和重新评审。
- 评审决策由 UI 发往 Host。批准与继续规划都带预期版本和 `requestId`。Host 在同一会话内串行检查、更新状态并登记执行尝试。旧版本回应冲突后刷新快照。重复请求返回同一个决定，两个标签页同时批准也只接受一个执行尝试。
- 所有更新包含会话标识与单调递增的 `seq`。Client 初次加载和重连读取持久快照，运行中复用 SSE 的 `plan_update` 事件。只接收当前会话、较新序号的数据。发现断档时重新读快照，避免把旧页面的审批或步骤混入当前会话。

建议接口为 `GET /api/plan/sessions/:sessionId` 读取快照，`PUT .../mode` 切换模式，`POST .../review` 提交批准或反馈，`POST .../continue` 显式恢复。操作合法性由 Host 判断。既有普通聊天 API 保持兼容，Plan 未启用时无需提供新增字段。

## 3. 执行边界与恢复

1. **规划运行。** Host 只暴露经过核查的读取工具和 `submit_plan`。执行前使用相同白名单二次检查，拒绝绕过工具清单的调用。规划允许保存会话和计划记录，工作区与其他业务存储保持只读。规划请求不触发目录自动创建、Git 初始化或基线提交。`save_memory` 虽然目前标记为 `read`，它会写长期记忆，不能进入白名单。
2. **提交和评审。** 模型提交结构化的 `submit_plan` 后，Host 保存快照并在工具边界结束规划运行。即便同批工具调用还有剩余，也不得继续执行。评审是一条可恢复的持久记录，关闭面板和断开 SSE 不会触发决定。
3. **批准和执行。** 批准先提交持久记录，再启动与版本绑定的执行运行，复用既有工具审批。审批页面明确区分「批准计划」与「授权当前工具」。执行状态只接受当前运行的合法步骤转换。模型可通过 `update_plan_step` 报告步骤情况，Host 校验顺序、版本和证据引用。测试失败保留失败证据，不把步骤标为完成。运行结束仍有未完成步骤时显示暂停及原因。
4. **重启和恢复。** 活动运行可重连。Host 重启后，未确定结束的执行显示暂停，标出最后确认的步骤。用户点击继续时先核对工作区和已记录结果，再继续未完成步骤。结果不确定的写入或命令不能直接重放。更换项目或绑定目录会要求重新评审。
5. **会话隔离。** 首版每个会话一份当前计划及其最新评审记录。旧会话按 Plan 关闭读取，原有会话不需迁移。分叉拷贝普通会话历史，新分支从 Plan 关闭开始，原会话批准不会转移。删除会话时其 Plan 状态一并删除。插件卸载时注销工具与订阅，并取消未结束的运行关联。

现有 Agent 工具审批负责单次写入和命令授权。作用域审批记录的是用户看过的目标和范围。Host 对工作区权限的检查独立执行，避免把一份概括性计划当作任意路径或命令的授权。

## 4. 实施清单

| 文件或目录 | 拟实施内容 |
| --- | --- |
| `packages/core/plan/package.json`、`tsconfig.json`、`README.i18n.yaml` | 私有工作区包，导出 `.`、`./contract`、`./client`，生成包 README。 |
| `packages/core/plan/src/index.ts`、`plan-service.ts`、`plan-routes.ts`、`contract/index.ts` | Cordis 服务、版本/状态校验、持久化接口、Host 路由和纯类型。Plan 以注入接口接收存储与执行能力。 |
| `packages/core/plan/client/Plan-Toggle.tsx`、`Plan-Progress.tsx`、`Plan-Review.tsx` 及同名 CSS Modules、`locales.ts` | 同包装配的响应式组件与中英文本。 |
| `packages/core/memory/src/types.ts`、`session-store.ts`、`index.ts` | 保存可选的、带版本的会话扩展记录。统一串行化同一会话的更新，避免消息写入与计划写入相互覆盖。 |
| `packages/core/agent/src/index.ts`、`agent-loop.ts`、`http-handler.ts`、`types.ts` | 接入运行模式、只读工具边界和版本绑定，增加 Plan 流式事件以及执行恢复入口。 |
| `packages/core/chat/client/composer-context.ts`、`chat-store.ts`、`stream-client.ts`、`components/ChatWorkspace.tsx` | 将旧提示词标签改接结构化会话状态，挂载 Plan 组件并消费状态。 |
| `apps/web/src/server.ts`、`main.tsx`、相关包清单与 `pnpm-lock.yaml` | 装配新插件、策略和路由，处理规划期间的目录预检，更新工作区链接。 |

依赖方向为 Agent → Plan Host 契约、Chat Client → Plan Client/契约，Plan 通过公开接口使用会话存储。应用入口提供执行回调，避免 Plan 和 Agent 相互导入。输入框挂载点由聊天包提供，沿用现有四栏 Shell。

## 5. 顺序、验收与回滚

1. 先实现服务、会话存储和状态机。验证旧会话读入、重复批准、过期版本、并发保存、会话分叉和删除。
2. 接通规划与执行。覆盖「完全访问」下的直调、同批次提交后的剩余工具、项目初始化和长期记忆副作用。验证获批后仍遵循现有工具审批，重启或停止后不会自动重放写入。
3. 接入可展开进度条与评审。内置浏览器覆盖双主题、双侧栏分屏、手机宽度、键盘操作、断线重连和跨会话隔离。最后运行相关测试、类型检查与构建。

新增包与跨包契约属于 A1。实施时将规划专用的 Host 写入限制单列验收，复用既有权限配置，保留普通模式的权限行为。回滚可关闭 Plan 装配并停用入口，保留已存会话；推出前验证旧客户端能读取带可选 Plan 记录的会话。
