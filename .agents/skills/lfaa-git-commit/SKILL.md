# LFAA Git 提交流程

本技能只规范 LFAA 仓库的提交边界。仓库根目录 `AGENTS.md`、`开发规范.md`、当前 `docs/PROMPTS.md` 合同和用户本轮要求优先。

## 触发与准备

1. 只有用户明确要求“提交 / commit”时才创建提交。“完成修改”“交付代码”不等于授权提交。
2. 核对仓库根目录、当前分支、`git status --short`、已暂存差异、未暂存差异和未跟踪文件。提交前不清理、回退、覆盖或暂存无关改动。
3. 对照当前任务合同，列出本次应提交的精确文件与必要验证。逐项审阅完整差异，识别同一文件内并行工作的无关改动。
4. 检查暂存区是否已经包含其他任务或用户的内容；不得用 `git add -A`、`git add .`、`git reset`、`git checkout` 或清理命令把它们混入或丢弃。

## 隔离与提交

1. 只暂存本次获准的文件或差异。若文件同时含有本次和并行改动，使用可核对的分块暂存；提交前再次检查 `git diff --cached` 和 `git diff --cached --check`。
2. 若暂存区已有其他任务内容，必须用路径限定或独立索引确保它们不进入本次提交，并在提交后确认原有暂存内容仍在。无法证明提交范围隔离时停止提交，报告具体冲突；不要清空别人的暂存区来继续。
3. 审阅暂存内容中的密钥、真实用户数据、生成产物、临时文件和无关格式化；发现不该提交的内容时只从本次候选提交中排除，不覆盖其工作树内容。
4. 使用仓库当前配置的 Git 身份。不要擅改全局/仓库身份，不添加虚构作者或 `Co-authored-by`，不因身份缺失伪造提交者。
5. 提交消息简洁说明真实变更。用户明确要求提交后，可以执行本地 `git commit`；推送、建 Tag、创建 GitHub Release、合并或部署仍需用户明确要求。

## 完成核对

- 记录提交 SHA、提交消息和实际包含的文件；查看 `git show --stat --oneline HEAD` 与 `git status --short`。
- 确认原有无关暂存和工作树改动仍保留，且没有误入本次提交。
- 如果提交命令失败，保留现场并报告原因；不得重置、改写历史或扩大暂存范围来掩盖失败。
- 最终说明提交 SHA、范围、已运行的直接相关验证，以及仍未验证的项目；未推送时明确写“仅本地提交”。
