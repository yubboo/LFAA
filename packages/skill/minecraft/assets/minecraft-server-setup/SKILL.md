# Minecraft 开服与恢复

预检或用户指定 Java 时，可用 `minecraft_resolve_core_artifact` 读取部署 Owner 的真实工件与运行时要求，再核对目标节点的环境。`runtime_resolve` 只确认传入主版本是否已安装，不负责判断核心要求。用户指定环境时部署须携带该节点的真实 `javaRuntimeId`；冲突先说明原因并请用户选择，不能省略参数后把自动选择说成符合指定版本。无需预检的普通自动开服仍可直接调用领域部署工具。

由用户提供的豆包 Skill 适配。它提供开服经验，实际能力以本轮工具、真实来源与节点回报为准；不承诺全版本、全核心或公网连通。

理解用户的版本、核心俗称、模组需求和目标机器。用户已给出的条件不再询问；无歧义的内存、端口和存储位置采用当前设置。版本不存在或目标机器有实质歧义时，一次澄清必要选项；不能偷偷替换版本。水桶通常指 Bukkit 插件生态，可解释 Paper 的兼容定位，由模型结合用户目标和真实目录选择核心，不能把 Paper 说成 Bukkit 本体。

本方法由所有应用共用的小鱼按目标发现和加载，不要求先进入 Minecraft 的界面。用户可选的应用/Skill 关联只是线索；未关联时也可以自主发现，关联后仍须决定是否需要正文、工具或专家。

区分核心部署与内容安装。原版使用真实目录中的 Vanilla；插件服、模组服按用户版本与兼容要求选择已登记核心，不把 Fabric/Forge 核心就绪说成整合包已安装，也不把 Paper 就绪说成指定插件已安装。当前没有专用模组市场/整合包安装工具时，明确说明范围，按需发现已授权的网页、节点 Shell、文件与环境工具，核对原始来源、下载完整性、许可、服务端/客户端适用性、加载器及游戏版本；不编造下载地址或默认换核心。游戏插件/模组放在实际实例目录内，由目标节点与实例状态合同保护，不能写入 Harness 的 data/plugins。

安装实际内容前核对节点和实例状态，沿用同一权限模式；需要停服的操作不得在运行状态直接改文件。启动后根据真实启动日志、模块/插件加载结果、进程及端口证据交付；仅下载或核心启动成功不能证明所有内容兼容。失败时保留原错误，依据新证据修复，不重复执行结果未知的写入或安装动作。

新开服优先使用 `minecraft_provision_server`：同一任务自动查找/安装匹配 Java、下载校验核心、写配置与实例元数据、启动并等候真实就绪。Paper 可省略 build，由工具选择目标版本最新稳定构建；省略端口时按设置默认值分配未登记端口。无需先逐项查询 Java、单独安装、创建启动脚本或手写 lfaa-instance.json。目标核心明确时按需查询该核心，避免读取全核心/全版本资料。独立查询可同轮发起；工具已返回就绪证据时直接交付，不重复收集同一证据。

复用已登记实例时，读取实例状态后直接选择启动或交付，不重新查询下载目录、构建、部署历史或所有提示词。节点上报的托管 Java 不依赖 PATH；不要用 where java 的结果否定它。Paper 的最低字节码与推荐 Java 不同，遵循领域服务的实际运行要求。故障时只查询最新错误所需的目录和少量日志，工具已提供 dataRoot/storageDirectory 时不再摸索磁盘。PowerShell 命令明确指定 shell=powershell。

缺少依赖时，优先让领域工具自动准备；需使用已提供的通用 Shell/文件工具时，先确认实际执行机器与已配置目录，使用可信下载来源及摘要，核实真实退出结果。不要把 Shell 的工作目录当成 data 根目录，不修改 PATH 或已有 Java 选择来掩盖问题。权限统一使用请求审批、替我审批、完全访问；EULA 与核心许可接受应在动作中说明，完全访问不额外要求去面板确认。读取 Skill 不等于授权。

任务失败先依据具体阶段与错误选择恢复；确认失败的部署使用 `minecraft_retry_deployment` 保留原实例和工件归属，不重复创建同名实例。结果未知或任务仍运行时只核对任务/状态/日志，不重放。防重反馈表示本次未派发，不能理解成整项任务已失败；根据已有证据纠正行动或给出真实最终结果。禁止反复重试无变化的源、手工伪造任务成功或把安装未完成的目录伪装成可启动实例。

交付说明核心/版本、实例、实际 Java、连接地址/端口和启动证据。本机监听不代表公网可达；开放防火墙、穿透、安装插件/模组等按用户实际目标和现有工具分别执行。需要专项方法时可使用 `minecraft_load_prompt`；普通开服无需加载所有提示词和参考手册。

独立环境需求使用 `runtime_list`、`runtime_resolve`、`runtime_operation` 与 `runtime_get_task`。`local` 是控制端本机，节点 ID 是实际执行设备；不能把控制端路径用到远端。安装先验证并复用已有主版本，按设置中的环境/缓存/临时位置执行；更新、卸载与移除登记须核对运行依赖。用户停止运行时，新环境任务和原生开服任务会请求取消；请求已发送不是执行器已确认退出。普通开服直接使用领域工具，无需为展示分工而强制重复调用子 Agent。

本机监听或 loopback 连接只证明该机器端口可用；局域网、外网与客户端登录均需各自实测，缺少证据写未验证。完成当前目标后简短交付，不追加改配置或清理其他实例的邀请。
