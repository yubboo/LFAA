# `lfaa-canvas-generation`

系统级画布的图片/视频生成编排 Owner。负责把用户在画布上的生成请求转换为真实的 Provider 调用，复用设置中心与凭据 Owner，并在成功后用画布 Owner 的能力原子写入素材与节点生成状态。本包不持有画布文件、素材二进制、模型账户、密钥或 Provider 协议；没有第二套认证、权限、会话或 Provider 实现。

- **权威归属：** 画布生成任务状态（节点 `data.generation` 的 `running/succeeded/failed`、`taskId`、错误原因、实际比例/时长）、生成请求参数边界与设置读取顺序由本包决定。项目/素材落盘与 `expectedUpdatedAt` 并发语义仍归 `lfaa-canvas`；Provider HTTP 协议与响应边界归 `lfaa-llm`（`generateProviderImage`、`createArkVideoTask/getArkVideoTask/cancelArkVideoTask/downloadArkVideo`）；账户、模型目录与生成设置归 `lfaa-settings`；密钥解析归 `lfaa-credentials`。
- **公开合同：** 包入口 `src/index.ts` 导出 Cordis 服务 `lfaaCanvasGeneration`（`inject ["lfaaCanvas", "lfaaSettings", "lfaaCredentials"]`）与 `createCanvasGenerationService(deps)` 工厂。服务方法：
  - `listImageModels(userId)` → 当前用户设置的默认图片模型与 Agent Plan 官方图像模型目录（只含账户/模型标识和公开元数据，不含密钥）。
  - `generateImage(userId, applicationId, projectId, { expectedUpdatedAt, nodeId?, prompt, modelTarget?, aspectRatio?, referenceAssetIds?, signal? })` → `Promise<{ project, asset: { assetId, name, mimeType, bytes } } | null>`；`modelTarget` 是经当前账户目录校验的单次账户/模型选择，不写回用户偏好；未指定时使用设置中的默认账户和模型。同步生图，成功才落素材，`nodeId` 存在时写节点 `data.generation`（`status="succeeded"`、`assetId`）。
  - `startVideo(userId, applicationId, projectId, { expectedUpdatedAt, nodeId?, prompt, durationSeconds?, aspectRatio?, referenceAssetIds?, signal? })` → `Promise<{ project } | null>`；校验设置与凭据后先把节点置 `running`，提交火山方舟任务后写入 `taskId`/`providerStatus`。视频必须指定生成节点。
  - `refreshVideo(userId, applicationId, projectId, nodeId, signal?)` / `cancelVideo(...)` → `Promise<CanvasProject | null>`；刷新按需调用（客户端只在面板可见时刷新，本包不建轮询计时器），只有服务商 `succeeded` 且下载到真实 MP4 才落素材并置 `succeeded`；失败/取消/过期置 `failed` 并写真实原因。返回 `null` 表示项目不存在。
  - 错误类：`CanvasGenerationConfigurationError`（控制器 400，未配置账户/模型、无密钥、模型不在目录、参数或参考素材无效）、`CanvasGenerationUnsupportedError`（控制器 501，本轮未接通的本机模型适配）、`CanvasGenerationNotFoundError`（404，生成节点不存在）；`CanvasConflictError` 沿用 `lfaa-canvas`（409）；其余 Provider 失败为普通 `Error`（控制器 422）。`CANVAS_GENERATION_LIMITS`、`CANVAS_IMAGE_ASPECT_RATIOS`、`CANVAS_VIDEO_ASPECT_RATIOS` 与纯函数（`normalizeImagePrompt`、`normalizeVideoPrompt`、`normalizeImageAspectRatio`、`normalizeVideoAspectRatio`、`normalizeVideoDuration`、`normalizeReferenceAssetIds`、`buildImagePrompt`、`mapProviderVideoStatus`、`videoTaskErrorMessage`、`isTerminalGenerationStatus`）同样公开，供控制器与回归复用同一份边界。
- **运行位置与装配：** Control Plane（Node），由 Web App Bundle 以 `id: canvas-generation`、`name: lfaa-canvas-generation`、`inject: [lfaaCanvas, lfaaSettings, lfaaCredentials]` 装配；`lfaa-api-canvas-controller` 通过 `lfaaCanvasGeneration` 注入。未装配前不得宣称路由可用。
- **设置与凭据：** 只读取 `aiRuntime` 既有配置，不新增第二套模型配置：画布图片使用 `imageGenerationAccountId/imageGenerationModelId`；`imageGenerationMode` 只决定 AI 漫剧使用本机或远程图片引擎，不会拦截画布的远程模型。AI 漫剧远程模式默认账户/模型与画布共用；Agent 可在模型目录中为单次画布生成选择 Agent Plan 图片模型。视频用 `videoGenerationMode/videoGenerationAccountId/videoGenerationModelId/videoGenerationDurationSeconds/videoGenerationRatio/videoGenerationResolution/videoGenerationGenerateAudio/videoGenerationWatermark`，超时统一读 `requestTimeoutSeconds`。账户必须属于当前用户且有密钥；图片支持 `openai`、`doubao` 和 Agent Plan 席位，视频支持 `doubao` 与 Agent Plan 席位；Agent Plan 图片/视频分别必须是目录中标记的对应能力模型，且匹配已选套餐档位。Settings 凭据来源将账户密钥解析限制为明确登记的消费者，`lfaa-canvas-generation` 已由 Settings Owner 登记；密钥只经 `lfaa-credentials` 解析，不写入项目、日志或响应。
- **数据与安全：** 参考图只允许当前项目素材（PNG/JPEG/WebP，单张 ≤3 MiB、最多 9 张、合计 ≤27 MiB），经画布 Owner `openAsset` 有界读取，不向模型发送缺失或不完整素材；生成结果经 `canvas.commitAsset` 与节点数据一次提交（素材字节原子写入 + 清单原子替换 + 回读校验），失败不留下素材记录；视频成片沿用画布 64 MiB 单文件上限。任务状态只写节点 `data.generation`，附加 `accountId/modelId/providerStatus` 仅用于刷新/取消恢复凭据与诊断。所有写操作都执行 `expectedUpdatedAt` 检查；刷新/取消在读取后遇到并发冲突会重新读取重试，不覆盖用户编辑。
- **如实边界：** 图片比例通过提示词附加“画面比例 X”说明传递——`lfaa-llm` 的 Provider 图片协议没有尺寸参数，本包不伪造服务商支持；`2:1` 只表示全景比例图像，不是真球面全景渲染。视频设置中心比例为 `adaptive` 时，画布没有导演台取景可继承，按 16:9 提交并把实际比例写回 `data.generation.aspectRatio`。本机 MOSS 图片模型与 MiniMax-H3 本机视频模型未在画布接通；画布图片使用已登记远程 Provider，不会因 AI 漫剧本机模式而返回 MOSS 未接通错误。画质增强/超分没有既有 Owner，本包不实现。
- **启用状态：** 源码与回归已实现（Provider 图片生成、火山方舟视频任务提交/刷新/取消、错误映射）。真实 Provider 计费调用、浏览器实页与桌面 WebView 属未实测边界；需 Lead 装配后按 Web Profile 验收。
- **验证：** `pnpm --filter lfaa-canvas-generation run build`（未识别新包时用 `cd packages/canvas/canvas-generation && node ../../../scripts/build-harness.mjs package`）；回归 `cd apps/cli && node --import tsx --import ./register-package-loader.mjs --import ./tests/isolated-test-environment.mjs --test tests/canvas-generation.test.mjs`——用注入的假画布 Owner 与假生成函数覆盖校验/未配置/失败/成功路径，不访问真实网络。
