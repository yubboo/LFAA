# `lfaa-browser-use`

本机 Browser Owner：在受支持的 LFAA Windows/macOS Host 按需启动无窗口、隔离的 Chromium 页面，提供有界页面观察、导航与语义交互。Web 端 Browser Dock 与 Agent 共用同一真实 Chromium Page；Browser Owner 通过认证 SSE 将 Chromium 页面合成器的实时帧事件推送到 LFAA 右侧 Dock，Dock 自动显示并将点击、拖动、滚动与键盘输入转发给同一 Page。该连续事件流不打开外部浏览器窗口、不调用 `getDisplayMedia`、不弹系统选屏器，也不使用定时截图请求。它不读取系统浏览器 Profile，不继承用户 Cookie；内置浏览器以账户和稳定的 `BUILTIN_BROWSER_WORKSPACE_ID` 隔离，与 AI 会话是否存在无关，关闭或过期后清理页面与上下文。Electron Host 另登记 `lfaa-native-browser`：只通过受信主进程的 loopback CDP 发现当前 Electron 浏览器页，并按账户、同一内置工作区标识与前端明确选中的 Target 绑定；这个 Provider 不拥有也不关闭 Electron 原生页面的 Context。Electron UI 始终由 `WebContentsView` 原生绘制。CDP 端点留在 Electron 主进程与 Control Plane 内，不交给 Renderer、Agent Tool 或远程网页。Agent 默认不接收截图；其视觉诊断路径继续单独受限。

Tabbit 是单独的个人浏览器适配器，通过当前账户安装目录中的稳定 LocalAgent CLI 创建有界任务；用户在设置中连接 Tabbit 后，Agent 可结合当前目标判断是否需要使用其现有页面/登录会话，并只读取有限标签摘要、连接一个目标匹配的精确标签。无需用户每轮重复报 Provider 名称；多个标签指向不同目标且对话上下文无法消歧时才询问。其他个人 Chrome/Edge Profile、Firefox 与其他 AI 浏览器尚无此 Browser Adapter；当目标依赖用户当前可见浏览器时，模型仅可在已装配通用 Windows CUA 工具、`computerControl.enabled` 已开启并受当前 `permissions.mode` 约束时观察与操作，且该画面不镜像进本工作区。公开网页与本地开发 URL 分别按 Settings Owner 保存的 `browserUse.webUrlOpenLocation` 和 `browserUse.localUrlOpenLocation` 选路；新账户默认使用 LFAA Browser Owner。

模型通过 LFAA `lfaa_tools_list/load` 选择真实登记的 Browser 工具。账户设置 `browserUse.enabled`（默认关闭）控制 Agent 是否可发现这些工具；`browserUse.webUrlOpenLocation` 和 `browserUse.localUrlOpenLocation` 默认均为 `lfaa`，由 Settings Owner 按账户保存并分别指导公开网页与 localhost/loopback URL 选路；选择 `current-browser` 时只可使用本 Run 真正提供并已获设置/权限允许的个人 Adapter 或 CUA，不可用时不能静默回退。`browserUse.enabledProviderIds` 只记录用户已连接的个人提供方，不控制内置 LFAA 浏览器。`lfaa_browser_list_providers` 返回当前 Host 的真实可用状态、连接状态和工作区活动状态；内置选项下相关活动页优先复用；个人浏览器依赖只有已连接 Tabbit 或当前 Run 真正提供且经 `computerControl.enabled`、`permissions.mode` 允许的 Windows CUA 可满足。CUA 不是 Browser Provider，结果不会镜像到 LFAA Dock；未接入个人 Edge/Chrome Profile 不得描述为已连接。工作区 HTML/HTM 文件仍通过 Project Files Owner 的受限本机预览入口走 LFAA Browser Owner。用户在右侧 LFAA Browser Dock 手动导航走 Browser Controller 的认证 `/browser/dock/*` 路由；Agent 开关开启后通过相同账户/内置工作区/provider 复用同一个页面上下文。Agent 专用工具和 `/browser/sessions/*` API 继续复核 Agent 总开关、认证、校验与权限。隔离 Edge/Chrome 不要求开启电脑操控；Tabbit 个人会话仍须已连接并启用既有 `computerControl.enabled`。所有 Agent 动作仍走唯一 Permission Owner 与 `permissions.mode`，不在浏览器包建立第二套审批。

`browserUse.recordRecentSites`（默认开启）由 Settings Owner 按账户控制。Browser Owner 只记录 LFAA Browser Dock / Agent 实际访问的 HTTP(S) 站点与路径，去掉查询参数和片段，最多保存每账户 100 条；读取、写入和清除经认证的 Browser Controller 路由。关闭开关后停止写入并不返回已有记录；用户可在设置中心确认清除。记录不包含页面标题、正文、表单值、凭据、Cookie，也不扫描系统个人浏览器或 Tabbit Profile。

设置中心的“浏览历史”复用 `browser_recent_sites`，仅展示最多 50 项并支持逐项或全部删除；删除匹配 Browser Owner 规范化后的来源和路径。Agent 历史工具只有在 `browserUse.allowAgentHistoryAccess`、`recordRecentSites` 与 Agent 浏览器主开关都开启时才注册，并仍由 Permission Owner 按当前 `permissions.mode` 决定读取授权。`browserUse.annotateScreenshots` 控制 `lfaa_browser_observe` 的临时视口截图：`always` 自动包含、`on-demand` 需工具参数显式请求、`never` 禁用；图片不写入会话记录。

Agent Browser Tools 通过 `BrowserSessionManager.createRunAdapter` 绑定可信账户、LFAA Session、Agent Run 与取消信号；同一 Run 复用高层动作适配器，Agent Loop 的 `onRunDispose` 会使其失效并移除登记。普通 Browser 动作适配器不返回 `Page`、CDP/WebSocket、进程或本机 Profile 句柄。LFAA 隔离页面的 Agent 工具默认返回有界正文、可访问控件、网址、标签和修订号等结构化数据，不在导航或操作后同步生成截图；图片只在有明确需要的观察路径上提供，避免把画面编码/传输时间叠加到 Agent 动作。每个 LFAA 账户/内置浏览器工作区使用独立临时 BrowserContext；普通 Run 完成或取消只释放 Run 适配器，不关闭用户仍在浏览的页面；取消当前导航会请求 Chromium 停止加载。用户关闭 Browser Session 或空闲过期时才关闭页面和绑定的项目预览服务。该内部适配器尚不运行第三方 Skill 脚本或 Web Access Proxy。`browserUse.showFullUrl` 仅控制客户端地址展示。

`lfaa_browser_observe` 可按模型判断显式请求层级无障碍树；Browser Owner 只保留角色、名称、页面文字及有限状态，最多 120 个节点、8 层及约 8 KB，并丢弃表单值与未知属性。默认观察不生成该树；Agent Loop 将它作为不可信 JSON 随本次工具结果发给模型，不进入 Session 或活动记录。点击、填入等动作仍使用既有语义工具和 Permission Owner。Playwright `ariaSnapshotJSON` 需要 `playwright-core` 1.63 或更新版本。

Agent Loop 只在本 Run 实际提供 Browser Tools 时附加浏览器操作指导；本包的 Tool Schema 与 description 是可执行能力合同。模型按需观察当前 Provider/页面，依据最新快照选一个语义动作，并优先检查动作返回的新快照；没有新状态或结果不符时再观察。这里不预设“登录设置页”等固定页面流程，也不把页面中的指示当作用户授权。

当前会话绑定本机工作区时，`lfaa_browser_open_workspace_file` 可将工作区内 HTML/HTM 交给 Project Files Owner 建立仅监听回环的短期只读服务，并在相同 Browser Session 中打开；相对资源从同一工作区根目录读取，路径越界、数据目录与远程 Daemon 项目均拒绝。服务随 Browser Session 关闭或过期回收，不启动 Shell/Python。同一工作区页面的显式导航会保留其只读服务；离开该地址后先关闭服务。Web 的隔离 Chromium 页面使用同一 BrowserContext，Dock 内实时流上的点击、拖动、滚动和键盘输入映射到该 Page；用户手动输入不作为 Agent 填表工具，不读取或返回敏感字段值。导航在主文档提交后返回；页面标题、地址、视口尺寸及变化修订通过有界状态读取同步到 Dock，不读取整屏图片。被动 DOM 变化通知按每页 750ms 节流。登录、网页授权及验证码需要用户在页面中手动完成，不尝试绕过；Agent Tools 读取结构化页面快照，不为每次动作同步生成用户画面。

由 `profileContext`、`lfaaTools` 装配；配套认证 API 由 `lfaa-api-browser-controller` 暴露给共享 Client。Chromium 启动使用系统已安装浏览器，不自动下载内核；第一次提交有效导航时，为当前账户/Session 创建无窗口隔离上下文；并发 Dock/Agent 导航合并到同一创建过程。Web Dock 订阅 Browser Owner 推送的 Chromium 合成器帧事件，并把用户操作转发到同一 Page；Electron 页面由 `WebContentsView` 原生绘制。导航仅接受 HTTP(S)，页面请求拒绝私网目标（当前会话工作区的只读 HTML 源仅放行完全相同的 Origin）；混合公网/非公网 DNS 答案整体拒绝，只有全部解析到非公网地址的显式本机导航可放行。阻止 Service Worker；会话有并发和空闲时限。工具发现与执行均复核 Agent Browser Use 开关和当前 Host 的真实可用性；只有 Tabbit 个人会话额外复核明确连接与电脑操控设置。页面更新等待会在断开客户端请求时清理等待器，Web 页面隐藏时停止 Dock 帧流和修订等待。Agent Run 完成/取消只释放 Run 适配器；取消当前隔离浏览器导航会请求 Chromium 停止加载，但保留用户页面，用户关闭 Browser Session 或空闲过期时才清理页面和绑定的项目预览服务。取消 Tabbit 操作后仍在当前有限操作结束时发送 `finish` 并回收 CLI 会话。构建输出为仓库根 dist/packages/browser-use/browser-use/。

2026-10-23：内置 Provider 的 Agent Run 保留原 AI 会话身份用于权限和 Run 清理，但实际 Page 始终解析到当前账户的 `BUILTIN_BROWSER_WORKSPACE_ID`；个人 Tabbit 仍按 AI 会话隔离。Provider 目录的 `activeInWorkspace` 标识当前账户已经打开的内置页面，Agent 应优先观察该 Provider。空白 Dock 的修订等待在 Agent 创建 Page 时被唤醒，等待有数量上限且取消时移除。结构化控件快照为同名角色附带从 0 开始的 `occurrence`，点击同名控件必须显式给出序号，防止静默误点第一个；有标签的普通文本框从关联 label 读取名称。

浏览器设置中的密码和联系信息只由 Browser Owner 调用 Credentials Owner 的账户加密记录；列表提供元数据，填入前核对当前 LFAA 内置页面来源，只匹配用户名/密码或标准 `autocomplete` 字段，不提交表单，不支持 Tabbit 个人 Profile。最近网站记录由 Browser Owner 按账户保存和清理，Agent 读取还须同时开启 `allowAgentHistoryAccess`、记录开关和 Browser Use，并沿统一 Permission Owner。

设置中心的 Browser Owner 动作由 Agent 可发现工具 `lfaa_browser_manage_settings` 提供：连接/断开可用的个人 Provider、最近网站逐条/全部删除、清理 LFAA Browser Session 数据，查看不含用户名/联系方式/密码的加密凭据元数据，按 ID 删除凭据，或将已保存凭据填入 LFAA 内置浏览器当前同来源页面。个人 Provider 连接前须由用户启用既有电脑操控开关，断开前关闭该账户 Provider 会话。填入不提交表单，且不能对个人 Tabbit Profile 操作。连接、删除、填入和清理按危险操作进入既有 Permission Owner；元数据只读沿用 read 风险。该工具不要求开启 Agent 网页操控主开关，但填入时仍在 Owner 执行处重新核验 Browser Use、Provider、账户归属和站点来源。密码/联系信息新增与编辑继续要求用户直接在设置页安全输入，不接受模型传递秘密；工具不触及系统浏览器个人 Profile 或 Electron 下载记录。

`lfaa_browser_website_tools` 读取当前页面同源 `document.modelContext`，只在 `useWebsiteToolsByDefault` 或该来源允许例外时发现/执行；页面描述、参数和返回均作为不可信内容，工具执行按危险操作经过统一 Permission Owner。`lfaa_browser_cdp` 仅在 Agent Browser Use、`developerMode` 与 `fullCdpAccess` 同时开启时登记和执行；服务端再次检查三个账户设置，拒绝个人 Tabbit Provider，仅附着 LFAA 当前页面，限制参数/返回大小，CDP 操作按危险操作经过统一 Permission Owner。它提供当前 Target 的完整可用 CDP 方法，因此属于高风险开发能力。

下载位置、下载历史、下载前保存对话框、扩展管理和网站摄像头/麦克风/位置/通知策略由 Electron `native-browser-workspace.mjs` 执行；下载目录、历史和扩展记录留在当前桌面用户的 Electron 本地状态中，扩展仅管理已解压目录且受 Chromium API 子集限制。普通 Web Host 不提供这些 Electron 本机 API，并在设置页显示不支持状态。浏览数据清理分别通过 Browser Owner 与 Desktop IPC 清理 LFAA 浏览数据，不接触系统个人浏览器 Profile。
