# Session JSONL 持久化

`lfaa-session-persistence-jsonl` 为 Session Owner 保存账户隔离的 JSONL 事务日志。每笔追加事务写入前按当前序号与 SHA-256 链校验，提交后 fsync；Session Owner 是本包写入接口的唯一业务调用者。

`repository.ts` 保留轻量头、计划模式与关联引用投影；标题列表借 SQLite 选择最多 200 个账户隔离键，直接返回已校验的权威头和状态，不逐条恢复完整 Kernel。每个已保留会话头仅关联一份经过完整日志重放校验的引用投影，随受控事务同步更新；查询不命中也不会逐会话重扫 JSONL。正文缓存按最近使用淘汰，最多 8 个会话与 32 MiB 编码记录预算。

Session JSONL 重放和受控用量提交同时维护账户级汇总：总请求数、可用 Token 总和及 Provider/模型分组；模型分组计数还保留带 Provider 缓存读取数的请求数。单行用量不会为汇总请求重新加载；运行时内存与账户数及不同 Provider/模型组数相关，而不随历史请求行数增长。JSONL 仍是唯一权威记录，重启后通过完整日志校验重建投影，缺失 Token 仍保持未知。最近消息页投影还保留每会话累计用量和最新 `request/context` 快照；容量按该请求的模型保存，Provider 响应中的实际 prompt Token 更新总占用，消息分项估算不会标成实际值。

JSONL 重放和受控写入同时维护展示字段白名单内的最近 100 条消息、反馈和分支来源；所有会话共享最多 128 页/16 MiB 编码内容预算。关联引用以 WeakMap 附着在本就保留的轻量会话头上，每个会话最多保存设置校验限制内的 ID 引用；不会保存完整事件，头被移除后投影可回收。首屏仅在文件大小、修改/变更时间、设备和 inode 与已完整校验的日志版本一致时使用最近页投影。更早页在会话仍处于正文缓存（最多 8 会话/32 MiB）且完整日志修订令牌未变化时，从已完整重放的记录生成有界候选页，并周期性让出事件循环、响应 AbortSignal；读取期间若修订变化会丢弃结果。缓存冷却/淘汰、文件版本变化和首次读取继续使用固定 64 KiB 缓冲、最多 101 个候选正文的异步单遍扫描，校验完整 SHA-256 链、稳定游标顺序及相关反馈。冷页 CPU/磁盘读取仍随完整日志增长；仓库启动恢复保留的事务去重索引也按历史事务数增长。缓存预算不等于 JS 堆实测；持久索引与 compaction 尚未实现。

`rewrite()` 仅供 Session Owner 在校验账户归属后重写单个会话日志。它验证原链、保留事务身份与顺序、写入受限临时文件、fsync 后原子替换日志，并重新计算完整性链。AI Work 个人记忆删除使用这一受限入口移除历史模型请求快照中的注入记忆正文；不修改普通用户/助手消息，也不重写其他会话。

`storageLocation(sessionId)` 只从受限会话 ID 推导 JSONL 根目录、哈希会话目录和 `events.jsonl` 路径，不访问或读取日志，也不确认目标文件是否存在。只有上层 Session Owner 完成当前账户/App 归属校验后，才能将此元数据提供给 Agent。

消息页与结构事件页共用私有 `scanChanges`：同一次流式扫描校验完整哈希链，不复制第二套恢复逻辑。消息页可在扫描中把事件交给调用方观察；投影缺失时 Session Owner 据此提取分支来源，不触发第二遍读取。断开请求会沿 AbortSignal 取消日志扫描。事件页最多 100 个白名单投影与一个下一页候选，按事件序号查询不会载入完整 Kernel；事件页与冷消息页仍需扫描完整日志。

最近消息页白名单投影同步关联主回答 `usage/record`，按原有 128 页/16 MiB 全局预算计入缓存并在消息淘汰时一同移除；冷页在同一遍哈希链扫描中匹配用量事件。回复后记忆请求标记为 `purpose=memory` 并排除在该消息的主回合显示用量之外。
