# Session JSONL 持久化

`lfaa-session-persistence-jsonl` 为 Session Owner 保存账户隔离的 JSONL 事务日志。每笔追加事务写入前按当前序号与 SHA-256 链校验，提交后 fsync；Session Owner 是本包写入接口的唯一业务调用者。

`repository.ts` 保留轻量头/定位和计划事件投影，正文缓存按最近使用淘汰，最多 8 会话与 32 MiB 编码记录预算。冷读取重新校验 JSONL；标题列表借 SQLite 选择最多 200 个账户隔离键后返回权威头与轻量状态，不加载整批 Kernel。消息页以固定 64 KiB 读取缓冲、单个当前事件和最多 101 个候选正文工作，响应最多 100 条；异步单次扫描校验整条哈希链、稳定游标顺序及相关反馈。因此不会把超长会话正文整体载入分页工作集，但每页仍需遍历完整日志，CPU/磁盘读取量仍随文件增长；仓库启动恢复保留的事务去重索引也按历史事务数增长。缓存预算不等于 JS 堆实测；持久索引与 compaction 尚未实现。

`rewrite()` 仅供 Session Owner 在校验账户归属后重写单个会话日志。它验证原链、保留事务身份与顺序、写入受限临时文件、fsync 后原子替换日志，并重新计算完整性链。AI Work 个人记忆删除使用这一受限入口移除历史模型请求快照中的注入记忆正文；不修改普通用户/助手消息，也不重写其他会话。

消息页与结构事件页共用私有 `scanChanges`：同一次流式扫描校验完整哈希链，不复制第二套恢复逻辑。消息页可在该次扫描中把事件交给调用方观察；持久化层不解释业务事件，Session Owner 只在首屏据此投影分支来源，不触发第二遍读取。事件页最多 100 个白名单投影与一个下一页候选，支持 AbortSignal；按事件序号查询不会载入完整 Kernel。事件页的全日志读取量与消息页相同，仍未接入持久索引。
