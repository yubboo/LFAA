# `lfaa-client-ui-workspace`

共享小鱼工作区接收 Workbench 投递的 `AiWorkGoalRequest` 并传给 `AiWorkChat`；聊天仍通过既有 Agent Loop 执行目标，没有 Provider 时保留草稿。

`AgentOfficePage` 消费 Client Connection 的认证 `/ai/office` 快照，展示已登记专家、主 Agent、真实活动任务、父子关系与公开活动标题。页面只读；单链 5 秒刷新在页面隐藏时取消，未完成请求不重叠。工位按实际容器宽度排列，使用 Workbench 当前 Appearance；不新增设置或用户数据。

2026-10-16：普通 App 是手动操作与成果管理面板，Agent 对话、能力资源和侧聊只在共享工作区展示。写作侧栏改用 `normal/WritingBookInfo`，保留作品信息与写作方法管理，不再提供 App 专属 AI Work 切换。普通面板不加载 Agent 能力目录；共享工作读取目录可取消，离开或切换账户时撤销请求。两类自定义模板（成果/应用面板）的目标与待实施范围见 [模板目标](../../../docs/development/application-panels-templates.zh.md)，本轮不声明模板运行时已实现。

Web/Desktop 共用的应用工作区 UI。除通用 Workspace 外，`AiVideoCanvasWorkspace` 将单个 AI 漫剧项目呈现为剧本、角色/场景档案和 React Flow 分镜画布，通过 Client Connection 调用认证 API 保存，不把浏览器存储作为项目数据 Owner。

系统画布的图标工具轨与顶栏直接使用 `@ant-design/icons`，图标控件仍提供可访问名称与悬停提示；画布项目、节点和素材 Owner 不变。

无限画布的小地图由 React Flow `MiniMap` 渲染在画布左上区域，避开顶栏与左侧工具轨；账户级 `canvas.showMiniMap` 只控制显隐，仍由 Settings Owner 保存。

系统画布的导演台节点由 `CanvasWorkspace` 打开 `CanvasDirectorDeskEditor`，编辑器消费 `ui-primitives` 的懒加载 `DirectorDeskStage`，提供程序化白模角色/场景块、对象列表与变换、环境/灯光、导演相机与实时取景预览。镜头及场景数据写入当前节点 `desk.scene`，沿用既有 Canvas Project API、账户/App 项目隔离和版本冲突校验；不创建第二份存储，也不调用生成服务。场景拖动吸附读取 `canvas.snapToGrid`，外观沿用 Appearance 共享主题令牌，编辑器按容器宽高适配窄栏与短屏。

`/apps/<app>/canvas` 由 `ApplicationWorkspace` 装配唯一的 `AiWorkChat` 会话运行时，再将聊天内容交给 `CanvasWorkspace` 的 DockKit 右侧栏；画布右下角入口打开同一会话/流式 UI，关闭面板会保留已挂载的聊天实例。中心画布和助手由 `ResizableWorkbench` 作为相邻区域排布，桌面默认宽度沿用 DockKit 右栏初始规则（22%，240–340px），拖动时画布同步挤压，右栏最大占工作区 40%，让中心画布始终宽于助手；吸附收起、反向拖回、键盘调整及释放清理均复用同一组件。此面板不读写布局 localStorage，宽度只在页面实例内变化；容器变窄时沿用 DockKit 响应式 Dock/Overlay 规则。面板默认开合沿用账户级 `canvas.agentPanelDefaultOpen`，不复制会话状态或 Agent 执行链。

整体布局由 `.module-workbench-stage` 外层盒子包住一个 `ResizableWorkbench` 根节点。图标功能区、二级菜单、中间工作区和右侧菜单作为根节点的四个同级区域直接传入；各区域 class 分别为 `module-workbench-region--leading`、`--secondary-navigation`、`--center-workspace`、`--right-menu`。分隔条与浮层是布局辅助元素，不把四个内容区域互相嵌套。公共几何样式从 `ui-dockkit/src/css/common.css` 复用；图标轨样式由 `ui-sidebar/src/GlobalNavigationRail.css` 负责，左二、中间、右侧内容盒子的样式分别由 `src/css/secondary-navigation.css`、`center-workspace.css`、`right-menu.css` 负责；`src/css/workbench-regions.css` 只保留四个同级区域共用的文字基线与底部面板样式。普通应用页面共用 `ApplicationNavigationPanel` 作为左二主导航，不在各 App 页面重复装配菜单；右侧显示当前应用工具与上下文。AI Work 左二保留会话/项目，右侧承载工具与资源。设置、文件和插件管理等独立页面继续由各自 UI 包维护。图标轨宽度继续使用现有 64px/48px 令牌，并沿用账户外观设置。

普通专业 App 页面复用同一主导航与中心标题栏；标题栏和主内容容器共用按中心列宽计算的水平锚点，并整体左移 8–16px，左右留白总量保持不变。宽列的基线留白为 20–32px，中心列不超过 560px 时为 8px/24px，不超过 360px 时为 8px/16px。专用 Writing、AI 漫剧与 AI Work 画布继续使用各自内容布局。

应用侧栏与中心区复用 `ResizableWorkbench`。Compact 普通应用默认临时收起左二；悬浮预览只由顶部栏指定切换按钮及其窄连接命中区，或键盘可见焦点打开，指针经过左侧其他区域不触发展开。打开后左二复用同一 Dock pane，中心区保持锚在左一全局轨之后，不因预览宽度右移；临时响应式开合值不覆盖保存偏好，回到 Desktop 后恢复。用户显式展开时仍由 DockKit 管理 Dock 几何。Mobile 左二由 DockKit 按真实容器可用宽度选择 Dock 或 Overlay。公共几何样式由该组件引入 `src/css/common.css`；各区域的局部外观继续由各自 CSS 文件维护。AI Work 将标题栏、对话流、输入区和上下文/缓存用量栏放在同一聊天根盒子内按 Y 轴纵向排列；对话流内部再分左侧锚点导航轨、中间消息流轨和右侧原生滚动条轨。标题、对话盒、输入盒和用量盒分别以同一份按中心容器宽度计算的间距左右对齐；对话内部的锚点与滚动条轨延展至中间列边缘，消息列表为滚动条预留补偿宽度，保持正文宽度与输入卡一致。此布局不改变 DockKit 四栏宽度与保存偏好。窄分栏使用同一容器公式，短屏时输入区仍可滚动并访问底部操作。

漫剧界面沿用工作台设置的主题、字体、强调色、侧栏对比色和字号；不新增外观设置。减少动态效果偏好由工作台现有样式链继承。剧本、角色/场景文字描述、参考图、镜头文字/连线/引用、视频任务状态、导入媒体、时间线和白模相机状态均由服务端账户项目文件保存。镜头图片用设置中心所选 OpenAI/豆包模型，已关联的本机角色/场景参考图会随请求传入。镜头视频用设置中心所选火山方舟账户/模型与参数；提交后显示真实排队/运行状态，工作区在当前项目打开时串行查询，应用服务也会在运行期继续保存任务结果。媒体工作区支持项目媒体浏览、导入/删除、视频/音频/字幕时间线、剪辑预览和浏览器原生编码导出；成片保存回项目并可下载。3D 导演台使用原生 Canvas 透视投影编辑白模和相机；用户点击后可启动设备取景并保存镜头参考图。上传与导出各有明确容量边界，音轨混合和 MediaRecorder 能力取决于运行浏览器。代码已接入；真实浏览器编解码、相机权限、桌面与运行服务尚未验收。

Git“变更”工作区以紧凑工具条和按文件排列的真实差异列表呈现；路径、状态、增删行、当前分支/上游来自 Git Owner，最多 4 个可见文件差异并发读取，滚出范围时取消请求并释放内容。差异左右并排显示并带旧/新行号，未变更区间默认折叠；展开区间通过认证 API 请求更多真实 Git 上下文，单次范围限制为 1000 行。完整文件查看复用现有只读/编辑器合同；暂存、提交、分支及远端操作仍在独立管理面板中。分支间比较未接入时不显示为可用操作。差异沿用 Appearance 的代码字体/字号、差异标记、主题和背景映射。

构建输出位于仓库根 `dist/packages/client/ui-workspace/`。

工作区终端可切换真实交互式会话和 Agent 任务输出；交互页选择已连接的本机/远程 Daemon，使用 xterm 处理输入、ANSI、中文、尺寸变化和 Ctrl+C。沿用 `general.integratedShell/taskFolder/terminalPosition/showBottomPanelControl`、统一权限模式及工作台主题、代码字体/字号、强调色、壁纸/遮罩/模糊和减少动态效果。容器 ResizeObserver 合并一帧内的缩放，输入与缩放分别串行发送；绘制容量 512 Ki 字符、历史 2000 行，超限失败关闭。卸载关闭会话并撤销 SSE、观察器与动画帧；节点状态查询复用可见性控制的串行轮询。

AI Work 的聊天始终留在中心工作区。顶栏 Git 菜单打开项目摘要悬浮卡：当前会话绑定的仓库置于主卡，账户下其他已登记项目文件夹逐行显示各自的真实 Git 状态和增删统计；“变更”入口联动打开对应仓库的右侧 Git 管理面板，不替换聊天或输入区。摘要下方“输出内容”和“来源”只汇总当前会话活动记录里的真实新建/修改与读取文件，超过首屏数量时可展开“查看全部”；通用附件未接入时不伪造来源。Agent Git 管理器管理多个完整本机项目仓库，并随 Agent 会话绑定；不要求用户手工添加仓库，也不依赖 Daemon 节点。默认工作区启用本地 Git 版本管理；用户项目在 Agent 首次获准实际创建或写入文件时自动初始化，Git init 与本次文件操作共用 Permission Owner 授权。状态、变更统计、差异、文本查看/编辑、暂存、提交历史与分支操作都基于真实仓库根。本地执行由 Agent Git Controller、Permission Owner 与 LFAA Host 负责。分支前缀读取账户 `git.branchPrefix`，Appearance 继续使用工作台共享主题。HTTPS remote 支持 fetch、干净工作区快进 pull、当前分支 push 和发布分支；凭据按账户加密保存。SSH 同步与 PR 写入未接入。Agent 的可选 Daemon 项目仍只表示节点任务目标。

AI Work 主聊天从空闲切换到运行时自动展开 Git 摘要卡，并复用现有摘要开合/会话仓库绑定流程；后续重复运行通知不会反复触发，空闲后用户仍可手动开合。手机布局同步打开左侧摘要页，沿用 DockKit 的临时开合恢复，不覆盖已保存布局。运行状态来源为当前 `AiWorkChat` 主 Run，不新增 Agent 状态或 Git 请求通道。

主项目和其他项目文件夹各自的“变更”行在悬停、键盘聚焦或触屏环境下提供 Git 操作入口。增删数和展开箭头组合为行尾信息；桌面悬停或键盘聚焦时收起该信息，并由最右侧 Git 操作图标接替。触屏下同时展示操作图标和留出空间的行尾信息。桌面四项 Git 操作菜单竖排；手机卡片内改为四项横排，卡片极窄时切换为两列并自然占位，不覆盖项目内容。项目分支与标题保持同一行并靠右显示。摘要滚动区与外框使用紧凑且左右对称的间隙；不为滚动条预留双侧空槽，只有内容溢出时滚动条才占用空间。项目增删数和分区计数由行与内框的留白和滚动条隔开。“输出内容”和“来源”各自使用完整宽度的内框，标题/文件信息左对齐、项目数右对齐，内框和行内容都限制在卡片宽度内。点击当前图标、点击菜单外部、按 Escape 或选择操作都会关闭；四项操作分别定位到现有管理器的提交信息、远端推送按钮或分支管理弹窗，不复制 Git 执行、远端能力和权限逻辑。Agent 写入活动变化时，已打开的摘要会取消过期读取并重新查询最多 12 个真实仓库的状态；不轮询，卡片关闭后会撤销计时器和请求。

手机布局不再把摘要作为悬浮卡片；从顶栏打开后，摘要在左侧项目/会话栏中作为独立页面显示，沿用同一份项目、Git 状态、输出和来源数据。顶部“项目与会话”返回按钮回到原会话列表，侧栏关闭、Escape 与进入 Git 管理器也会结束摘要页；操作项仍使用同一 Git 管理器。摘要内容在侧栏内独立纵向滚动，不改变会话/项目选择 Owner。

## 小鱼共享工作入口（2026-10-14）

根地址与默认首页进入 `/work` 小鱼智能体对话区。全局导航的“应用”入口打开右侧 Dock 的“应用”视图，保留游戏库及 SteamCMD、Minecraft、LFAA 联机服务、写作空间和 AI 漫剧常规入口。应用切换继续调用 Workbench/Client Renderer 已有打开与路由标记，不在菜单复制业务规则；应用视图选择状态由 Workbench 持有，切换 App 路由后保持可用。

右侧“应用”视图复用相同的过滤后导航清单和 `SecondaryNavigation` 回调。应用入口卡片根据右栏实际内容宽度自动排成多列；窄栏和嵌入式窄容器自动回到单列。卡片表面、强调态和文字沿用 Appearance 共享令牌，不改变 `general.hiddenApplicationNavigationIds` 或 Dock 宽度偏好。

设置、文件和插件页发出的跨页“应用”请求按 `requestId` 在工作区内最多消费一次：先标记并确认请求，再更新 Dock/工具页签状态。响应式测量或回调身份变化导致 effect 再执行时，已处理请求不会重放。

`/work` 和专业应用共用固定四栏：全局导航轨、左侧二级栏、中间工作区、右侧工具/上下文栏。普通应用左二显示 `Workbench` 注入的 `applicationNavigationItems` 与当前应用子页面，由 `SecondaryNavigation` 呈现并调用现有路由/App 打开回调；AI Work 左二显示草稿、置顶、项目和最近会话。普通应用右栏只呈现当前应用工具、资源与状态；AI Work 右栏继续以“工具与资源”/“应用”视图访问工具及应用菜单。Minecraft、联机服务子菜单和写作目录 Portal 属于普通应用左二。全局应用按钮在普通应用中开合左二，在 AI Work 中切换右侧应用视图；设置、文件和插件管理页的打开请求进入 `/work` 并展示同一右侧应用视图。各区域尺寸、拖动、收起和响应式行为仍唯一归 `ResizableWorkbench`。

AI Work 的会话与右侧工具页签由 `ApplicationWorkspace` 持有。中心区展开时只在标题栏显示当前会话名；中心列拖动越过完全收起阈值、按住不放时，右侧菜单顶栏立即显示会话、新标签页、已打开的工具页签和加号；反向拖回或取消手势会撤下预览，松手仍停在阈值才提交收起。初始工具页签为“新标签页”，展示真实可用的浏览器、Git 变更、侧边聊天、应用导航和已登记扩展面板入口；点击入口后当前空白页签变为该功能，标签栏末尾的加号紧跟已开标签并创建新的“新标签页”，各页签可关闭。只有 Git“变更”标签是单例：打开后所有新标签页隐藏重复的“变更”入口，再次从程序入口调用时聚焦已有 Git 标签；关闭后入口随当前标签状态恢复。其他工具仍可重复打开并继续显示入口。Skill/Prompt/Expert/Tool 目录只作为能力资源展示，不伪装为可点击 UI 功能；浏览器、Git、应用和扩展页都复用各自现有 Owner。选择会话页签恢复中心列；拖动收起时暂时填满工作区的浏览器 Dock 不覆盖用户保存的栏宽，聊天恢复后回到收起前的宽度。`ResizableWorkbench` 只在吸附预览状态变化时通知上层，不随每帧尺寸更新触发 React 渲染；页签是组件本地瞬态状态，不创建第二个浏览器或会话。

首次桌面三栏工作区默认展开右侧资源栏以组成四个可见区域；用户已有面板开合状态继续优先。`general.navigationLayout`、Appearance 共享令牌和 `ResizableWorkbench` 左栏宽度偏好保持现有设置 Owner，不新增或重置配置。

AI Work 右侧“新标签页”以工具主页呈现：变更、终端、文件和侧边聊天按右栏实际容器宽度排成紧凑双列或单列；应用、扩展面板及已登记能力资源收在原生“更多工具”展开区；浏览器本身是该标签页的内容模式，不作为另一个工具或另一个工作区标签。主页地址栏常驻在标签条下方；提交网址/搜索、推荐站点或最近记录后，只替换主页内容，BrowserPanel 的网页画面在同一红框内容区域显示，工具栏和右侧工作区标签保持原位。BrowserPanel 隐藏期间读取当前 Browser Owner 已有标签，不在主页访问时启动新浏览器会话。推荐与最近继续复用当前 Browser Owner 数据和一次性导航请求，不另建网站清单或读取个人浏览器历史。样式由本包 `src/css/right-menu.css` 单独维护并沿用 Appearance 主题令牌。

推荐区继续显示当前打开的网站标签；“最近”通过 Client Connection 的认证 API 加载 Browser Owner 按账户保存的 LFAA Browser Dock/Agent 最近网站记录，点击记录复用当前工作区标签。记录是否启用由 Settings Owner 的 `browserUse.recordRecentSites` 控制；该区域只保留按需查询的页面状态，不建立本地历史库。新标签页地址栏复用 Browser Address Owner 的 URL/搜索词解析与 Browser Dock 导航；手动导航不要求用户接入 Provider 或改 Agent 设置。浏览工具栏在主页与网页内容模式保持同一套；BrowserPanel/NativeBrowserPanel 只渲染网页，不再包含嵌套地址栏、Provider 选择或第二套标签。推荐、最近和地址栏进入同一个 Browser Owner Session；若 Agent 已配置为同一账户/内置工作区/provider，则可按现有权限与设置复用同一页面。关闭右侧工作区标签时只移除该页签，最后一个页签以空白“新标签页”替代并收起右侧栏。
