# client/ui-sidebar

全局导航轨在所有页面共用固定的入口顺序：小鱼智能体、应用、最近会话、设置、文件管理及更多功能。它不随当前 App 插入显示器样式的模式主页或重复 AI 工作捷径；应用内部主页与功能模块由左二当前工作区导航提供。“更多功能”“个人账户”和“键盘快捷键”浮卡左边缘与左二栏起点对齐，宽度按 Workbench 左栏最小宽度减去 12px 滚动槽计算，底边与导航轨 14px/安全区留白对齐；短屏内容在卡片内滚动。功能列表也为自己的滚动条保留稳定槽位。应用切换、会话和权限继续由原有 Owner 管理。

## 小鱼共享工作入口（2026-10-14）

全局导航轨增加独立 `/agent-office` 入口，并在办公室路由标记当前页；页面呈现归 `ui-workspace`，导航组件只负责进入路由。

所有页面的全局图标轨都共用固定入口和位置：小鱼智能体、应用、最近会话、设置、文件管理、更多功能及账户/服务状态。显示器样式的模式主页图标和重复 AI 工作快捷入口不再出现；小鱼入口固定返回 `/work`。文件管理由常驻文件夹图标进入当前账户 Data 总览；各调用方在导航前清除游戏路径来源和返回状态。AI 员工办公室、无限画布、插件及工作区工具/资源由“更多功能”菜单分类呈现并可搜索；菜单只调用既有路由与回调，不复制业务状态或权限。插件入口导航到独立 `/plugin-manager` 工作区；DSH Host 保留 `/plugins` 作为只读资源包路由。当前 App 的主页与领域功能模块由左二工作区导航提供，内容按应用变化但沿用同一布局与菜单样式，不混入其他应用模块。全局“应用”按钮始终位于图标轨的同一位置，并沿用调用方既有的应用清单和路由 Owner。连接状态点消费 `general.showServiceStatus`；“最近会话”使用调用方现有回调：AI Work 页面展开既有左二 Dock，工作区外进入 `/work` 并展开 Dock。会话选择继续沿用原工作区会话操作，不为每个 App 建重复入口。

`SecondaryNavigation` 是设置分类和 AI Work 应用目录复用的二级菜单呈现组件。应用工作区的领域模块由 `ApplicationWorkspace` 呈现，共用同一工作区布局与菜单样式，模块内容仍归当前 App 的路由和 Owner。调用方提供分组、当前项与选择回调并持有唯一状态；组件统一提供滚动、分组折叠、当前项反馈和键盘移动，不读取设置或执行业务导航。侧栏尺寸、拖动、吸附、收起与响应式 Overlay 继续由 `lfaa-client-ui-dockkit/ResizableWorkbench` 持有。

`GlobalNavigationRail` 的可选 `className` 会追加到导航轨根 `<nav>`，供调用方标识自己的布局区域；它不改变导航内容或交互。在 `ApplicationWorkspace` 中，该类名用于标记最左侧图标轨。

全局“应用”菜单接收 Workbench 的完整应用清单及按 `general.hiddenApplicationNavigationIds` 过滤后的可见清单。普通应用通过图标轨“应用”弹层切换全局清单，AI Work 右侧“应用”视图保留完整目录；普通应用左二只显示当前 App 的功能模块，AI Work 左二只负责草稿、会话和项目。设置分类只控制全局导航入口显隐，不改变应用权限、路由或实例状态；所有隐藏时显示设置入口提示，不生成替代应用。
